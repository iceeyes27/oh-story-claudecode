# 读者体验优化：第一轮结果

规则清理、精简成稿入口和连续三章对照已完成。现在的流程更一致，写手收到的通用资料更少；这次试写仍然出现重复解释和操作过程偏长，尚不能证明读者满意度提高。

## 已落地

- 普通长篇写手只必读两份核心参考，其余技法按实际问题取用。当前核心参考共 **3688 个字符**；原成稿入口要求完整读取的八份参考共 67846 个字符。这只比较参考正文，不包含代理模板、章节材料及运行环境提示，不能当作总上下文或成本降幅。
- 规则区分事实与因果、本书笔调、可选技法。保留有功能的标点、代词、心理直写和生活细节，取消固定道具次数、逐段闭环及按统计带整章重写；相连要求可以自然合并表达。
- 连续三章及以上使用同一情绪标签只提示复核，不凭标签拒绝新章。候选、事实绑定、作者采用和追踪边界保留，输入损坏仍会拒绝。
- 普通候选字数统一为现有的 2200–2800，默认目标 2500；先测裸首稿，再在事务与阅读凭证齐备后做完整预检。
- 写后分别记录理解、趣味与作者决定；第 3/5 章及单元结尾建议连读。模型审读是代理证据，未做的部分标为未评估。
- 已同步 Claude、OpenCode、Codex 的写手模板及共享参考。没有向真实小说项目部署，也没有修改真实正文或提交推送。

## 直接试读

原创试验故事《小满修理铺》：女儿接手父亲的店，用一天完成修冷柜、临时安置鱼货、赢得客户信任的第一单。

三份都是同一故事的连续三章，全部保留一次首稿。阅读前可先不看分组：

## 实测结果

| 对照条件 | 第1章字数 | 第2章字数 | 第3章字数 | 字数达标 |
|---|---:|---:|---:|---:|
| 原入口八份参考 | 2503 | 2353 | 2339 | 3/3 |
| 清理规则后的核心参考 | 2578 | 2788 | 2738 | 3/3 |
| 核心参考加场景设计小节 | 2773 | 2807 | 2755 | 2/3 |

计数使用项目现行 `visible_chars_v1`：不计标题与空白，正文标点计入。超出上限 7 字的首稿没有补改或删除。这里没有选出胜出方案。

三个隔离审读者只收到各自匿名正文和相同问题。共同反馈是：事件能复述，修柜与信任变化有兑现，继续读的动力主要来自人物；反复说明、记数、搬运和验收拖慢了连读。仅清理组还有“七点／八点”的时段歧义；附加场景小节组有营业牌状态不够清楚的小疑点。

这些是模型观察，作者和真人反馈仍待验收。完整意见：[R17](reviews/R17.md)、[R42](reviews/R42.md)、[R86](reviews/R86.md)。

**首稿也没有通过现行禁词预检。** 九章均有禁词阻断命中，全部原始结果保留在[扫描记录](check-ai-patterns.js.json)；其中“几分钟”被按“几分”命中，是可以直接核查的误报。重复／截断／工程信息泄漏扫描没有发现项。完整候选采用检查未执行：本试验没有生产事务或阅读凭证，不能把试读稿当成已获准采用的正稿。

## 工程验收与后续重点

相关总验收 **15/15 通过**，包含候选采用 48 项、追踪 36 项；字数工具 13 项及最终引用、预算、静态、共享和 Codex 检查另行通过。首次运行的两个环境失败及复核条件保留在[验收记录](validation.json)，没有改用户全局环境或隐去首次失败。

本轮证明了规则和流程可以精简，尚未证明文风或趣味更好。下一轮最值得处理的是：只展开真正改变人物、信息或局面的步骤，压缩读者已经懂的重复确认；同时校准禁词误报。作者认可的好句应先保留，再做局部改动。真人试读前，不批量改写已有小说。
