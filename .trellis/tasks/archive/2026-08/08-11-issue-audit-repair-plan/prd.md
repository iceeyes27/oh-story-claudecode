# 修复审计确认的问题

## Goal

为当前统一 Skill 架构中的 8 项已确认缺陷制定可实施、可回归验证的修复方案，优先恢复正文守卫与唯一数据来源约束，再修复跨批审查、扫榜契约和 Codex 适配一致性。本任务只完成规划与审查，不修改业务代码。

## Background

当前分支为 `main@b70a44b`，工作区初始状态干净。上游旧名 `story-long-scan`、`story-long-analyze` 已分别合并为当前 `story-scan`、`story-analyze`；缺陷必须修在统一目标中，不恢复旧目录。

已确认范围：

- R1 / #316：Claude Code 的 Bash 写正文路径未进入大纲前置检查和写后检查。
- R2 / #333：Stage 6 文风 SOP 同时要求只读 Stage 0 章节边界表、又指导重新 Grep 和调整正则。
- R3 / #343：跨批审查要求继承上一批 findings，但没有持久化位置、格式、生命周期和只读模式规则。
- R4 / #339：起点移动端和 PC 模式缺少字数、总推荐、签约、收费模式字段。
- R5 / #340：七猫文档承诺大热榜日榜/月榜，脚本没有周期参数、页面切换和输出标识。
- R6 / #341：扫榜脚本的参数校验、简介截断和文件日期/抓取时间存在跨平台不一致。
- R7 / #319：Codex Python hook 使用无限深度 glob，未排除 `node_modules`，与其他端的目录发现边界不一致。
- R8 / #317：Codex 部署标记用子串判断 `target_cli`，会把 `opencode` 误认为包含 `codex`。

## Requirements

- R1 必须覆盖 Claude Code `Bash` 写入正文的前置授权检查，以及成功和失败命令的写后检查；写后检查只报告、不能声称撤销已发生的写入。
- R2 必须使 Stage 0 的章节边界表成为 Stage 1/2/6 唯一切片来源；边界状态带来源指纹并可确定性校验，Stage 6 不得自行重新识别边界。
- R3 必须定义跨批 findings 的项目内版本化状态；full/lean 可并发安全写入和恢复，solo 与显式只读模式只读，不得产生文件副作用。
- R4 必须让起点两种采集模式输出同一核心字段集合，并对字段缺失给出明确质量状态。
- R5 必须让七猫日榜/月榜承诺与脚本参数、页面操作、文件头和文件名一致。
- R6 必须统一各平台完整 CLI 校验、简介 100 个 Unicode 字符截断和同一时刻快照生成的文件日期/抓取时间；非法输入必须在网络和文件副作用前失败。
- R7 必须统一书目录发现为“标记距项目根最多 4 层”，忽略点目录、`.git`、`node_modules` 和符号链接，并覆盖当前书与全部书两个入口。
- R8 必须按逗号分隔 token 精确判断 `target_cli`，兼容单目标、多目标、空白和缺失字段。
- 所有共享行为应有单一实现或单一契约来源；生成模板和平台副本必须同步。
- 现有公开 Skill 数量、统一命名、`_shared` 边界和本地无 CI 约束不得改变。

## Acceptance Criteria

- [ ] AC1：Bash 创建、覆盖、追加、复制或移动正文文件时，大纲前置检查和成功/失败写后检查均有真实 Hook 注册回归；非正文 Bash 命令不误拦截。
- [ ] AC2：Stage 6 文档和检查器不再包含重新切片分支；章节边界表缺失、无效或来源变化时明确停止并要求重建 Stage 0。
- [ ] AC3：跨批审查状态具有固定路径、版本化格式、独占 revision 申领、批次标识和异常恢复规则；full/lean 可跨压缩或新会话恢复，solo/显式只读模式不写文件。
- [ ] AC4：起点 mobile-ssr 与 cdp-pc 均输出固定的 14 个逐书字段；缺失字段以 `null` 和 `missing_fields` 进入数据质量报告。
- [ ] AC5：七猫 `--period` 的合法值、页面切换、输出标识和默认行为都有回归测试。
- [ ] AC6：番茄、七猫、晋江、起点对未知、重复、缺值、空值、类型和范围错误均在副作用前失败；简介截断共用实现；日期与时间来自同一 `Date` 快照。
- [ ] AC7：Codex 目录发现跳过隐藏目录、`.git`、`node_modules`，深度规则与共享实现一致，并有深层目录与大目录回归。
- [ ] AC8：`target_cli: opencode` 会提示未部署 Codex；`codex` 与包含 Codex 的多目标值不会误报。
- [ ] AC9：相关静态契约、平台适配、部署检查和新增定向测试全部通过；不得新增 GitHub Actions。
- [ ] AC10：修复只发生在统一 Skill 目标及其权威模板/检查器中，不恢复 `story-long-*` 或 `story-short-*`。
