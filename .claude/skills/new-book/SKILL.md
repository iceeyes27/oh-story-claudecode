# 開新書

## 一、蒐集材料

先讀本專案既有檔案，已有內容就不要重問。然後用**一則訊息**向使用者問清楚還缺的部分，允許使用者只回答一部分：

1. 題材、目標平台、目標讀者
2. 核心賣點：讀者追這本書，是為了得到什麼樣的滿足
3. 主角：處境、目標、最大的缺陷或限制
4. 主要衝突與對手
5. 世界規則、能力或體系（如果有）
6. 第一卷大致要走到哪裡
7. **文風樣本**：請使用者提供 1～2 段自己寫的文字，或指定一段喜歡的文風。**不要由 AI 生成樣本**，否則等於拿 AI 腔當標準。使用者暫時沒有樣本時，先記「待補」，並提醒寫作前要補上。

使用者提供的材料，區分「已確定」與「待決」，待決的不要替使用者決定。

## 二、建立檔案

依各模板建立或填寫：

- `設定/設定.md`：世界觀、規則、資源、組織、地點
- `設定/角色/〈角色名〉.md`：主要角色，依 `設定/角色/_模板.md`
- `大綱/大綱.md`：全書方向與第一卷大綱；遠期可以只寫方向
- `設定/兌現登記.md`：把已知要兌現的設定與名場面、要遵守的約束、要常駐的特質登記進去，依模板欄位填寫
- `設定/文風樣本.md`
- `追蹤/追蹤.md`：初始狀態

推斷或補全的內容一律標「【待確認】」。

## 三、設定完善性檢查

呼叫 `structure-reviewer`（模式三），給它 `設定/`、`大綱/大綱.md`、角色卡。結果寫入 `審閱/設定檢查.md`。

## 四、交給使用者確認

在對話中簡短列出：已建立的檔案、【待確認】的項目、完善性檢查中「待定」的面向，以及哪些會影響第一卷、最晚何時要決定。請使用者逐項確認或修改。

## 五、確認之後

1. 依使用者的決定更新檔案，移除已確認項目的【待確認】標記。
2. 專案還不是 git repo 時，建議使用者執行 `git init`（方便日後回溯與比對修改），使用者同意才執行；是 repo 就 commit。
3. 告訴使用者可以用 `/plan-chapter 1` 開始規劃第一章。
