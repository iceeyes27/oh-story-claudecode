# 产物创建模板

各产物的标准模板与创建指引。agent 在 Phase 2-3 过渡时按需加载此文件。

**模板列表：**
- 设定/关系.md
- 设定/题材定位.md
- 大纲/卷纲_第X卷.md（含情绪弧线+反转规划）
- 追踪/伏笔.md
- 追踪/时间线.md
- 追踪/角色状态.md
- 追踪/流水线.md（日更批量状态票）
- 对标/{对标书名}/拆文报告.md
- 对标/{对标书名}/原文/第XXX章_{章名}.md

**层级关系：**
- 大纲.md = 全书鸟瞰（每卷一两句话定位）
- 卷纲_第X卷.md = 单卷规划（爽点节奏+情绪+人物+伏笔+反转）
- 细纲_第XXX章.md = 单章蓝图（内容概括 + 多线情节安排 + 人物关系/出场顺序 + 情节细化 + 结尾设定/钩子；旧字段核心事件/目标情绪/章首钩子/爽点/章尾钩子/字数目标保留）

## 对标/{对标书名}/拆文报告.md

> **拆文库/对标关系**：`拆文库/` = analyze skill 的原始产出（数据源）。`对标/` = 写作项目的引用视图。首次引用时从 `拆文库/` 复制到 `对标/`。

此文件由 `story-long-analyze` 拆解管道输出（快速预览报告或完整拆文报告）。write skill 的职责是**读取**，不创建。

```markdown
- 书名：{}
- 作者：{}

- 开篇钩子：{类型 + 手法}
- 爽点密度：{约 N 字/次}
- 节奏模式：{描述}
- 可借鉴套路：
  1. {}
  2. {}
  3. {}

## 禁止照搬
- {}（只学结构，不抄桥段）
```

## 大纲/细纲_第XXX章.md

细纲是正文写作的章节蓝图，而不是只列事件和钩子的清单。新版模板兼容旧字段：旧项目已有 `核心事件 / 情节点序列 / 目标情绪 / 章首钩子 / 爽点 / 章尾钩子 / 字数目标` 时仍可日更；新建、补建、回填时用下列结构。未知字段写 `[待补充]`，不要为了补齐字段杜撰副线或人物关系。

```markdown
## 细纲（第 N 章）

### 第 N 章：{章名}
- 核心事件：{一句话}
- 字数目标：{X} 字
- 目标情绪：{本章交付什么情绪}
- 章节定位：{高压/推进/修炼试错/关系回收/低压生活/信息整理；可留空，留空按推进章。见 outline-structure-theory.md「章节定位与张弛」}
- 章首钩子：{类型} — {具体内容；低压/过场章可写"弱钩子/仅情绪钩子，功能是…"}
- 爽点：{本章爽点 / 低压·修炼·过场章可写"无显性爽点但承担的功能"，但仍须给一个往下看的理由}

#### 内容概括（五段式）
- 起因：{事件为什么发生}
- 发展：{冲突如何推进}
- 转折：{信息/关系/局势变化}
- 高潮：{情绪或动作峰值}
- 结尾：{收束状态}

#### 情节安排（多线）
- 主线推进：{主目标推进}
- 辅线推进：{可写“无”或 `[待补充]`}
- 事件线 / 任务线：{外部事件链}
- 感情线 / 关系线：{关系变化；无显性则说明“无显性”}
- 逻辑线：原因 → 行动 → 结果 → 后果/新问题

#### 人物关系和出场顺序
- 出场顺序：{角色/势力/关键物件按实际出现顺序}
- 人物关系变化：{本章前 → 本章后}
- 视角/信息差：{谁知道什么；读者知道什么；主角误判什么}

#### 情节细化
- 情节点序列：{按字数预算编排——每点标密/疏给字数预算（密≥250、爽点400-600；疏≈40；铺垫取中约120-150；目标<1500字短章密点下限下浮到约120-250），Σ预算落在[章目标,章目标×1.1]，低于则增展开点、高于则压疏点，不注水；每点写“谁做了什么 + 功能标签”，末尾写“预算合计：X字（目标Y，范围Y-Z）”}
- 代价兑现 / 收益兑现：{谁付出代价；谁获得收益；后续账}

#### 结尾设定和钩子
- 结尾设定：{未解决问题；下一章推动力}
- 章尾钩子：{类型} — {具体内容；期待度；低压/过场章可弱钩子或留阶段目标；与下一章承接}
```

## 追踪/伏笔.md

**状态含义**：`未埋` = 已规划但尚未埋设；`已埋` = 已埋设且仍开放，是长篇正常状态；`已回收` = 已关闭；`已过期` = 已错过预计回收窗口，需要 `/story-review` 或显式修复。SessionStart hook 不应仅因 `未埋`、`已埋` 或 `已回收` 报警。日更流程只处理本轮新增/推进/回收的伏笔，全量伏笔审计必须由 `/story-review` 或用户明确要求触发。

```markdown
# 伏笔追踪
```

## 追踪/情绪债务.md

情绪债务 = 对读者的情绪承诺：正文里已经铺垫、读者已经在等的情绪兑现（打脸、发泄、揭穿、感情确认、报仇雪耻）。与伏笔的分工：伏笔是情节信息（一个设定/线索何时揭示），情绪债务是读者期待（一次情绪释放何时给、蓄了多少势）。同一处剧情可以既是伏笔又是情绪债务，分开登记、各管各的兑现。只登记读者明显在等的强承诺；一章内自然兑现的即时爽点不登记，避免表膨胀。

**状态含义**：`蓄势中` = 已立债、正在加压，是长篇正常状态；`已兑现` = 已释放并记录效果；`已过期` = 拖过预计兑现窗口仍未释放——读者期待会衰减成不耐烦，是弃书点，需要尽快兑现或降级处理。蓄势越久兑现越爽，但只在窗口内成立。

```markdown
# 情绪债务追踪

## 债务表

| ID | 债务内容（承诺给读者的情绪兑现） | 立债章节 | 蓄势强度{高/中/低} | 预计兑现章节 | 状态{蓄势中/已兑现/已过期} |
|----|--------------------------------|---------|------------------|-------------|---------------------------|
| E001 | {例：宋丽拿走的五万彩礼，读者在等主角当面讨回} | 第{N}章 | {级别} | 第{N}章 | {状态} |

## 兑现日志
| 章节 | 兑现的债务ID | 兑现方式{正面打脸/借刀/当众揭穿/延迟加倍} | 蓄势时长（章数） | 效果 |
|------|-------------|------------------------------------------|----------------|------|

## 过期债务
| ID | 原因 | 处理{立即兑现/降级快速兑现/放弃并给读者交代} |
|----|------|--------------------------------------------|
```

创建时机：Phase 3 大纲完成后与 `追踪/伏笔.md` 一同创建。更新规则见 `state-tracking.md`「情绪债务追踪」。

## 追踪/流水线.md

日更批量的章节流水线状态票：把每章各步骤的完成状态落盘，会话中断、compact 或跨会话后按票从未完成步骤续跑，不重写已完成章节。**只记当前批次**——新批次开始时整文件重置；历史进度以 `追踪/上下文.md` 和磁盘工件为准，本文件是断点索引，不是日志。

```markdown
# 章节流水线

- 批次：第 {S}-{E} 章
- 批次状态：{进行中/已完成}
- 更新时间：{YYYY-MM-DD}

## 章节进度

| 章 | 细纲 | 写前准备 | 正文落盘 | 字数验证 | 章检扫描 | 追踪更新 | 门控 | 交接包 |
|----|------|---------|---------|---------|---------|---------|------|--------|
| {NNN} | {待/完成/卡住} | {…} | {…} | {…} | {…} | {…} | {待/PASS/FAIL/不适用} | {待/完成/不适用} |

## 批次收尾

- 脚本收尾（check-ai-patterns / normalize-punctuation / check-degeneration）：{待/完成}
- 稳定性批量验收：{待/PASS/FAIL/不适用}
- 进度摘要（追踪/上下文.md 汇总）：{待/完成}

## 断点备注

- {无 / 第{NNN}章卡在{步骤}：原因 + 待办}
```

使用规则：

1. 日更 Step 2 确定批次范围后创建/重置；每完成一步立即回写对应格，失败改「卡住」并写断点备注。
2. 未启用长篇稳定性验收时，「门控/交接包」列与「稳定性批量验收」写「不适用」。
3. **续跑以磁盘为准**：状态票与磁盘不一致（票记「完成」但正文缺失/过小，或票记「待」但工件已落盘）时，先按磁盘修正票再续跑。
4. 单章写作（非日更批量）不强制使用本文件；文件缺失不阻塞任何流程。

## 创作偏好.md（工作区级，跨书）

存放在工作区根（与 `拆文库/`、`{书名}/` 同级），跨书、跨会话累积作者偏好。与 `设定/文风.md` 的分工：`设定/文风.md` 是**本书**的权威风格基，进入每章写作回路；`创作偏好.md` 记录**跨书**倾向，只在开书、日更启动、大修时加载——文风类倾向经开书时写入新书的 `设定/文风.md` 生效，不直接喂给 narrative-writer，不动既有文风优先级链。


**回写规则（偏好沉淀）**：
1. 触发条件二选一：同类修改反馈**第二次**出现（跨章或跨书均算），或用户明确说「以后都这样」「记住这个」。指向单章的一次性修改不沉淀。
2. 提炼成一条**可执行**的偏好（写清做什么/不做什么），带日期和证据（哪本书哪章的什么反馈），追加到对应小节。
3. 写入后回一句「已记住：{偏好}」，让用户有机会纠正。
4. 与既有条目冲突时以新反馈为准：更新旧条目而非追加矛盾条目。
5. 文件不存在时首次沉淀直接创建；不预先创建空文件。
