# 设计

## 修改边界
共享脚本从 canonical 修改，再由 manifest 同步。普通候选继续使用 fanqie-long-v2 的兼容采用路径：本轮统一其写前字数说明为该 profile 的既有 2200–2800 与默认 2500，不新增 profile/schema 轴；P1 与短篇的实验/计数协议保留独立适用范围。按用户明确字数若超出现行 profile，写前指出兼容范围，不到采用时才隐性冲突。

将情绪连排降为 advisory，取消其对新章的特殊拒绝。情绪词表仍作分类元数据，不作为“有趣”的判定。

默认成稿入口只完整加载短的核心参考，悬念/反转/道具技法按章节定位召回。新增紧凑 reader-first 参考供写手和主流程使用。编排规则与正文写法分离，作者偏好/本书例句保持作用域。

阅读反馈先保存建议性记录，绑定候选正文，隔离读者与作者答案；未运行须标未评估。第 3/5 章及单元结尾的检查不扩大 arc blocking 与采用绑定 schema。本轮不改 .story-quality 研究协议。

## 试验
先冻结当前 git HEAD 的基线。生成在仓库外临时目录，用无会话继承的生成调用；三臂分别连续生成三章，同章共用故事边界与预算，仅规则处理不同。所有原文留存，失败和重试有日志。对照只说明一次流程/方法的探索，不证明系统收益。真人反馈留空并报告待验收。
