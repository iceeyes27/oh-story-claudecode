# 开新书

进入或恢复本流程时，依 `.novel-kit/workflows/progressive-disclosure.md` 辨识阶段，只读当前步骤所需资料；作者确认与采用关卡不变。

## 一、搜集材料

先读本项目既有档案，已有内容不要重问。然后用**一则消息**向用户问清还缺的部分，允许用户只回答一部分：

1. 题材、目标平台、目标读者
2. 核心卖点：读者追这本书是为了得到什么满足；并凝练成**一句话推销**（谁在什么处境、靠什么、对抗什么），讲给陌生人听他会想看
3. 主角：处境、目标、最大的缺陷或限制，以及他的**核心思维方式与决策本能**（遇到事先怎么想、本能地算计什么、在乎什么、肯为什么付代价）
4. 主要冲突与对手
5. 世界规则、能力或体系，重点是“**故事引擎**”：哪些规则自带矛盾、代价或两难，能不断逼出冲突；纯背景资料可后补
6. **贯穿全书的大问题**（读者一路追着要答案的悬念）；第一卷大致走到哪里、回答多少、再抛出什么新问题
7. **文风样本**：请用户提供 1～2 段自己写的文字，或指定一段喜欢的文风。**不要由 AI 生成样本**，否则等于拿 AI 腔当标准。暂时没有先记“待补”，并提醒写作前补上

用户提供的材料，区分“已确定”与“待决”，待决的不替用户决定。

## 二、建立档案

依各模板建立或填写，先写故事引擎与追读设计，背景资料按需：

- `設定/設定.md`：基本信息、一句话推销、故事引擎、规则与能力体系；世界观、组织、地点按需补充，不追求设定集完整
- `設定/角色/〈角色名〉.md`：主要角色，含决策方式，依 `設定/角色/_模板.md`
- `大綱/大綱.md`：全书大问题、追读问题链与第一卷大纲；远期可只写方向
- `設定/兌現登記.md`：已知要兑现的设定与名场面、要遵守的约束、要常驻的特质，依模板字段
- `設定/文風樣本.md`
- `追蹤/追蹤.md`：初始状态

推断或补全的内容一律标“【待确认】”。

## 三、设定检查（完善性 + 抓人测试）

呼叫 `structure-reviewer`（模式三），给它 `設定/`、`大綱/大綱.md`、角色卡。除完善性外重点做抓人测试：一句话推销是否让人想看、故事引擎能否持续逼出冲突、问题链是否成立。结果写入 `審閱/設定檢查.md`。

## 四、交给用户确认

在对话中简短列出：已建立的档案、【待确认】项目、检查中“待定”与“不抓人”的面向，以及哪些会影响第一卷、最晚何时决定。请用户逐项确认或修改。

## 五、确认之后

1. 依用户决定更新档案，移除已确认项目的【待确认】标记。
2. 项目还不是 git repo 时，建议用户执行 `git init`（方便日后回溯与比对），用户同意才执行；是 repo 就依 `.novel-kit/workflows/adoption.md` 按档案提交，不动原有暂存。
3. 告诉用户可以用 plan-chapter 开始规划第一章。
