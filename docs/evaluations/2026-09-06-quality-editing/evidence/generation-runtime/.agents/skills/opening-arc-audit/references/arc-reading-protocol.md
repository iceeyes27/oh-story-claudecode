# 开篇连读 · 产 ledger 的子代理协议

> 本文件由 [../SKILL.md](../SKILL.md) 引用。目标：连读前 N 章，逐章判「开了哪些悬念 / 闭了哪些 / 是否推进主线」，产出 [ledger-example.json](ledger-example.json) 同构的 ledger JSON，交共享 `arc-ledger.js` 做确定性裁决。

## 概念

- **开环（open）**：本章新抛出的、让读者想追下去的问号（任务成不成、谜团是什么、某人图什么、危机怎么解）。每个开环给一个稳定 `id` 和一句话 `q`。
- **闭环（close）**：本章给出了某个先前开环的答案 → 记该开环的 `id`。答案必须在**正文里明写或明确暗示**，不能只在设定里。
- **主线推进（mainAdvance）**：本章主角的**核心目标状态**有没有发生可指认的改变（更接近/更远离目标、拿到关键资源、关系质变）。只是加铺垫、重复同一冲突、闲笔日常 → `false`。

## 判定纪律

1. **连读，不抽查**：按章号顺序读完整个窗口，边读边记开/闭，像真读者一样攒问号。
2. **闭环要较真**：读者到这一章真的得到答案了吗？「后文会揭晓」不算闭，只算这个开环还悬着。
3. **主线推进要较真**：这章过后，主角离目标更近了吗？说不出具体推进 = `false`。别把「写得热闹」当推进。
4. **id 一致**：闭环引用的 id 必须是之前某章开过的。不许闭一个没开过的、或闭一个未来才开的（脚本会报错拦截）。

## 子代理提示词（连读产 ledger）

```
你是一个只读的中文小说「开篇连读」审查代理。任务：把这本书的前 N 章当成一个整体连读，像一个真读者一样，记录每章「抛出了哪些让你想追下去的问号（开环）」「回答了哪些之前的问号（闭环）」「主角的核心目标有没有实际推进」。只读不改，最后产出一份 ledger JSON。

文件范围：<正文/第001章 … 第0NN章>，N 默认 15。

方法（按章号顺序连读，禁止跳读）：
对每一章记三件事：
1. opens：本章新抛出的问号，每个给一个短 id（Q1/Q2…全局唯一）和一句话描述 q。没有就空数组。
2. closes：本章明确回答了之前哪些问号，列出那些问号的 id。答案必须在正文里明写或明确暗示；「以后会讲」不算闭。没有就空数组。
3. mainAdvance：本章主角的核心目标有没有发生可指认的推进（更近/更远/拿到关键资源/关系质变）= true；只是铺垫、重复同一冲突、闲笔 = false。

较真两点：闭环——读者到这章真拿到答案了吗？主线——说得出这章把主角往目标推了哪一步吗？说不出就别记 true / 别记 close。

输出：严格的 JSON，形如
{"book":"书名","window":15,"chapters":[
  {"num":1,"opens":[{"id":"Q1","q":"…"}],"closes":[],"mainAdvance":true},
  ...
]}
只输出这个 JSON，不要额外解释。id 不许闭一个没开过的或未来才开的。
```

## 产出后

把 JSON 存成文件，跑：

```bash
node ../../_shared/scripts/arc-ledger.js <你的ledger.json>
```

脚本会给出收支表和裁决。若脚本报 ledger 错误（close 引用不存在/未来章 id），说明连读记错了，回去修 ledger 再跑。
