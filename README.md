# 小說寫作工具組（輕量版）

用 Claude Code 寫長篇小說的工作流程：**逐場景寫作 → 五位審閱者自動審閱 → 你逐場景把關**。支援開新書、接手舊稿，以及修改已完成的正文。

角色分工借用自 oh-story-claudecode 的 `story-review`，但拿掉了收據、狀態腳本等複雜機制，只保留審閱分工、問題格式、兌現判定與停止規則。

## 需要的東西

- **Claude Code**：桌面版、VS Code 擴充或命令列皆可。建議用桌面版或 VS Code，比對修改比較方便。
- **git**（強烈建議）：每次通過自動 commit，修改舊稿時可以隨時比對、回復。
- **Python 3**（選用）：場景關卡 hook 用。Windows 上如果指令是 `python` 而不是 `python3`，把 `.claude/settings.json` 裡的 `python3` 改成 `python`。沒有 Python 就刪掉 `.claude/settings.json`，關卡規則仍寫在 `CLAUDE.md` 裡，只是少了一道硬性攔截。
- **Obsidian 或 VS Code**：用來讀交付檔。把書的資料夾直接當成 Obsidian vault 開啟即可。

## 安裝

1. **一本書一個資料夾。** 把本工具組的全部內容（包括隱藏的 `.claude` 資料夾）複製進去。
2. 在該資料夾開啟 Claude Code。
3. 如果這個資料夾裝過 oh-story（跑過 `/story-setup`），建議另開新資料夾，再用 `/import-book` 把正文導入，避免兩套 hooks 和 agents 互相干擾。

## 開新書

```
/new-book          → 回答問題、提供文風樣本、確認設定與待定項目
/plan-chapter 1    → 確認到期檢查與細綱
/write-scene       → 寫第一個場景
```

## 接手舊稿

```
/import-book 〈原稿路徑〉
```

流程：確認範圍 → 備份原稿到 `導入/原稿/` → 切成一章一檔 → 逐章抽取 → 重建設定、角色、追蹤、兌現登記 → 你確認衝突與待確認項目 →（可選）全書體檢。

之後要續寫就用 `/plan-chapter`，要修改就用 `/revise`。

書很長時，可以選擇只詳細抽取最近幾十章，更早的只做摘要，節省時間和用量。

## 日常循環

每寫完一個場景，Claude 會產出 `審閱/第NNN章/場景MM_交付.md` 然後停下。你在 Obsidian 裡讀完，回到對話回覆：

| 回覆 | 結果 |
|---|---|
| `通過` | 標記通過、套用追蹤與兌現登記的變更、git commit，然後停下 |
| `通過，繼續` | 同上，並直接寫下一個場景 |
| `修改：〈具體意見〉` | 依你的意見修改，再跑一輪審閱，產出新版交付檔 |
| `重寫：〈方向〉` | 依方向重寫整個場景，重跑完整審閱 |

本章最後一個場景通過後，會自動做**章節收尾**：合併場景、順稿、整章盲讀、更新追蹤，並附上下一章的到期預覽。收尾也要你回覆「通過」。

## 修改正文

```
/revise 第012章 把師父發現真相的時間延後到第15章
/revise 我手改了第008章
```

- **文字修訂**只改表達；**情節修訂**會改變事實、知情、關係或兌現。分不清時一律當情節修訂。
- 情節修訂會先做**影響分析**，列出後續哪些章節必須跟著改、哪些兌現條目受影響，**等你確認範圍後才動手**。
- 修訂期間不能寫新場景（關卡會攔住）。
- 你自己手改的部分，AI 只審不改，問題列給你決定。

## 交付檔怎麼讀

1. **定稿全文**：先讀這個，用讀者的心態讀。
2. **自動修改紀錄**：看 AI 自己改了哪裡，不滿意可以要求改回。
3. **兌現判定**：確認細綱要求的條目有沒有真的兌現。
4. **剩餘問題**：S3／S4 沒有自動修，你決定要不要處理。
5. **審閱者分歧**：審閱者意見衝突的地方，由你裁決。
6. **建議的追蹤與登記變更**：回覆「通過」就會套用。有不同意的，回覆時一起說明，例如「通過，但 SET-004 不算兌現」。

## 審閱者與模型

| 審閱者 | 看什麼 | 模型 |
|---|---|---|
| copy-editor | 盲讀正文：指代、承接、因果、病句、句段節奏 | opus |
| consistency-checker | 設定、約束、時間線、伏筆、道具、角色知情 | sonnet |
| character-reviewer | 聲線、對話、動機、關係推進 | sonnet |
| prose-reviewer | AI 味、套話、總結式收尾、標點節奏 | sonnet |
| structure-reviewer | 細綱符合度、結尾狀態、兌現判定 | opus |
| scene-writer（寫手） | 寫作與修改 | opus |
| chapter-extractor | 導入舊稿時逐章抽取 | sonnet |

要調整模型，改 `.claude/agents/〈名稱〉.md` 開頭的 `model:` 欄位。

**用量提醒：** 每個場景會呼叫五位審閱者，最多再加兩輪修正。額度吃緊時，可以在過渡場景告訴 Claude「這場只跑文字模式」（只跑 copy-editor 和 consistency-checker），關鍵場景再跑完整模式。不建議把審閱者降到 haiku，抓邏輯斷裂和知情範圍會明顯變弱。

## 關卡的限制

- `scene_gate.py` 只攔「新建場景檔」：細綱未確認、上一場景未通過、上一章收尾未通過、有修訂進行中，都寫不進去。
- 「只有你說通過才算通過」是寫在 `CLAUDE.md` 的規則，技術上無法強制。如果發現 Claude 自行改了狀態，直接指正它。

## 常見問題

**斜線指令沒有出現？** 部分環境（例如手機遠端）可能不會載入專案內的 skill。直接用自然語言說「照 write-scene 的流程寫下一場」即可。

**被關卡擋住了？** 錯誤訊息會說明原因。通常是細綱還沒確認，或上一場還在等你審。

**審閱者一直挑小毛病？** S3／S4 本來就不會自動修，也不會擋住流程，可以直接忽略。如果某位審閱者的判斷持續不符合你的喜好，修改對應 agent 檔裡的「需要保護的東西」一節。

**寫出來的文風不對？** 最有效的做法是換掉 `設定/文風樣本.md`，放你自己寫的段落。
