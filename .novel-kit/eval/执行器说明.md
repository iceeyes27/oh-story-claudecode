# 可恢复的评测执行器

`scripts/eval_runner.py` 负责启动和留存执行证据，不替模型判分，不把报告生成解释为质量验收通过。每项任务启动独立的 `codex exec --ephemeral`，提示直接来自任务 JSON，保留原文；请求禁用记忆与嵌套多代理，模型和推理设置继承当前宿主配置。禁用参数不代表实际生效：任何已观察到的代理等待、委派或新建线程调用都会阻止完成；正常退出但存在这类调用时标为 `needs_review`，超时任务仍保留 `timeout`。

## 执行小批次

在项目根目录运行：

```text
python3 .novel-kit/scripts/eval_runner.py --tasks .novel-kit/eval/记录/2026-10-03_验收/审阅任务.json --root . --evidence-dir .novel-kit/eval/记录/2026-10-03_验收/执行证据 --timeout 240 --workers 3 --limit 3
```

`--timeout` 是每项任务的秒数；默认 180，较长场景可以显式设为 240。`--workers` 默认 3，`--limit` 默认 3，限制筛选后本批任务数量，其中也包含已有报告的核验。`--budget` 是本批执行时间预算，默认 600 秒；剩余预算小于单项超时则使用剩余时间，进程清理可能额外占用少量时间。`--datasets` 按任务的 `dataset` 筛选，`--skip` 按任务 `id` 排除。恢复时继续使用同一份任务文件与证据目录，以便核对已有凭据；推进后续任务时显式跳过已核验的编号。

启动前检查整份任务文件：重复 `id` 或指向同一规范化报告路径的任务一律拒绝，即使重复项在本批 `--limit` 外或被筛选排除，也不会先启动一部分任务。执行时还会按实际报告目标加进程锁，锁文件保存在报告旁的 `.<报告文件名>.eval-runner.lock`，跨任务编号、证据目录及符号链接别名共享。冲突项返回 `busy`，不能算完成；锁文件保留不代表仍被占用，不应在运行时删除它。

任务文件沿用 `{"jobs": [...]}` 格式；每项至少包含 `id`、`prompt`、`output`、`input_hashes`、`allowed_inputs`。哈希使用 SHA-256，`allowed_inputs` 必须与哈希表的路径集合完全对应。`dataset`、`role`、`phase` 等原有字段可保留。使用完整输入路径；报告路径必须位于 `--root` 内。任务编号允许中文，但不能包含路径分隔符或 `..`。示意：

```json
{
  "jobs": [
    {
      "id": "A01_修后_copy-editor_1",
      "dataset": "regression",
      "prompt": "此处填实际冻结提示，明确输入和报告路径。",
      "output": "/完整路径/outputs/A01_修后_copy-editor_1.md",
      "allowed_inputs": ["/完整路径/冻结输入/正文.md"],
      "input_hashes": {
        "/完整路径/冻结输入/正文.md": "此处替换为正文文件的64位SHA-256"
      }
    }
  ]
}
```

示意中的哈希不是可执行值；应使用冻结时记录的实际哈希。提示中的输入和输出路径必须与任务字段一致，执行器不替换路径、不追加提示、不替作者重写评测问题。

## Claude 宿主（--host claude）

默认仍是 `codex exec`。加 `--host claude` 改用 `claude -p`，其余（任务文件、哈希、证据目录、已完成跳过、进程锁、信号清理）完全相同：

```text
python3 .novel-kit/scripts/eval_runner.py --tasks <任务.json> --root . --evidence-dir <证据目录> --host claude --model opus --workers 3 --limit 3 --timeout 600
```

- 每项在证据目录里运行（不加载书稿的 `CLAUDE.md`、本地 Hook 与记忆），只开放 Read、Write、Glob、Grep，`dontAsk` 拒绝其余工具，不装载技能与 MCP，不保存会话。
- `--model` 取别名（opus、sonnet、haiku）或完整名称；实际模型取自会话开场事件，写入结果的 `model_id`。`--claude-bin` 可指定可执行文件，默认取 PATH 中的 `claude`，其次是桌面应用内置的最新版本。
- 完成标记是最终的 `result` 事件且 `is_error` 为假。**未登录或接口出错时事件仍显示 `subtype: success`，但 `is_error` 为真，执行器记 `needs_review`，不会因为文件存在而算完成。**
- 读取范围：Read 只允许任务的 `allowed_inputs` 和本项输出；越界读取记入 `outside_reads` 并阻止完成。Glob、Grep 与全部读取写入 `tool_reads` 供事后核对。出现 Agent、Task、SendMessage 等调用同样阻止完成。
- 成本：`usage` 记录轮数、耗时、`total_cost_usd` 与 token 用量（宿主未提供的项目缺省）。

**认证前提**：无头 `claude -p` 不继承桌面应用的会话，需要先在终端 `claude auth login`，或设置 `ANTHROPIC_API_KEY`。两者的计费方式不同；未认证时每项会很快返回 `needs_review`，证据里是 “Not logged in”。认证由作者自行完成，执行器和协调器都不处理密钥。

## 完成与恢复

执行前核对输入哈希，保存提示和开读记录；执行后同时核对退出状态、`turn.completed` 事件、报告包含非空白内容及输入是否发生变化。每项结果保存到 `<证据目录>/<任务编号>/run-<随机编号>/result.json`，同时保留 `opening.json`、`events.jsonl` 和 `stderr.log`；批次逐项追加 `batch-<随机编号>.jsonl`。重试新建目录，保留旧记录。

已有报告需要与它对应的成功执行凭据一致，才能作为完成项恢复。仅有输出文件、超时留下的片段或没有成功结束证据的报告，都不能算成功；执行器保留这些文件供核对，不覆盖重跑。报告或提示变化后，应另开评测版本，不能沿用旧凭据。输入变化也要重新冻结，不能事后改旧哈希使检查通过。

新版开读记录保存 `runner_schema_version` 和加载时执行器源码 SHA-256，结果保存开读记录与事件日志哈希。`nested_agents_requested_disabled` 记录请求，`nested_agent_calls` 和 `nested_agent_call_details` 记录日志中观察到的调用数量及工具名；同一事件的开始和结束只计一次。没有开读哈希或实际嵌套调用检查的旧执行结果会被标为 `unverified_output`，需要单独核验；工具不会补造历史凭据。`completed` 表示本次执行证据齐备，`resumed` 表示已有完成报告核验通过；`input_drift`、`timeout`、`needs_review`、`unverified_output`、`execution_error`、`budget_exhausted` 均不计完成。全部本批任务为 `completed` 或 `resumed` 时退出码为 0，否则为 2。

超时会终止本项的进程组，以免子进程在批次结束后继续写报告。CLI 收到 `SIGTERM` 或 `SIGINT` 时请求所有本批执行停止；每项在约 0.1 秒的检查间隔内清理自己启动的进程组，保存 `interrupted` 结果后退出，退出码分别为 143 或 130。清理不按进程名称搜索，也不停止其他批次或外部进程。强制 `SIGKILL` 无法被捕获。中断后的下一批仍须先检查已有输出及证据；不能把停止记录冒充成功报告。

在外部 Python 程序的主线程直接调用 `execute(...)` 时，自动安装临时信号处理器，结束后恢复调用者原来的处理器。若由工作线程调用，必须先在主线程用 `with signal_cleanup():` 包围整个线程池的生命周期；缺少该范围时拒绝启动，避免返回一个无法响应主进程信号的后台执行。信号清理完成后，该范围以 `SystemExit(128 + 信号编号)` 结束调用进程。

凭据和哈希用于核对版本及防止意外混用，不是签名认证，也不能单独证明模型只读取了允许范围。质量验收仍须核对实际读取范围、原始报告、逐项判分、保护项、修正副本与独立修后盲读；作者采用和真实宿主验收另行记录。

## 工程验证

```text
python3 -m unittest discover -s tests -p test_eval_runner.py -v
```

测试只运行临时假执行器，覆盖输入漂移、缺输入、已有无凭据输出、成功恢复、提示与报告变化、非零退出、缺结束事件、空报告、超时子进程清理、重试证据保留、主进程信号清理且不误杀外部进程，以及跨任务与证据目录的输出互斥。工程测试通过只说明执行机制符合这些检查，不代表真实模型质量或其他操作系统的宿主验收通过。
