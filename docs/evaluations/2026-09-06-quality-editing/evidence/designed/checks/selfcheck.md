# designed 臂写手自检与交付记录

本轮使用冻结 runtime 的完整 Codex narrative-writer 生成配置及两个普通长篇核心参考，沿用当前继承模型与 effort。未设置 P0/P1 treatment，未使用 Claude launcher。本臂故事输入只有 inputs/story-input.json 和 inputs/arm-plan.md；设计权取自主线程本次授权。

## 实际生成时序

先写 design.md，随后第一批第1至2章蓝图，再补第3章蓝图；首稿开始前按实际检查器 schema 补齐结构字段、词表取值、因果字段，未新增故事结果。每章均先运行骨架、细纲契约与 strict 因果检查，并保存完整命令、时点、退出码和输出，再保存实际 writer_packet、读取完整 packet、写一个完整 raw 初稿、复制候选、执行实测与扫描。三章 raw 和候选逐章哈希相同。

所有写前结构检查的实际退出码为0。检查时未创建 tracking；这些结果不代表采用。第2至3章消费的是本臂前章未采用原稿，packet明确标明此事实。父流程负责隔离前文state、独立reader及完整candidate check。

## 写手定点自检记录（不替代独立审读）

- 第1章无机器句式finding。未执行额外阅读编辑，保留原稿。
- 第2章 micro-action-tic：脚本报9处、7.0/千字，这是定位提示。当前原稿包含看箱与扣盖的功能动作，也有喝水、扫视等可复核动作；未按密度自动删除，留给父流程阅读意见。
- 第2章 formulaic-parallelism：命中原句“你看能不能扣住，不能就直说”。此处前半询问密封条件，后半要求不同意便直说，写手记录为条件回应功能；没有据此改写，亦未把advisory升降级为采用结论。
- 第2章 em-dash：父亲“得先把货——”被小满“已经存好了”打断，符号承担实际打断功能，保持原句。
- 第3章机器无句式finding；有单个“魚摊”繁体字，作为具体文字问题记录，未改raw或候选。
- 对话自检只记录上述可定位问题与功能。未建立独立理解/趣味receipt，未给阅读满意度、胜负、真人反馈或PASS。父流程后续读者审查不属于本次写手自检。

## 后写事实抽取

三章扫描结束后，按主线程追加要求写 metadata/chapter-NN.postwrite.json。每章 summary 不超过110字，覆盖五个O-ID的证据均用实际候选原句核验并附行号；人物状态、承诺、金额只截至相应章节。metadata不是生成前输入，也不是tracking事务或reader回执。inputs/read-files.json区分生成前阅读与写后抽取。
