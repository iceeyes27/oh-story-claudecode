# 候选系统落地方案（Candidate System）

## 背景

借鉴 narralume 的核心理念「AI 出候选，作者拍板」：AI 产出的正文先进入**待批准的候选态**，作者确认后才并入正稿。本仓库现状是 `story-write` 写作流由 narrative-writer 直接把正文落盘到 `正文/第XXX章_章名.md`，随即由写后 hook / deslop 闸口做「写后拦截」，但**缺一个显式的「待批准」中间态**——AI 一写即生效。这与 CHANGELOG 里长期在治的「照抄细纲 / 电报体 / 脚本污染 / 越界注水」同源：本质都是「AI 直接生效」带来的失控。

## Goal

在不破坏现有跨平台部署契约与日更批量流的前提下，为 `story-write`（长篇 mode=long 优先）引入一层**文件约定驱动**的候选态：正文先写入 `正文/候选/`，作者显式「采用」后由脚本原子地并入 `正文/` 并推进追踪；拒绝/替换的候选归档而非硬删。

## Requirements

### 功能需求
- R1 **候选目录约定**：候选正文写入 `正文/候选/第XXX章_章名.md`，与正稿 `正文/` 物理隔离（对齐 narralume「production 与 candidate 显式分离」）。
- R2 **候选模式路由**：候选态为**可选模式**，通过意图关键词（「候选/逐章确认/先给我看」）或项目配置开启；默认单章写作与「逐章确认」日更走候选，纯批量日更默认维持现状（见 R7）。
- R3 **追踪不提前推进**：候选未采用前，`_tracking-state.json` 不推进——它代表「已发生的事实」，不能反映未批准内容。候选章的追踪事务 JSON 随候选文件暂存（`正文/候选/第XXX章_追踪事务.json`），采用时回放。
- R4 **采用（promote）**：作者说「采用第X章 / 全部采用」时，脚本原子地：移动候选→正稿、回放该章 `tracking_commit.py commit`、更新 flow-state；失败可安全重跑。
- R5 **拒绝/替换归档**：作者说「重写第X章 更XX / 弃用第X章」时，旧候选归档到 `正文/候选/_历史/第XXX章_时间戳.md` 而非硬删（对齐 narralume 恢复箱理念，也符合本仓库既有「中途快照」安全网）。
- R6 **候选也要过质量网**：写后 AI 句式 / 去味 / 退化扫描要覆盖候选目录，让作者审阅的是已清理文本；`毒句式欠账门`（拦下一章）在候选模式下由「审批门」自然承接。
- R7 **日更兼容**：路由到 `workflow-daily.md` 的纯批量日更**默认行为不变**（直接落盘 + 逐章追踪），避免破坏「不询问是否继续」的串行批量；候选批量（provisional tracking）列为扩展项，不在 MVP。

### 约束
- C1 **平台中立优先**：机制以 SKILL 提示词 + 文件约定为主，不依赖平台 hook，确保 generic Web AI / 无 hook 环境也能用；hook 仅作兜底增强。
- C2 **部署契约**：改动 narrative-writer 或新增脚本需 bump `agents_version`（当前 25），并要求重跑 `/story-setup` 新开会话；跨端 parity 锁不得破。
- C3 **复用既有事务模型**：采用走既有 `tracking_commit.py`（原子替换 `_tracking-state.json`），不另造第二套追踪权威。
- C4 **不改既有单章直写作为默认**：候选是 opt-in；未开启时行为与现状完全一致。

## Acceptance Criteria

- [ ] AC1：开启候选模式写单章时，正文出现在 `正文/候选/`，`正文/` 与 `_tracking-state.json` 均未变化。
- [ ] AC2：「采用第X章」后，正文出现在 `正文/`，`tracking_commit.py check` 通过且 `state_revision` 推进；候选目录该章清空或归档。
- [ ] AC3：「重写第X章」后旧候选进 `正文/候选/_历史/`，新候选覆盖 `正文/候选/`，`正文/` 与追踪不受影响。
- [ ] AC4：候选正文经过 AI 句式 / 退化扫描，blocking 命中当轮清零后才提示作者审阅。
- [ ] AC5：未开启候选模式的单章直写与纯批量日更，行为与改动前逐字节一致（回归测试）。
- [ ] AC6：新增脚本有对应测试（参照 `scripts/test-tracking-*.py` 风格），跨端 parity 检查通过。

## Notes / 非目标（MVP 外，文档记录为扩展）

- 日更批量候选 + provisional tracking（多章暂存、全部采用时统一 finalize）。
- 写后 hook 路径覆盖候选目录的跨端 parity 落地（MVP 先靠 SKILL 级手动扫描）。
- `/story dashboard` 候选审阅视图 + 候选/正稿 diff 命令。
- 短篇 mode=short 的候选态（MVP 只做 long）。
