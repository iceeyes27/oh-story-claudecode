# 接手舊稿

原則：**書稿證據優先於模型猜測。** 所有重建內容都要能追溯到原文；推斷的一律標【待確認】。

## 一、確認範圍

向使用者確認（一則訊息問完）：

1. 原稿在哪裡、是什麼格式（一章一檔，或全書一檔）
2. 完整的章節範圍；有沒有殘稿（寫到一半的章節）
3. 題材、平台
4. 接手後的目標：繼續寫、只修改，或兩者都要
5. 書很長時：全部詳細抽取，還是只詳細抽取最近 N 章、更早的只做摘要（例如最近 30 章詳細）
6. 是否同意 `git init`（強烈建議，修改舊稿時可以隨時比對和回復）

## 二、備份與整理

1. 原稿**完整複製**到 `導入/原稿/`，之後不得修改或刪除。
2. 整理成 `正文/第NNN章.md`，一章一檔。全書一檔時依章節標題切分。**不改動任何文字**，只允許調整檔名與首尾空白。
3. 殘稿放 `導入/殘稿/`，不算完整章節。
4. 切分結果（每章檔名、標題、字數、開頭一句）寫入 `審閱/導入報告.md` 的第一節。
5. 使用者同意 git 時：`git init`，並把整理好的原稿做第一次 commit（「導入原稿」）。

## 三、逐章抽取

1. 依序呼叫 `chapter-extractor`，每次 1 章（短章可以 2～3 章一次），結果寫入 `導入/抽取/第NNN章.md`。
2. 只做摘要的早期章節，只抽取事件、設定、知情變化與伏筆。
3. 章數很多時，每完成 20 章在對話中簡短回報一次進度。

## 四、重建

依抽取結果建立或填寫（依各模板）：

- `設定/設定.md`：規則、資源、組織、地點，每條註明出處章節
- `設定/角色/〈角色名〉.md`：屬性、稱呼、關係、**說話特徵與代表台詞**
- `追蹤/追蹤.md`：當前位置（最後一章的章末狀態）、活躍伏筆、角色知情、讀者已知與作者真相、近三章摘要、下一章承諾
- `設定/兌現登記.md`：
  - 已經寫出來的重要場面與設定展示 → 「已兌現」，證據填原文與章節
  - 已經提出、尚未兌現的承諾與懸念 → 「規劃中」，預定位置寫「待定」
  - 已確立的規則 → 「約束／生效中」
  - 反覆出現的人物特質或關係模式 → 「常駐」，最近出現章節照實填
- `大綱/大綱.md`：「已寫部分」為各章摘要；「後續」留給使用者
- `設定/文風樣本.md`：**從原稿中挑 2 段最能代表作者文風的段落**（對白一段、敘述一段），註明出處

同一事實在不同章節說法不一時，不要自行選一個，列入衝突。

## 五、導入報告與確認

`審閱/導入報告.md` 補上：

1. 識別範圍：完整章節、殘稿、只做摘要的範圍
2. 重建結果概覽
3. **衝突與歧義**：前後矛盾的事實，附兩邊原文
4. **待確認清單**：所有【待確認】項目，附依據
5. 未兌現的承諾與懸而未決的伏筆

在對話中簡短回報重點，請使用者逐項確認衝突與待確認項目。確認後更新檔案、移除標記，git commit。

## 六、可選：全書體檢

使用者要求時才做。對指定範圍的每一章：

- 呼叫 `copy-editor`（前文為上一章最後約 1500 字）與 `consistency-checker`
- 結果寫入 `審閱/體檢/第NNN章.md`
- **只報告，不修改正文**

最後產出 `審閱/體檢/總表.md`：依 S1 → S2 排序列出所有問題，並把同一根因的問題歸在一起（例如某個設定前後不一，影響了 5 章）。使用者再用 `/revise` 挑選要修的部分。

## 七、接著寫

使用者要繼續寫時：

- 有殘稿：問使用者要從殘稿續寫（殘稿內容併入第一個場景的前文），還是捨棄重寫。
- 用 `/plan-chapter` 規劃下一章。導入的章節不需要在 `追蹤/場景狀態.md` 登記，關卡會以 `正文/` 中的檔案為準。
