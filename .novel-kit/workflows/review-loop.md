# 自动审阅与逐场景详细交付

write-scene、章节收尾与 revise 共用本流程。协调器指定对象、模式、前文范围和细纲或修改要求。**作者审核单位始终是场景**：写作和优化每次只推进一场，详细展示当前版本，等待作者决定；整章盲读补充跨场检查，不能代替逐场景审核。

## 一、审阅模式

| 模式 | 用途 | 审阅者 |
|---|---|---|
| 完整 | 新场景、重写、情节修订 | copy-editor、consistency-checker、character-reviewer、prose-reviewer、structure-reviewer |
| 文字 | 已采用正文的文字修订 | copy-editor、consistency-checker |
| 章節 | 章节收尾、整章修订最终检查 | copy-editor（整章盲读）、consistency-checker、structure-reviewer（章节模式） |

模式参数沿用工具支持的 `完整`、`文字`、`章節`。整章修订先逐场完成当前模式的详细审核，最后再做整章检查。

## 二、资料范围与独立性

### 同一组前文原文

写手与 copy-editor 使用同一份冻结的 source prose 范围，由上下文清单记录路径、版本和实际阅读段落：

1. **直接前场**：按叙事阅读顺序选前一场完整原文，不按故事时间倒推；第一场使用上一章结尾完整场景。边界无法可靠识别，尤其导入章无可靠场景边界时，给上一章全文。
2. **必要前因原文**：当前场景涉及的动机、关系、能力限制、物件来历、旧承诺等更早原文，协调器按证据选择，不按固定字数截断。
3. **当前场景候选**：完整纯正文，不夹带任务、修改说明或出口状态。

跨章来源使用最新正式采用的 `正文/`，不能用旧场景草稿代替修订后的正式章。尚未整章采用时，同章前场使用版本已采用的场景。写手另收累计事实、角色知情、资源和出口状态；copy-editor 不收这些解释。累计事实从最新有效采用版本重建，修订后替换旧值，不重复追加新旧增量。

需要补原文时，先标“前文不足”，补充已采用原文并更新清单、重新启动独立盲读；不能用设定、摘要或作者意图说服编辑认为读者已知道。固定长度、成本和较短上下文不证明供给完整。章节收尾另给整章候选和最新正式上一章；保留完整整章盲读。

| 审阅者 | 提供资料 |
|---|---|
| copy-editor | 同范围前文、完整纯正文候选、语文规格、文风样本；修订可另给指定相邻已采用正文。不给细纲、设定、追踪、累计事实、出口状态、作者意图、修改要求、对照、任务或其他审阅意见 |
| consistency-checker | 对象、前文、相关设定与角色、追踪、兑现登记、最新累计事实与出口状态；允许搜索后续已采用正文核对依赖 |
| character-reviewer | 对象、前文、出场角色卡 |
| prose-reviewer | 对象、文风样本、语文规格的口语和特色表达保护边界、prose-check 的 advisory 位置 |
| structure-reviewer | 对象、本场细纲及兑现表、相关兑现条目；修订另给作者修改要求与原细纲（如有） |

**确定性预检**：每次冻结前对候选执行 `./novel prose-check <候选路径>`，只读不改。blocking（长句复读、截断、占位或拒绝语、细纲等流程术语混入正文）不是文学判断，交 scene-writer 重写所在段落后再检，最多一次，不计入自动修正轮数；仍有则照常审阅，交付标“仍有严重问题”并附命中原句。advisory（章节结构词、引号内的流程术语）只交 prose-reviewer 逐处核对，不给 copy-editor，不自动定级。

首轮开读前依 adoption 执行 `review-start`，冻结候选和全部实际输入；修正、补读或输入变化后用新版本重开审阅。prepare 核对开读版本，不能在交付时才第一次冻结。

各审阅者使用独立上下文，首轮互不接收意见，可并行；每轮 copy-editor 使用新上下文。Claude Code 依 setup 的 quality/inherit 策略；其他宿主继承用户设定。主会话切换角色不算独立盲读。逐位记录 completed、失败或缺席、版本及范围；失败最多重试一次，仍失败交付“审阅不完整”，必要缺口交作者裁决。模型意见不是真人验证。

## 三、问题、保留项与定级

```yaml
- id: CE-1                # CE / CC / CH / PR / ST 对应五位审阅者
  severity: S2           # S1 / S2 / S3 / S4；供给不足则待核
  category: 承接
  location: "草稿/第012章/場景03.md 第5段"
  evidence: "问题原句"
  reference: "冲突来源原句与路径；事实问题必填"
  issue: "具体读错、停顿或回读发生在哪里"
  fix: "授权范围内的建议；语文问题依语文规格选择修法"
```

类别可用指代、承接、因果、时空、病句、重复、事实、设定、约束、时间线、伏笔、知情、资源、道具、声线、对话、动机、AI味、节奏、细纲、兑现。每位审阅者另列保留项，引用有效表达及保留理由。

| 层 | 依据 | 主要角色 |
|---|---|---|
| L1 语文正确 | 语文规格第一节及保护清单 | copy-editor |
| L2 段落与衔接 | 语文规格第二节及实际前文 | copy-editor |
| L3 上下文事实 | 已采用正文优先，其次设定和追踪 | consistency-checker |
| L4 自然度 | 文风样本、表达功能 | prose-reviewer |
| L5 好看 | 细纲、角色、场景功能 | structure-reviewer、character-reviewer |

同位置先修影响理解的语文或事实问题，再处理自然度；层级不直接决定严重度。

- **S1**：破坏主线、重要规则、动机或基本理解，例如误读行动者、角色凭空得知关键事实。
- **S2**：有证据的明显阅读损失、因果断裂、必要兑现缺失或声线显著偏移。语文问题须指出实际歧义、读错、停顿或回读，不能仅凭句式标签定级。
- **S3**：合法但别扭、累赘、轻微重复或局部拖沓。
- **S4**：偏好与可选建议；L5 建议一律 S4。

对白口语符合身份、说话者明确且不导致关键语义误读时，不报，不需要额外文风样本。特色叙述或标点需要文风样本或已采用正文证据。关联词省略或“但……却”等搭配不自动算硬错，按实际语义判断。前文缺失单列待核，不把供给缺口判成正文缺陷。

## 四、汇总与修正

1. 保存各角色原始结果；缺原文或事实 reference 的问题列待核，不自动改，也不当作已证实。
2. 同位置同问题合并；严重度有冲突时保留各自证据。审阅者分歧交作者裁决，不交写手擅自修。
3. 区分有意留白、缺前因和实际误解。当场必须理解且有阅读损失才判问题；需补原文的按第二节重做盲读。
4. **只自动修有证据、无分歧且在授权内的 S1/S2**；S3/S4 交作者选择。作者手改稿只审不自动修。
5. 第1轮给 scene-writer 问题和全部保留项，只改问题所在位置，回报原句 → 新句 → 理由 → 问题编号与证据。重新启动 copy-editor 整场盲读，原提问角色核对解决情况和新问题。
6. 仍有 S1/S2 再修1轮；首次未解决的先重新诊断根因。第2轮后仍未解决即停，标“仍有严重问题”。待审稿局部修改最多1轮。新增重要事实、改变设定或超出授权时停在候选，交作者决定。

## 五、每场详细交付

新场景写入 `審閱/第NNN章/場景MM_交付.md`；修订场景写入对应修订目录，新版本加 `_v2` 等并用新 ID。交付至少包括：

```markdown
# 第NNN章 场景MM 交付 vN

- 状态：审阅完成且无未决严重问题 / 仍有严重问题 / 审阅不完整
- 候选、来源正文、版本、实际阅读范围和上下文清单：
- 审阅模式、字数、修正轮数：

## 一、本场候选全文
（完整只读快照；每个待采用 source 按 adoption 放唯一全文校验块）

## 二、保留项
| 原文位置 | 有效表达原句 | 保留理由 |
|---|---|---|

## 三、逐条修改对照
| 位置 | 原句 | 改句 | 理由 | 问题编号及证据 |
|---|---|---|---|---|
（新写场景没有改前原句时标“新写”；无改动时明示）

## 四、章内事实增量（事实、资源、道具与知情变化）
| 类别 | 改前或入场状态 | 本场变化 | 改后或出口状态 | 原文证据 | 待确认 |
|---|---|---|---|---|---|
（时间、地点、在场者、资源收支、持有物、伤势、关系、知情、未完成动作、新增次要细节）

| 编号 | 细纲要求 | 已兑现 / 部分兑现 / 未兑现 | 候选原句 | 剩余义务 |
|---|---|---|---|---|

## 六、审阅执行与覆盖
| 角色 | completed / 失败 / 缺席 | 版本与阅读范围 | 结论或覆盖缺口 |
|---|---|---|---|
| prose-check | 已执行 / 未执行 | 候选版本 | blocking 与 advisory 数，及重写处理 |

## 七、剩余问题、分歧与待裁决事项
（附严重度、位置、证据、双方意见及作者决定项；无项也明示）

## 八、建议同步内容
（新场景只记录章内增量；整章采用或修订收尾才同步全书追踪、设定与兑现登记）
```

## 六、展示与停止

依 adoption 核对开读版本后 prepare。unresolved 包含未决 S1/S2、严重分歧与关键待核项；completed 只填真正独立完成者。

**对话必须给作者可直接审核的本场完整候选正文及详细对照**；篇幅较长时可打开含全文的交付文件，同时在对话逐条展示主要原句、改句、理由、保留项、事实变化和待裁决事项。不能只报路径、计数或“已优化”，也不能只给片段让作者猜整场效果。

交付后停下等待明确回复。`通过` 只确认当前场与明确版本；`通过，继续` 才推进下一场。已采用整章的分场确认只确认该场候选，正式章更新仍须最终全章版本采用。章节收尾保留独立整章盲读；顺稿改动已确认场景时，按场展示差异并重新确认受影响场景，再交全章收尾。
