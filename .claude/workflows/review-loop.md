# 自動審閱流程

`/write-scene`、章節收尾與 `/revise` 共用本流程。呼叫方要告訴你：**審閱對象**（檔案路徑與範圍）、**審閱模式**、**前文**（檔案路徑與範圍）、**本次的細綱或修改要求**。

## 一、審閱模式與審閱者

| 模式 | 用在哪裡 | 審閱者 |
|---|---|---|
| 完整 | 新場景、重寫、情節修訂 | copy-editor、consistency-checker、character-reviewer、prose-reviewer、structure-reviewer |
| 文字 | 已採用正文的文字修訂 | copy-editor、consistency-checker |
| 章節 | 章節收尾 | copy-editor（整章盲讀）、consistency-checker、structure-reviewer（章節模式） |

## 二、每位審閱者拿到什麼

**嚴格照表給，不多給。** 尤其 copy-editor 必須盲讀，只給正文。

| 審閱者 | 給它的內容 |
|---|---|
| copy-editor | 前文路徑與範圍、審閱對象路徑。**不給**細綱、設定、追蹤、兌現登記、其他審閱意見 |
| consistency-checker | 審閱對象、前文、`設定/`、相關角色卡、`追蹤/追蹤.md`、`設定/兌現登記.md` |
| character-reviewer | 審閱對象、前文、出場角色的角色卡 |
| prose-reviewer | 審閱對象、`設定/文風樣本.md` |
| structure-reviewer | 審閱對象、本場景細綱（含「本場景兌現」表）、`設定/兌現登記.md` 相關條目 |

本模式的審閱者彼此獨立，可並行呼叫。每輪 copy-editor 使用新的上下文，不繼承前輪意見，只讀正文。模型審閱不是真人驗證。

逐位記錄完成／失敗／未執行、閱讀範圍與候選版本。失敗項最多重試一次，仍失敗就交付「審閱不完整」，不能當成沒有問題。

## 三、問題格式（所有審閱者共用）

```yaml
- id: CE-1                 # 前綴：CE copy-editor / CC consistency / CH character / PR prose / ST structure
  severity: S2             # S1 / S2 / S3 / S4
  category: 承接           # 見下方類別
  location: "草稿/第012章/場景03.md 第 5 段"
  evidence: "引用審閱對象原文（必填）"
  reference: "引用衝突來源原文，註明檔案（事實類必填）"
  issue: "具體的閱讀損失是什麼"
  fix: "最小修改建議：改詞、改句或改一小段"
```

類別：指代、承接、因果、時空、病句、重複、事實、設定、約束、時間線、伏筆、知情範圍、道具、聲線、對話、動機、AI味、節奏、細綱、兌現。

每位審閱者另外列出**保留項**：寫得有效、修改時不能破壞的表達，附原文與理由。

### 嚴重度

- **S1**：破壞主線、設定、角色動機或讀者理解。例如：角色知道不該知道的事、違反約束條目、指代錯到讀者會誤解是誰做了什麼。
- **S2**：明顯的閱讀損失。例如：句段接不上、因果斷裂、細綱要求兌現的條目沒有兌現、聲線明顯跑掉、開頭接不上前文。
- **S3**：局部問題。例如：措辭彆扭、局部節奏拖沓、輕微重複。
- **S4**：建議或風格偏好。

## 四、彙整

1. 收齊所有審閱結果，原始結果寫入 `審閱/第NNN章/場景MM_審閱紀錄.md`（章節模式寫 `收尾_審閱紀錄.md`，修訂寫到修訂資料夾）。
2. 缺原文或 reference 的問題列為待核，不自動修改、不當作已證實；保留原始紀錄。影響關鍵判斷的缺口交作者裁決。
3. 同一位置、同一問題合併，取較高嚴重度。
4. **比對理解**：先區分有意留白、前文不足與實際誤解。只有當場必須理解且存在具體閱讀損失才列 S2。前因不足先補已採用正文，不拿設定代替，也不要求讀者知道所有作者意圖。
5. 審閱者之間意見衝突（例如一方認為口語是人物特色、另一方認為是病句），列入「分歧」，**不交給寫手修**。

## 五、修正迴圈

**只修有證據且在授權內的 S1、S2；S3、S4 不自動修。** 嚴重分歧仍算未決，不因為沒交寫手而消失。

1. **第 1 輪**：有未列入分歧的 S1／S2 時，呼叫 `scene-writer`（修正模式），交給它：審閱對象路徑、這些問題、所有保留項。寫手只改問題所在位置，回報修改清單（原句 → 新句 → 對應問題編號）。
2. **複審**：
   - 重新啟動獨立 copy-editor，只給正文，重讀**整個**審閱對象（加前文），不能只看改動處。
   - 提出 S1／S2 的審閱者確認各自的問題是否已解決，並檢查修改處是否引入新問題。
3. **第 2 輪**：仍有 S1／S2 時再修一次。第 1 輪修過卻沒解決的問題，先請原審閱者重新診斷根因（為什麼沒改好、根本原因在哪一層），再交給寫手。
4. **停止**：第 2 輪後仍有 S1／S2，停止自動修改，交付狀態標「仍有嚴重問題」，列出剩餘問題，交給使用者決定。
5. 修正需要新增情節或改變設定時，不自動改，列入交付檔讓使用者決定。

## 六、交付檔

寫入 `審閱/第NNN章/場景MM_交付.md`（使用者要求修改後的新版本加 `_v2`、`_v3`）：

```markdown
# 第NNN章 場景MM 交付

- 狀態：審閱完成且無未決嚴重問題 ／ 仍有嚴重問題 ／ 審閱不完整
- 候選路徑、交付版本、實際閱讀範圍：
- 各審閱者執行狀態：
- 審閱模式：完整 ／ 文字 ／ 章節
- 字數：n（細綱目標 n）
- 修正輪數：0 ／ 1 ／ 2

## 一、候選全文
（候選的只讀快照；修改此副本需重新生成候選與交付）

## 二、自動修改紀錄
| 問題編號 | 原句 | 新句 |

## 三、兌現判定
| 編號 | 細綱要求 | 判定（已兌現／部分兌現／未兌現） | 證據原句 | 剩餘義務 |

## 四、剩餘問題（S3／S4，以及未解決的 S1／S2）
（沿用問題格式，精簡呈現）

## 五、審閱者分歧
| 位置 | 甲方意見 | 乙方意見 | 各自證據 |

## 六、建議的追蹤與登記變更（場景為章內增量，整章採用才更新全書）
- 追蹤/追蹤.md：……
- 設定/兌現登記.md：SET-001 已排入 → 已兌現，證據：「……」（草稿/第012章/場景03.md）
- 新增的次要細節：……
```

## 七、完成後

1. 依 `.claude/workflows/adoption.md` 產生規格並 prepare。unresolved 列未決 S1/S2、嚴重分歧和關鍵待核項；completed 只列實際完成者。工具更新待審狀態。
2. 在對話中只回報：交付檔路徑、狀態、S1～S4 各剩幾條、分歧幾條、需要使用者決定的事項。**不要在對話裡貼全文。**
3. 停下，等使用者回覆。
