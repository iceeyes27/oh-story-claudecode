# 小说写作工具组

一本书一个目录，用逐场景写作或优化、独立审阅、作者明确采用完成章节。支持开书、导入旧稿和修订；候选与正式正文分开，开读冻结和采用日志绑定实际版本。

## 安装

核心需要 Python 3.9+，无第三方 Python 依赖。Git 只用于可选版本记录。工具组包含隐藏的 `.agents`、`.novel-kit`，放进独立书稿目录；已有其他工具时建议另建目录导入，避免混用状态。

| 平台 | 配置 | 自检 |
|---|---|---|
| macOS | `./novel setup --agent codex` | `./novel doctor --agent codex` |
| Windows PowerShell/CMD | `.\novel.cmd setup --agent codex` | `.\novel.cmd doctor --agent codex` |

按实际宿主把 codex 换成 claude 或 generic，确实同时用两者才选 all。macOS 启动权限缺失可用 sh novel；也可由可用 Python 调用 novel.py。搬目录或切换系统后重跑。

配置只更新本目录适配，保留其他设置。自定义适配冲突会停止，检查后用 setup --replace 先备份再更新。只读源码核对可用 setup --agent all --models quality --check-sources，检查确定性生成副本，不要求本机配置已经部署。Codex 需在 /hooks 核对来源和信任，Claude 也需宿主加载；doctor 验证启动器和载荷，不能证明实际会话已信任或隔离子代理。共享来源和保护边界见 [兼容性说明](docs/compatibility.md)。

## 日常使用

自然语言即可，Claude Code 也支持斜线入口，Codex 可使用技能或自然语言：

```text
开一本新书，先建立设定、角色和第一卷方向。
规划第一章，按场景详细展示细纲给我确认。
按已确认细纲写当前场，完整审阅后详细给我审核。
```

有旧稿先 import-book，原稿备份、抽取事实、作者确认并登记导入版本；仅有正文文件不代表完成导入。六个技能是 new-book、import-book、plan-chapter、write-scene、revise、fiction-scene-polishing。完整步骤见 [使用指引](docs/novel-kit-使用指引.md)。

## 每次只交当前场

**写作和优化都按场景详细审核，每次只推进一场。** 交付包含本场完整候选、保留项、逐条原句 → 改句 → 理由 → 问题证据，以及事实、资源收支、道具、知情、兑现、实际审阅范围、完成或缺席、分歧和待裁决事项。

对话直接提供全文和详细要点；长场可打开含全文的交付并逐条展示对照，不能只报路径、计数或结论。

| 作者回复 | 后续 |
|---|---|
| 通过 | 采用指向的具体版本，通常停止 |
| 通过，继续 | 采用后才写或优化下一场 |
| 修改：意见 | 重开候选，新版本审阅交付 |
| 重写：方向 | 重写当前场，完整审阅交付 |
| 只检查，先不改 | 只读报告，不修改文件 |

末场采用后准备整章收尾，保留独立整章盲读、事实及兑现检查。顺稿改动已确认场景须逐场展示并确认，再等全章采用；整章采用才更新正式正文和全书追踪。整章检查不能替代逐场作者审核。

## 修订与手改

已采用整章的优化从最新正式正文按场景拆出候选，每场先审、展示、等作者。场景确认只确认对应候选，不能把片段覆盖整章；全部场景确认后合成完整章、独立整章盲读、采用完整版本。修订任务全部正文采用及追踪同步完成才解除续写阻塞。

作者手改只审不自动修。保留当前稿，找可核实的采用快照或 Git 比较，无改前基准明示。再手改时 revision-refresh 保存历次基准，用新 ID 重审。

## 审阅与前文

新场景和情节修订用五位独立审阅者；文字修订用 copy-editor、consistency-checker；整章最终检查用文字、事实、结构三位。每轮盲读新上下文。缺席如实列“审阅不完整”，模型意见不等于作者采用或真人验证。通常最多两轮自动修正，局部修改最多一轮，仅修授权内有证据、无分歧的严重问题。

前文使用叙事顺序的直接前场完整原文＋协调器按证据选择的必要前因。写手和文字编辑同范围冻结来源，写手另收最新累计事实；文字编辑不收事实解释或作者意图。跨章读最新正式正文，边界不可靠给上一章全文。供给工具验证版本，不自动判断前因语义。品质收益需另做保留集和真实使用验证。

Claude quality 策略默认写手和文字编辑 opus、其余角色 sonnet；setup --agent claude --models inherit 可全继承。Codex 和通用 Agent 继承宿主模型。

## 版本与恢复

日常命令由协调器执行，作者不手填 JSON。详见 [采用与恢复](.novel-kit/workflows/adoption.md)。

- 候选准备后先 review-start 冻结，审阅后 prepare 核对同版本与交付全文，再等明确采用。
- 工作单元撤回用 withdraw，保留手改、候选和历史；前置修订仍须完成。已有写作的细纲变化用 rebind-plan，记录确认和影响复核。
- 中断采用可重跑，外部手改冲突保留现场；Git 只提交指定字面路径，保留原有暂存，失败报告“已采用、未提交”。
- 启用 Hook 检查匹配写工具；无有效 Python 时匹配写入全部拒绝，修复环境再自检。Shell、外部编辑器及未匹配工具不受其拦截，版本核对发现漂移。
- 工具记录作者决定，不能证明真人授权，不能自行捏造通过。

## 验证

```sh
python3 -m unittest discover -s tests -v
```

Windows 使用本机可用 Python。测试在临时目录验证采用、恢复、修订、导入、Hook、路径提交和上下文来源；Windows 原生检查在其他系统明确略过。CI 配置存在不证明远端已运行；本地通过不证明文学品质、真实宿主加载或全书完成。历史记录与本轮范围见 [验证记录](docs/validation.md)。
