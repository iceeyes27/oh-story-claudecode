# 自動審閱流程

`/write-scene`、章節收尾與 `/revise` 共用本流程。呼叫方要告訴你：**審閱對象**（檔案路徑與範圍）、**審閱模式**、**前文**（檔案路徑與範圍）、**本次的細綱或修改要求**。

## 零、確定性掃描

審閱前，協調器對審閱對象執行：

```sh
bash .claude/scripts/py.sh .claude/scripts/novel.py scan 〈審閱對象路徑〉
```

- **作者禁詞**（`設定/禁用詞.md`）與**繁體字**（正文要求簡體時）：直接列為 S2 問題，id 前綴 SC，進入修正迴圈。
- **提示命中**（`.claude/workflows/ai-patterns.md`）：原樣交給 prose-reviewer 複核，不直接當問題。
- 掃描結果原樣寫進審閱紀錄；每輪修正後重跑一次。
- 掃描命令報錯（詞表損壞、作者禁詞缺出處）時先停下修好詞表，不能跳過掃描直接交付。

## 一、審閱模式與審閱者

| 模式 | 用在哪裡 | 審閱者 |
|---|---|---|
| 完整 | 新場景、重寫、情節修訂 | copy-editor、reader-reviewer、consistency-checker、character-reviewer、prose-reviewer、structure-reviewer |
| 文字 | 已採用正文的文字修訂 | copy-editor、consistency-checker |
| 章節 | 章節收尾 | copy-editor（整章盲讀）、reader-reviewer（整章盲讀）、consistency-checker、structure-reviewer（章節模式） |

文字模式仍要執行掃描；它不加 prose-reviewer，提示命中列在交付檔的「掃描結果」給作者參考。

## 二、每位審閱者拿到什麼

**嚴格照表給，不多給。** 尤其 copy-editor 與 reader-reviewer 必須盲讀，只給正文。

| 審閱者 | 給它的內容 |
|---|---|
| copy-editor | 前文路徑與範圍、審閱對象路徑。**不給**細綱、設定、追蹤、兌現登記、其他審閱意見 |
| reader-reviewer | 同 copy-editor：只給前文與審閱對象，**不給**細綱、設定、追蹤、兌現登記、掃描結果、其他審閱意見 |
| consistency-checker | 審閱對象、前文、`設定/`、相關角色卡、`追蹤/追蹤.md`、`設定/兌現登記.md` |
| character-reviewer | 審閱對象、前文、出場角色的角色卡 |
| prose-reviewer | 審閱對象、`設定/文風樣本.md`、本輪掃描結果 |
| structure-reviewer | 審閱對象、本場景細綱（含「本場景兌現」、閱讀回報、讀者期待、展開與略寫）、`設定/兌現登記.md` 相關條目 |

本模式的審閱者彼此獨立，可並行呼叫。每輪 copy-editor 與 reader-reviewer 使用新的上下文，不繼承前輪意見，只讀正文。模型審閱不是真人驗證，模型讀者的感受也不是真人讀者的反應。

逐位記錄完成／失敗／未執行、閱讀範圍與候選版本。失敗項最多重試一次，仍失敗就交付「審閱不完整」，不能當成沒有問題。

## 三、問題格式（所有審閱者共用）

```yaml
- id: CE-1                 # 前綴：CE copy-editor / RD reader / CC consistency / CH character / PR prose / ST structure / SC 掃描
  severity: S2             # S1 / S2 / S3 / S4
  category: 承接           # 見下方類別
  location: "草稿/第012章/場景03.md 第 5 段"
  evidence: "引用審閱對象原文（必填）"
  reference: "引用衝突來源原文，註明檔案（事實類必填）"
  issue: "具體的閱讀損失是什麼"
  fix: "最小修改建議：改詞、改句或改一小段"
```

類別：指代、承接、因果、時空、病句、重複、事實、設定、約束、時間線、伏筆、知情範圍、道具、聲線、對話、動機、AI味、節奏、細綱、兌現、回報、冗述、欠寫作、收尾。

每位審閱者另外列出**保留項**：寫得有效、修改時不能破壞的表達，附原文與理由。

### 嚴重度

- **S1**：破壞主線、設定、角色動機或讀者理解。例如：角色知道不該知道的事、違反約束條目、指代錯到讀者會誤解是誰做了什麼。
- **S2**：明顯的閱讀損失。例如：句段接不上、因果斷裂、細綱要求兌現的條目沒有兌現、聲線明顯跑掉、開頭接不上前文、作者禁詞、簡體正文出現繁體字。讀者體驗只有四類局部可修的問題能給 S2：冗述拖慢一段以上、關鍵時刻被一句帶過（閱讀回報沒上頁）、場景或章末停在替讀者下結論的總結、章末完全沒有往下讀的動力。「整體悶、不夠爽、要改情節」最高 S3，交作者決定。
- **S3**：局部問題。例如：措辭彆扭、局部節奏拖沓、輕微重複。
- **S4**：建議或風格偏好。

## 四、彙整

1. 收齊所有審閱結果，原始結果寫入 `審閱/第NNN章/場景MM_審閱紀錄.md`（章節模式寫 `收尾_審閱紀錄.md`，修訂寫到修訂資料夾）。
2. 缺原文或 reference 的問題列為待核，不自動修改、不當作已證實；保留原始紀錄。影響關鍵判斷的缺口交作者裁決。
3. 同一位置、同一問題合併，取較高嚴重度。
4. **比對理解**：先區分有意留白、前文不足與實際誤解。只有當場必須理解且存在具體閱讀損失才列 S2。前因不足先補已採用正文，不拿設定代替，也不要求讀者知道所有作者意圖。
5. **比對讀者體驗**：拿 reader-reviewer 的「讀完得到了什麼」「最想知道接下來」對照細綱的「閱讀回報」「讀者期待」。事件已在正文發生、讀者卻沒感受到回報：協調器記一條 S2（category：回報，id 前綴 RD，附 reader-reviewer 原話與細綱原文），交寫手在該處局部展開；事件根本沒發生，歸 structure-reviewer 的細綱符合度。讀者期待與細綱不同但同樣有動力，不算問題，寫進交付供作者參考。
6. 審閱者之間意見衝突（例如一方認為口語是人物特色、另一方認為是病句；reader-reviewer 想略、structure-reviewer 要求展開），列入「分歧」，**不交給寫手修**。

## 五、修正迴圈

**只修有證據且在授權內的 S1、S2；S3、S4 不自動修。** 嚴重分歧仍算未決，不因為沒交寫手而消失。

1. **第 1 輪**：有未列入分歧的 S1／S2 時，呼叫 `scene-writer`（修正模式），交給它：審閱對象路徑、這些問題、所有保留項。寫手只改問題所在位置，回報修改清單（原句 → 新句 → 對應問題編號）。
2. **複審**：
   - 重新啟動獨立 copy-editor，只給正文，重讀**整個**審閱對象（加前文），不能只看改動處。
   - reader-reviewer 本輪提過 S2 時，也以新上下文重讀整個審閱對象；協調器核對原低點是否仍被報出。
   - 重跑確定性掃描，作者禁詞與繁體字須歸零或列入未決。
   - 提出 S1／S2 的其他審閱者確認各自的問題是否已解決，並檢查修改處是否引入新問題。
3. **第 2 輪**：仍有 S1／S2 時再修一次。第 1 輪修過卻沒解決的問題，先請原審閱者重新診斷根因（為什麼沒改好、根本原因在哪一層），再交給寫手。
4. **停止**：第 2 輪後仍有 S1／S2，停止自動修改，交付狀態標「仍有嚴重問題」，列出剩餘問題，交給使用者決定。
5. 修正需要新增情節或改變設定時，不自動改，列入交付檔讓使用者決定。

## 六、交付檔

寫入 `審閱/第NNN章/場景MM_交付.md`（使用者要求修改後的新版本加 `_v2`、`_v3`）：

```markdown
# 第NNN章 場景MM 交付

- 狀態：審閱完成且無未決嚴重問題 ／ 仍有嚴重問題 ／ 審閱不完整
- 候選路徑、交付版本、實際閱讀範圍：
- 各審閱者執行狀態：
- 審閱模式：完整 ／ 文字 ／ 章節
- 字數：n（細綱目標 n）
- 修正輪數：0 ／ 1 ／ 2

## 一、候選全文
（候選的只讀快照；修改此副本需重新生成候選與交付）

## 二、自動修改紀錄
| 問題編號 | 原句 | 新句 |

## 三、兌現判定
| 編號 | 細綱要求 | 判定（已兌現／部分兌現／未兌現） | 證據原句 | 剩餘義務 |

## 三之一、讀者體驗（模型讀者的代理判斷，不代表真人讀者）
- 往下讀意願：想往下讀／可有可無／想跳過（reader-reviewer 原話）
- 讀者得到的 vs 細綱閱讀回報：
- 讀者期待 vs 細綱讀者期待：
- 高點與低點（各附原文）：
- 給作者的整體意見（不自動修）：

## 三之二、掃描結果
- 作者禁詞：n 處（須為 0，或列入未決由作者裁決）
- 繁體字：n 處（正文要求簡體時須為 0）
- 提示命中與 prose-reviewer 裁定：| 編號 | 位置 | 原文 | 裁定（確認／保留） | 理由 |

## 四、剩餘問題（S3／S4，以及未解決的 S1／S2）
（沿用問題格式，精簡呈現）

## 五、審閱者分歧
| 位置 | 甲方意見 | 乙方意見 | 各自證據 |

## 六、建議的追蹤與登記變更（場景為章內增量，整章採用才更新全書）
- 追蹤/追蹤.md：……
- 設定/兌現登記.md：SET-001 已排入 → 已兌現，證據：「……」（草稿/第012章/場景03.md）
- 新增的次要細節：……
```

## 七、完成後

1. 依 `.claude/workflows/adoption.md` 產生規格並 prepare。unresolved 列未決 S1/S2、嚴重分歧和關鍵待核項；completed 只列實際完成者。工具會再掃一次正文，把仍存在的作者禁詞與繁體字自動加入 unresolved，並更新待審狀態。
2. 在對話中只回報：交付檔路徑、狀態、S1～S4 各剩幾條、分歧幾條、模型讀者的往下讀意願、需要使用者決定的事項。**不要在對話裡貼全文。**
3. 停下，等使用者回覆。
