# 寫場景

## 一、找出要寫的場景

1. 讀 `追蹤/場景狀態.md`。
2. 有場景是「待審」：告訴使用者該場景還在等審核（附交付檔路徑），**停止**。
3. 找出細綱已確認的章節中，第一個不是「已通過」的場景。
4. 找不到：本章場景已全部通過就執行「章節收尾」；收尾也已通過，就提示使用者先執行 `/plan-chapter`。
5. 使用者有指定場景時，先確認前一個場景已通過；沒有通過就說明原因並停止。

## 二、準備前文

- 本章第一個場景：上一章 `正文/第NNN章.md` 的最後約 3000 字。
- 其他場景：上一章最後約 1500 字，加上本章所有已通過場景的全文。

## 三、寫作

1. 場景狀態改為「撰寫中」。
2. 呼叫 `scene-writer`（模式一：寫作），交給它：
   - `大綱/細綱/第NNN章.md` 與要寫的場景號
   - 細綱「本場景兌現」表中各條目在兌現登記裡的內容
   - `設定/設定.md` 中相關的部分、出場角色的角色卡
   - `追蹤/追蹤.md`
   - `設定/文風樣本.md`
   - 前文的路徑與範圍
   - 寫入路徑：`草稿/第NNN章/場景MM.md`
3. 寫手回報細綱寫不通時，停下，把問題告訴使用者，請使用者修改細綱或做決定。

## 四、自動審閱

場景狀態改為「自動審閱中」，依 `.claude/workflows/review-loop.md` 執行**完整模式**。審閱對象是剛寫好的場景檔。

## 五、交付

依 review-loop 第六、七節產出交付檔、更新狀態為「待審」、簡短回報，然後停下。

---

## 使用者要求修改（「修改：〈意見〉」）

1. 場景狀態改為「撰寫中」。
2. 呼叫 `scene-writer`（模式三），交給它：場景檔、使用者的意見、上一版交付檔中的保留項。
3. 依 review-loop 執行**文字模式**審閱，最多 1 輪修正。使用者的意見涉及聲線、情節或兌現時，另外加上對應的審閱者（character-reviewer、structure-reviewer）。
4. 產出新版交付檔（`_v2`、`_v3`…），第二節分成「本次依使用者意見的修改」與「自動修改」兩部分。
5. 狀態改為「待審」，停下。

## 使用者要求重寫（「重寫：〈方向〉」）

呼叫 `scene-writer`（模式四），然後照第四、五節跑完整模式審閱與交付。

---

## 章節收尾

本章所有場景都「已通過」後執行。

1. `追蹤/場景狀態.md` 中本章「收尾」列改為「撰寫中」。
2. 把所有場景依序合併成 `正文/第NNN章.md`（章節標題照細綱）。
3. 呼叫 `scene-writer`（模式五：順稿），只處理場景之間的銜接與跨場景的重複。
4. 依 review-loop 執行**章節模式**：
   - copy-editor 盲讀整章，前文是上一章最後約 3000 字
   - structure-reviewer 用章節模式，給它整章、本章細綱、上一章結尾
5. 有 S1／S2 照 review-loop 修正，最多 2 輪。
6. 交付檔寫入 `審閱/第NNN章/收尾_交付.md`。第六節要包含章節層級的追蹤更新：當前位置、近期摘要（只保留最近三章，更早的併入 `大綱/大綱.md` 的「已寫部分」）、下一章承諾、活躍伏筆、角色知情。
7. 另外附上**下一章的到期預覽**：兌現登記中預定位置已到或將到的條目、超出窗口的常駐條目、預計回收的伏筆。
8. 「收尾」列改為「待審」，停下。

使用者回覆「通過」後，照 CLAUDE.md 的通過流程處理。`草稿/第NNN章/` 保留，供日後回溯。
