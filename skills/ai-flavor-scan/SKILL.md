# 网文去 AI 味 · 十层扫描法

从《我在越南捞沉船》多卷复核中踩坑固化出来的流程。

**核心教训（二则）**：
1. 只查词表会漏掉最像 AI 的那一层——抽象融合比喻，它不在任何词表里。
2. 只做减法（清掉多余的）会漏掉另一类 AI 病——欠写作/电报体，用摘要取代场景展开。

初版报告用两层表扫，结论「基本干净」，但用户点名第 46 章「把这口海和这条路一起**拧住**」→ 不在任何词表里 → 补扫出融合比喻盲区，新增第 3 层。
第 73 章「潮更乱，底也更黑」→ 不在任何词表里，也不是多余，是**不够**——六个字抖完一个该展开三五句的水下场景。全系统六层都是减法，全漏 → 新增第 7 层（加法：欠写作探测）。
→ **词表是下限，不是上限。前六层管"写了不该写的"，第七层管"该写的没写够"。**

## 何时用
- 用户要查某卷/某项目小说的 AI 味、说明书式说话、比喻滥用
- 用户说「再扫一遍」「还有没有 AI 味」「第 X 章还有问题」
- 重读后想系统化排查

## 四层扫描法（务必逐层做，缺一不可）

> 已扩展为十层。前五层是词表/正则可批量扫的；第 6-9 层是语义层，需逐段人工通读；第 10 层是章节标题专项，可脚本自动化。下文按层列出。

### 第 1 层：硬禁用词
目的：抓项目已定义的禁用词。
pattern（示例，按项目实际 `报告/禁用词清单.md` 调整）：`仿佛|宛如|犹如|恰似|宛若|淡淡|微微|一丝|深吸一口气|意味着|眼神复杂|轻轻`
动作：Grep 全正文目录，0 命中即过。注意旧「禁用词清单」往往是大快照，**必须以当前文件实扫为准**（文件可能被后续编辑改过，旧清单会误报"100 处"而实际已清）。

### 第 2 层：AI 修辞词库
目的：抓抽象双关名词（棋/桌/血脉/根系/暗涌/底色/余温/余烬/余响 等）。
pattern：`棋盘|棋局|棋子|棋手|落子|执棋|对弈|掀桌|血脉|骨血|根系|根须|骨子里的|暗涌|底色|褶皱|注脚|回声|肌理|纹理|刻度|锚点|切面|坐标|余温|余烬|余响`
判定：**具象用法保留**（如「木头晒过的余温」是真实触觉，非抽象情感余温）。抽象情感/权力隐喻才该清。

### 第 3 层：抽象融合比喻（最关键，最易被漏）
目的：抓「把两个不搭界抽象域用物理/工业/手工动词硬揉」的写法——最像 AI。
pattern（动词+成/住/在一起）：
- 拧：`拧住|拧在一起|拧在一块|拧成牌|拧成一盘|拧成砝码|硬拧成一套`
- 揉：`揉成|揉进|揉在一起|揉碎|揉入`
- 捏：`捏成|捏进|捏在一起|捏入`
- 织：`织成|织进|织在一起|织入`
- 焊：`焊成|焊死|焊在一起`
- 缝/缠/裹/嵌/熔/搓/糅/拼/串/叠：`缝成|缝进|缝在一起|缠成|缠在一起|裹成|裹进|裹在一起|嵌进|嵌成|嵌在一起|熔成|熔在一起|搓成|糅合|糅进|糅在一起|拼成|拼在一起|串成|串在一起|叠成|叠在一起`
判定：
- **保留**：字面动作（缝金条进棉袄、裹杯进布、揉纸团、搓绳）、俗语/voice 锚点（拧成一股绳、串成一条链）、真实感官混融（「陈茶和潮木头拧在一块的味」）、常见认知隐喻（拼成图、字串成句）。
- **该清**：抽象归属/塑形/层级用物理动词硬喻（「人心焊死在他身上」→拴死；「把人捏成别人认得的样子」→扮成；「海和路一起拧住」→攥在手里）。
改法：换成 plain 动词（拢/并/叠/攥/拴/串/扮），保义。

#### 3b. 物理清除/抹消动词 × 抽象对象（补充子层）
> 与 3a 同类——把抽象概念（时间/记忆/痕迹/一切）当物理对象去"抹平/冲走/刮掉"。最易漏，因为动词本身太常用，不在任何词表里。

pattern（动词×抽象宾语，LLM 语义判定，非正则引擎执行）：
- 抹：`抹平` + 时间/岁月/痕迹/一切/棱角/差异/裂痕 | `抹掉` + 记忆/证据/痕迹/一切/所有 | `抹去` + 记忆/痕迹/一切
- 盖：`盖过` + 声音/事实/真相/一切
- 冲：`冲走` + 记忆/理智/一切/所有 | `冲淡` + 记忆/痕迹
- 刮：`刮掉` + 痕迹/记忆/一切 | `刮去` + 痕迹/记忆
- 洗：`洗掉` + 罪名/记忆/污点/痕迹/一切 | `洗去` + 罪名/记忆/痕迹
- 碾：`碾碎` + 希望/尊严/一切/所有
- 削：`削平` + 棱角/差异/一切

判定：
- **保留**：字面物理动作（抹平水泥、冲走泥沙、洗掉污渍、刮掉标签胶）。
- **该清**：动词 + 抽象对象——"把时间抹平""把记忆冲走""把棱角削平"，这些是文学化概念转译，真人在现场会用具体说法（趁痕迹还在→别让证据被清掉；把记忆冲走→记不起来了；把棱角削平→被磨没了脾气）。

> 注：本子层关键字同步注册进[共享禁用词表](../_shared/references/banned-words.md)的通感隐喻段，供 `check-ai-patterns.js` 正则拦截。

### 第 4 层：排比 / 空洞总结
目的：抓作者借角色念说明书、空洞总结句。
pattern：`说到底|归根结底|说穿了|总而言之|一言以蔽之|换言之|究其根本|万变不离|说白了|一句话`
判定：命中若都是**活人说话/动作/内心嘀咕**（人物锐评、一句话按住某人），不算病；只有「作者旁白式空洞总结」才该清。
另扫说明书式说话标记：`你懂吗|说白了|其实就是|换句话说|我跟你讲|听好了|简单来说|说穿了|归根到底|你知不知道|明白没有`。同样只清「借角色念设定/科普」的，活人自然口语保留。

#### 4b. 说明书式平铺陈述（缺人味，非 meta 标记）

> 与 4a 的「说白了/你懂吗」类 meta 标记不同：本子类**没有任何标记词**，就是一句干巴巴的平直陈述，读着像说明书 / 操作手册 / 法条条目在客观汇报，而不是一个活人在此刻这样说、这样做。这是最隐蔽的「没人味」——词表全盲、正则难拦，只能靠通读语感判。用户原话：「说明书式表达，没有人味。」

两类典型形态：

**① 动作说明书（旁白 Tell 无 Show）**——把本该由角色"演"出来的反应，压成「名字 + 动作 + 得 + 快/慢/准」式结果汇报。
- 案例：「苏青岚接得很快」——只报了"她接话快"这个结果，没演过程（身子往前一倾？半句截住对方？杯子往桌上一顿？）。读者拿到一句旁白结论而非画面，像舞台指示被直接当正文。
- 判定：凡「X + 得 + 程度副词」只在**汇报动作结果**、不给感官/身体/反应落地，判 说明书式、缺人味。
- 改法：落到动作/身体/反应（Show Don't Tell）。如「苏青岚没等他说完，半句就截了上去」「苏青岚把话头一把接住」。
- **窄留口**：高速对话交锋里孤立的「X 接得很快」若是有意当重拍节奏、且前后已有充分 Show，可留；但凡它成了"交代信息"的主要载体，则清。

**② 道理说明书（台词侧，扁平说理金句）**——把角色本该带着情绪/立场/利害说出的判断，压成工整的「X 比 Y 都 Z」「X 作数」式法则金句，像教科书在陈述规律，不像人在表态。此态无标记词、结构干净，正则全盲。
- 案例：「病历比谁说的话都作数」——一句话把"客观证据优先于言词"打包成定律抛出。读着是作者在给读者划重点，不是苏青岚这个人在此刻带着职业判断开口。
- 判定与改法：**台词类归 `dialogue-naturalness-scan` 第 6 类（点题式/扁平说理金句，advisory 通读复核，不 blocking）**——把"定律"拆回人物当下的具体处境/动作/声口，绑到眼前物证（如让她翻到病历某页、手指点着时间点说；或「这份病历上，急诊、麻醉、复苏的时间点一个都卡着钟——他按手印那会儿清不清醒，纸面上写得明明白白」）。

**③ 情绪说明书（旁白侧，全知抒情旁白）**——把角色该"演"出来的心理反应，压成「情绪标签词 + 抽象收束」的旁白宣告，作者替角色下"正确"的情绪结论。
- 案例：「周春来还坐在那里，发懵，不敢信真有人愿意替他往前走一步」（本卷 Ch001）——"发懵/不敢信"是情绪标签直给，"替他往前走一步"是抽象比喻收束；作者替角色宣告感动，读者拿到结论而非画面，且"正确"的感动违背「内心要脏要乱」（活人第一反应常是怀疑/麻木）。
- 判定：凡作者旁白出现「(坐|站|愣)在那里，发懵/愣住/不敢信/没想到…」+「替他往前走一步/替他扛」式抽象收束，判 情绪说明书、缺人味；角色**台词**里的口语（"我真没想到你会帮我"）豁免。
- 改法：删标签词与抽象收束，落到当下可见动作/身体反应（盯协议、喉结动、没说话），情绪留白不点题；要露情绪就露"脏/乱"闪念。
- 拦截：正则已注册进 `../_shared/references/banned-words.md`（「通感隐喻」段末尾自动加载 + 新增「全知抒情旁白」人工段）。

**统一研判口令**：读完这句，你听到的是"叙述者在汇报/下结论"，还是"这个活人在此刻这样说/做"？是前者 = 说明书式、缺人味，该落回人话与身体。

**与第 7 层（欠写作）的区别**：7 层抓"该展开却压成摘要"（场景条件没写够）；本层抓"用平直陈述代替活人呈现"（动作/道理被压成干条）。一句可同时中两层，分别处理。

#### 4c. 主语连贯性 / 视角断裂与句内主谓动线（三项主谓防错，advisory 通读复核）

> 同属"叙述连贯性与动线自洽"类，单独列出便于系统复核。
> 1. **段首视角跳切**：相邻段落里叙述主语从角色 A 切到 B，B 仍用"他/她"未点名，读者按就近原则误读成 A。典型是电影化跳切：A 定格 → 切 B 的动作/心声，无过渡。
>    - 案例（Ch001）：`周春来还坐在那里…` 后紧接 `他…三天。够了。`——"三天"是江澈对韩克勤期限的回应，主语已切江澈却未点名。
> 2. **句内双人动作连逗号（主语突变）**：句首为 A，逗号后直接用代词「他/她」切换为 B 的动作。
>    - 案例（Ch036）：「江澈指了指对面的椅子，他把双拐靠在椅背边……」→ 改为「江澈指了指对面的椅子。周春来把双拐靠在椅背边……」
> 3. **同性同场代词漂移**：同场同性别两人（江澈/韩克勤、苏青岚/彭晓蕊）分句盲用「他/她」。
>    - 案例（Ch106）：「韩克勤总爱先把难处说足，他听归听……」→ 改为「韩克勤总爱先把难处说足，江澈听归听……」
> 4. **物理施受力动线脱节（自伤错配）**：抛/掷/甩/推物品后紧接未定所属的受创反应。
>    - 案例（Ch001）：「韩克勤把一沓材料扔到桌上，纸边划过手背，一道细口子，蜇得他缩了一下手。」→ 改为「韩克勤把一沓材料扔到桌上。卷宗顺着桌面滑过来，锋利的纸边擦过江澈搭在桌沿的手背，划开一道细口子，隐隐的刺痛蜇得他手指缩了一下。」
> 
> 判定口诀：两人物动作必断句、同性同场不省名、物理受击写轨迹。
> 规则详情见 `../_shared/references/banned-words.md`「句内主谓动线与代词指代错位」段。

#### 4e. 旁白口号腔（叙述者跳出来喊口号，blocking）

> 从《法援律师》168 章全量扫描固化（2026-08-19）。这是 4 层「排比/空洞总结」的最极端形态：**无说话人、无引号的作者旁白**，用排比＋抽象大词（正义/法治/尊严/真相/公道）＋口号收尾（不胜不休/正义必胜/绝不妥协/依法维权到底）替全书点题。
>
> 判据口诀：把句子抽出来读，**像不像电视普法节目的旁白字幕 / 法治宣传片解说词**？像 → 命中。
>
> - 案例（Ch068 已修）：「法援律师用铁一般的证据与法条，逐一击穿了各方精心构筑的免责壁垒，逝去的年轻生命的尊严与家属的合法权益，必将在法治的晴空下得到最公正的伸张，不胜不休，正义必胜！」——叙述者直接向读者宣示"正义必胜"，把读者当普法对象，既出戏又稀释爽点。
> - 改法：删掉口号尾，收束成角色当下可见的场景/动作/物件（窗外、白板、证据链、灯光、卷宗、送达回执），情绪留给下一章钩子，不替读者下结论。已改：「窗外暮色苍茫，会议室内的灯光坚定而温暖。江澈把三份专项法律意见书并排放进卷宗，第一页上，校方的免责协议被红笔划了一道。」
> - **边界**：① 引号内台词口号（「正义的审判才刚刚开始」「不胜不休」）归 `dialogue-naturalness-scan` 第 6 类（advisory），本层只扫旁白侧，两条口径不重复计；② in-world 群众/群聊口号（家长群刷「正义必胜」）是场面描写，豁免；③ 具体法律行动清单收尾（「第四，依法启动名誉权侵权诉讼与刑事自诉，绝不姑息任何造谣者」）是程序陈述，豁免。
> - 拦截：正则已注册进 `../_shared/references/banned-words.md`「旁白口号腔」段，`check-ai-patterns.js` 以 `narration-slogan` 类型 blocking 拦截（只扫引号外叙述，maskQuoted 排除台词与群聊）。
> - 高频口号家族：不胜不休 / 正义必胜 / 正义绝不（缺席|低头|妥协） / 胜利终将（必将）属于 / 依法维权到底 / 法治的晴空（轨道|底线|威严|蓝天） / 正义的（审判|锁链|巨浪|钟声|铁壁|利剑|铁拳|法网|利刃|防线） / 紧握正义之（剑|笔） / 筑起（铸就）正义的（铁壁|屏障|盾牌|巨伞） / 撕开（击穿）虚伪（伪善）的（面具|外壳） / 真相终将大白于天下 / 光明（黎明）终将来临 / 黑夜终将过去 / 公道自在人心 / 朗朗乾坤（晴空） / 公平正义重见天日 / 告慰……在天之灵 / 法援律师用……筑起…… / 法援律师的目光坚定如铁。命中即改，勿同义轮换（「正义必胜」换「公理长存」仍是口号）。
>
> **换皮检测（通读口径，正则抓不到新皮，必须靠人/代理审稿时按功能判）**：口号家族会换皮——同义大词轮换（正义必胜→公理长存/邪不压正/天理昭彰/公道自在）、武器库轮换（正义的利剑→法治的长矛/法律的雷霆/天平的砝码）、排比结构保留但动词换词（击穿壁垒→碾碎防线/撕破屏障/荡平障碍）、收尾口号换字（不胜不休→誓不罢休/决不退让/战斗到底）。正则只抓已知皮；未知新皮靠**功能判据**兜底：不看用了哪个词，只看这句旁白在干什么——是不是**替读者下结论 / 宣告结局 / 升华主旨**？是 → 命中，无论词表有没有。通读时遇叙述性收尾句（尤其章末、案件收口、胜负揭晓后），一律先过这道功能问：这句是在**收束可见场景**（窗外/白板/卷宗/送达回执/当事人反应），还是在**替全书喊口号**？后者即换皮口号，按 4e 改法清掉。发现新皮后当场补注册：加进 `banned-words.md`「旁白口号腔」段的高频家族 + `check-ai-patterns.js` 的 `NARRATION_SLOGAN_PATTERNS` 正则，防止下次漏扫。

#### 4d. 跨章信息续接 / 章节边界连贯性（advisory 通读复核）

> 同属"叙述连贯性"类，**不是 AI 味问题**（人类作者也会犯），单独列出便于复核。
> 特征：上一章结尾 ↔ 下一章开头之间的信息续接断裂——上章收尾的动作/计划/状态，下章开头没接上。
> 已踩坑四型（均已在正文修复）：
> 1. **计划悬空**：Ch5 结尾说「明天先去医院」，Ch6 夜里已改口"明天去食堂"，Ch7 实际去工地食堂——"去医院"无人兑现（医院线 Ch9 才真去）。改法：计划句要么下章兑现，要么下章明确改口，不能悬空。
> 2. **钩子悬空**：Ch45 深夜「接进来」匿名热线，Ch46 未交代来电人——补一句「昨晚打热线电话的，就是她」落地。改法：结尾动作（接电话/收到消息/推门出去）的后续，下章开头必须有人认领。
> 3. **跨章复读**：Ch60 结尾与 Ch61 开头整句重复「三块互相遮掩的控制事实被书面说明钉住，裂口合到合同解除那一栏」——同一意象跨章复读，删下章一侧。改法：上章已收的意象，下章不要再原句重放；真要回指用短指代。
> 4. **人物位置断裂**：Ch1 结尾江澈走到楼道尽头（离场），Ch2 开头他已在桌边翻协议——补折返过渡「江澈在楼道尽头站了片刻，转身折回桌边」。改法：上章结尾人物离场，下章开头他重新在场，中间必须有折返/转场交代。
> 检测脚本 `.agents/skills/_shared/scripts/check-chapter-boundary.js`（advisory，三类：跨章复读相似度 / 计划悬空 / 动作钩子收尾，输出上章尾句+下章头句供复核）。跑法：`node .agents/skills/_shared/scripts/check-chapter-boundary.js "书目录"`。
> 判定口诀：上一章收尾的动作/计划/状态，下一章开头是否直接接得上、或给了明确的换场/跨天标记？接得上 → 豁免；接不上（人凭空换位、计划被悄悄改掉、钩子无人认领）→ 补一句过渡/点名。

### 第 5 层：高频黑话单字滥用（补充层）
目的：抓被过度依赖的单字形容词（硬/狠/稳/野/滑/毒 等），尤其单字抽象省略用法。
pattern（以「硬」为例，按需换字）：`真硬|要硬|够硬|才硬|得硬|来硬|挺硬|人硬|敢硬|硬气` + 全字 `硬`
判定：
- **保留**：固定搭配/习语/字面（嘴硬、命硬、骨头硬、硬碰硬、硬生生、硬着头皮、硬撑、硬壳、硬茧、硬盒烟）——这些是江湖/市井 voice 底色，密度高也别删，删了反而假。
- **该清**：单字抽象省略、读着断的用法。案例：ch046「你要真**硬**，就落个字」→「你要真**敢**，就落个字」（"硬"单用作"硬气/敢硬来"的省略，承接不顺；换成承接语气的实义词）。
- 方法：先全字 grep 看总量与占比，再挑"单字+抽象"的少数怪处改，**不做全局降密度**（除非用户明确要求）。

### 第 6 层：生造词 / 强行搭配（盲区补漏）
目的：抓「词表外、靠语感判」的 AI 病——① 生造抽象名词/伪深沉短语；② 为凑双关/对称/排比硬造的不自然搭配或逻辑断裂。第 1–5 层全会漏（第 3 层只认融合动词，不认生造词）。
典型命中：
- 伪深沉名词：「不归海算」「海的定数」「河的逻辑」「风的章法」「土的命数」「光的秩序」「水的经纬」。
- 强行搭配/双关/排比：「不为心松」（为跟"松手"凑双关硬造"心松"，非自然搭配）、为凑对仗 cramped 的不自然语序、为凑"是A，是B，是C"排比强塞不并列分句导致逻辑断裂（见下案例）。
- 文人量词/不通俗：「一口海今天给不给你饭吃」（"口"当文人量词配拟人，文气不通俗、像 AI）；但渔民俗语"一口海"=一个渔场（"下一口海""从一口海做成一张牌"）是行业 voice，留。判据：量词是文人修饰还是行业用语。
判定：
- **该清（伪深沉）**：意象未在上下文建立为系统性象征，却单句蹦出"意象+抽象名词"的 cryptic 短语，读着像 AI 硬拔高。改法：① 删掉伪深沉尾，落到已建立的 voice；② 抽象名词换 plain 动词/口语。
- **该清（强行搭配）**：为凑双关/对仗，把不自然的词/语序硬塞进句子。分两型：① 生造抽象名词——如"心松""不为心松"，改法：用自然搭配重说（"手是松了，心没松"）；② 生造动词/名词组合——为跟前词凑对仗，硬造一个在口语/书面中均不独立存在的搭配，如"试命"（只活在"试海，还是试命"这句话里）。"试命"不是实词，没人说过"我去试个命""这趟是试命的"，它只在跟"试海"对上时才被生造出来。改法：换成实词——"赌命""拿命试"；若对仗本身也多余，连结构一起拆。
- **该清（排比断裂）**：为凑"是A，是B，是C"/对仗结构，第三拍强塞不并列、逻辑不通的成分（如名词排比后突然接分句），读着像 AI 硬凹结构、读者看不懂、没人这么说话。改法：① 给结构一个能统辖第三拍的框架（"靠的是潮，是风，是…"）；② 直接拆排比落人话。
- **该清（文人量词/不通俗）**：用诗化量词（一口/一汪/一泓…）配拟人/抽象求诗意，读着文气、不通俗、像 AI，禁掉。但同形词若是行业俗语（渔民俗语"一口海"=渔场）且出自活人对话，属 voice，留。判据：量词是文人修饰还是行业用语。
- **该留**：意象/搭配是全卷系统性象征，且服务于该象征，则保留，只降密度。已固化两例：① 第二卷「桌」=华人商圈层级且进了章标题；② **「门」母题**——贯穿全书的「进门—通路—门道」系统：门路（入局通路/人脉 route-in）、门道（门道/窍门/行规 know-how）、门/这道门/几道门（层层关隘 the layered gates）、旧门认旧器（圈内相认暗号）、认门认账（认路数也认账面）、看门认（看码头那道门认不认咱——门里头不点你的货，搬得再勤也出不去；ch024 首现已钉死为「码头那道关」=运货要过的验货口，故为有意且可读意象，非生硬抽象；更早的裸门首现 ch019「七叔好处也没从这道门过」（不点地名，靠动词「过」托底）、ch023「走货的旧门」亦已补托底，扫描勿判该清）；还进了章标题（ch110「第一层门，算是开了」）。此系统内的 门 用法一律保留，扫描不得判该清。
- **方法论提醒**：这一层靠"语感 + 上下文"判，grep 穷不尽。扫完第 1–5 层仍觉得某句"飘"或"巧得发假"，就用这一层兜底。
- 案例（ch081）：「他松这一下手，不为心松。这地方的水，已经不归海算了。」
  - "不为心松"＝为凑"松手"双关硬造"心松"，语序 cramped（自然说法"手是松了，心没松"），判该清。
  - "海算"＝生造抽象名词，判该清。
  - 整句建议改为：「他松了这一下手，手是松了，心没松。会安那口海今天给不给你饭吃，到了堤岸，得另算。」
- 案例（ch073 生造搭配）：「你这是试海，还是试命。」——"试命"只在跟"试海"对仗时才被生造出来，口语/书面中均不独立存在（没人说"试个命""这趟是试命的"）。它看起来能读通，细想才发现是硬凑——这是此型最具欺骗性的地方：第一眼不假，第二眼才露馅。改法：换成实词"赌命"。已落盘改为「你这是试海，还是赌命。」
- 案例（ch081 排比逻辑断裂）：「会安那边是潮，是风，是一口海今天给不给你饭吃。」——"是A，是B，是C"排比承诺三个并列名词，第三拍却塞进完整分句，结构断裂、读者看不懂、一眼判 AI（实测读者误读成"什么是潮湿风是一口海"）。改法二选一：① 给排比框架统辖分句（"会安那边靠的是潮，是风，是这片海今天给不给你饭吃"）；② 拆排比落人话（"会安那边，潮起潮落，风大风小，全看这片海今天给不给你饭吃"）。原 ch081 此句已落盘改为后者（"一口海"的"口"是文人量词、不够通俗，最终用"这片海"）。

### 第 7 层：欠写作 / 电报体（加法盲区）
目的：抓「应该展开却压缩成摘要」的 AI 病——用抽象形容词/副词直接概括场景条件，跳过感官展开，读着像大纲/细纲备注而非正文。第 1–6 层全是**减法**（清掉多余的），这一层是**加法**（把没写够的审出来）。

典型命中：
- **抽象条件压缩**：「离黑背沟还要外出一截，潮更乱，底也更黑。」——"潮更乱，底也更黑"是六个字的电报式摘要。读者拿到的是"乱"和"黑"两个抽象结论，零感官体验（漩涡怎么拧的？暗流怎么拽人的？黑到什么程度？午时的日头照得进去吗？全没写）。
- **「更…更…」/「越…越…」空转**：`A更X，B也更Y` 或 `越X越Y` 结构，只给程度比较不给感官落地。如「水更深，流更急」「天更暗，风更大」——不是不能这样写，是写完后必须跟上至少一句具体描写，不能拿抽象比较当描写的终点。
- **场景应展未展**：一句话里明确设置了一个感官丰富的场景（深水点、暴雨天、险滩），但只用一两个抽象形容词/副词匆匆带过，像在列细纲条目而非写正文。信号：描述句以抽象程度词收尾，后面直接跳下一件事。**最极端形态——整句抽象标签**：用"X是Y"结构拿单个抽象词当两处场景的完整对比，二字句独立成段，零感官展开。案例（ch073）：「黑背沟是闷。这口深点是压。」——"闷"和"压"是两个潜水点的全部描写，读者拿到这两个字就像只有标题没有正文。展开为呼吸质感（湿布裹胸 vs 铁板顶胸）、压力差异（水裹 vs 水挤）、身体反应（吸气多用三成力）。
- **因果链缩写（心理戏/经验对比也会电报体）**：不止环境描写，人物内心的经验对比同样会被压成密码。案例（ch024）：「港里塞烟塞鱼，他熟。到了这里，钱递错一只手，后头几道门都得翻脸。」三处并发——①"塞烟塞鱼，他熟"：塞给谁、换什么全靠读者脑补（因果链断）；②"递错一只手"：生造搭配，实际是"递给了不该收的人"；③"门翻脸"：门不会翻脸，翻脸的是门后的人，隐喻跳级。改后参考：「在港里办事，给人塞包烟、递两条鱼，人家抬抬手就放你过，这一套他做熟了。可这儿不一样——钱要是递错了人，不光眼前这道门进不去，后头几道门里的人，个个都得翻脸。」——因果写全（塞→放行）、搭配还原成人话、翻脸还给人。信号：一句内堆多个省略了主语/宾语/因果的短语，读者需逐个解码。

判定（这一层的判定方向跟前面六层相反——这里不存在"该留"的例外，只有"该展"和"不必展"之分）：
- **该展**：句子设置了一个需要感官落地的场景/条件（地点描述、环境交代、气氛铺陈），但只给了抽象结论。读到此处读者脑子里没有画面——只有"乱""黑"两个字。改法：按场景功能展开至少 1-3 句具体描写。优先写动作/视觉/触觉，不补空洞形容词。案例（ch073）：「图上圈的是一口更远的深点，离黑背沟还要外出一截，潮更乱，底也更黑。」——"潮更乱"怎么乱？展开为旋涡形状、暗流方向、水面与水下反差。"底也更黑"怎么黑？展开为光线穿透深度、可见度、颜色。改后参考：「……潮更乱——不是涌上来的，是拧着打旋的，水面看着平静，底下暗流能把人脚踝往下拽。底子也更黑，那片海底黑得连午时的日头都照不进去，像一口灌满了墨汁的井。」
- **不必展**：句子只是承上启下的过渡（不是在设置场景），或已经在前文充分展开过此处只是概括复述。如战斗场面中「他更快了」承接前面已展示的速度细节，不展。
- **边界**：不是所有短句都是电报体。短句是网文的长处——对话交锋、动作快切、情绪爆发时的短句不属此层。这一层只抓"设置场景/条件时拿抽象总结当描写的终点"。

方法论提醒：
- 这一层**不能靠 grep**，必须通读时逐段人工判。扫描流程：通读正文时，遇描述性段落就问：「这里我看到了画面还是拿到了结论？」
- 判断口诀：「看完这段，脑子里有没有长出画面？没有——是结论，该展。」
- 跟第 6 层的区别：第 6 层抓"写得巧得发假"（生造词/强行搭配），第 7 层抓"写得少得发虚"（电报压缩）。两者可能共存：一句里既有生造词又有电报压缩，分属两层，分别处理。

### 第 8 层：物理自洽语义错配（属性/力度/宾语/抽象对象/状态归属，五类盲区）

> 从《法援律师》Ch001 两句固化——「纸的棱角擦过手背，刮出一道火辣辣的疼」（一句三中）和「每个字都挤得发干」（一句两中）。单个词都不是禁词、组合才出问题，正则难覆盖，需要通读语义判。

目的：抓「物理不自洽」的描写——物体属性、动作力度与结果、感受当实体、抽象对象被当物理处理、状态归属错对象。第 1–7 层全漏，因为这些词组合合法、不是套话、不是电报、不是生造——是**物理常识/归属错**。

**五类错配**：

1. **物体属性错配**：把立体硬物属性套到平面/软物上，或把不属于该物体的属性硬套。
   - 典型：纸有"棱角"（纸只有"边/边角/纸边"）、布有"刃口"、水有"硬度"、皮有"脆性"。
   - 判定：该物体在现实中是否真有所写属性？

2. **动作-结果因果错配**：动作力度与结果不匹配。
   - 典型："擦过"（轻接触一掠而过）却"刮出"（需力有切入感）；"轻触"却"火辣辣的疼"（持续灼烧感需持续刺激或化学刺激）；"碰了一下"却"血流如注"。
   - 擦≠刮≠割≠划，力度递增；轻触不出持续灼痛。纸边伤人是 paper cut，一瞬锐痛，是"割/划"不是"擦"。
   - 判定：这个动作真出得了这个结果吗？

3. **痛感/感受当物理动作的可数宾语**（宾语位）：把痛感、感受、情绪当成能被"刮出/划出/切出/擦出/挤出"的实体。
   - 典型："刮出一道疼""划出一阵酸""切出一股凉意""擦出一丝灼热"。
   - 痛感是身体反应，不是物体，不能被"取出/产出"。正确写法：写痛感的**性质**（蜇/灼/锐/钝）或**身体反应**（缩手/倒吸气/咬牙），不写"出+一道+感受"。
   - 判定：这个宾语是个东西还是个感受？

4. **抽象对象被当物理对象处理**（主语位/动作位）：把非物理实体（字/话/声音/情绪/目光/记忆/后路/退路/出路/活路/前途/前程）当成能承受物理动作（挤/拽/扯/拧/掰/塞/抽/断/堵/封/挡）的对象。
   - 典型："每个字都挤得发干"（字不能被挤）、"声音被拽回来"（声音不能被拽）、"目光被扯过去"（目光不能被扯）、"记忆塞满了脑子"（记忆不能被塞）、"把你的后路全断在这张纸上"（后路是抽象权利，不能被断、不能断在纸上）、"后路可能被堵死"（后路不能被堵死）。
   - **高频变体：抽象途径词 + 物理动作 + 物理地点**。"后路/退路/出路"是抽象途径，常被误套"断/堵/封/挡" + 物理地点（纸上/桌上/眼里），把抽象塞进物理载体。典型："后路断在纸上""退路堵在门口"。改法：换成法律/商业具体动作（买断/排除/阻断）或具体后果（后面该要的钱要不回来）。
   - **边界（不误报）**："断后路/堵后路/断了退路"是中文惯用搭配（断后路=切断退路），单独使用不报；但"后路断在纸上""后路被堵死"这种带物理地点或用"死"强化物理感的需通读复核——前者把抽象塞进物理地点，后者比单纯惯用语生硬。
   - 与第3类的区别：第3类是**宾语位**错配（动作宾语是感受），第4类是**主语位/动作位**错配（承受动作的是抽象对象）。本质相同——非物理当物理处理，但正则覆盖能力不同，分开记。
   - 判定：这个承受动作的对象是物理实体吗？字/声音/目光/情绪/记忆/后路/退路不是物理实体，不能被挤/拽/扯/塞/断/堵。

5. **状态归属错配**：把属于 A 对象的状态/属性套到 B 对象上。
   - 典型："每个字都发干"（"发干"是嗓子的状态，不是字的属性）、"目光沉重"（"沉重"是身体/四肢的状态，不是目光的属性——目光有"锐利/涣散/聚焦"但没有"沉重"）、"声音发紧"（"发紧"是喉咙/声带的状态，不是声音本身的属性——声音有"尖/哑/低/颤"但本身不"发紧"）。
   - 与第1类的区别：第1类是**物体本身不具备**某属性（纸无棱角），第5类是**状态确实存在但归错了对象**（发干确实存在，但归嗓子不归字）。
   - 判定：这个状态/属性在现实中归谁？写的是 A，但这个状态实际属于 B 吗？

**综合案例**：

案例A（Ch001，一句三中，类1+2+3）：
- 原句：「纸的棱角擦过江澈的手背，刮出一道火辣辣的疼。」
  - 纸无棱角（类1）＋擦不出刮（类2）＋"刮出一道疼"把疼当实体（类3）。
- 改后：「卷宗顺着桌面滑过来，锋利的纸边擦过江澈搭在桌沿的手背，划开一道细口子，隐隐的刺痛蜇得他手指缩了一下。」
  - 纸边（属性对）＋擦过/划开（动作对）＋明确主谓动线与受体＋细口子（实体结果）＋蜇痛（痛感性质）。

案例B（Ch001，一句两中，类4+5）：
- 原句：「她嗓子已经哭哑了，每个字都挤得发干。」
  - 字不能被挤（类4，抽象对象被当物理处理）＋"发干"是嗓子的状态不是字的属性（类5，状态归属错配）。
- 改后：「她嗓子已经哭哑了，话从干裂的喉咙里一个字一个字往外磨。」
  - 话是动作主体（磨）＋喉咙是受力对象（干裂）＋状态归位（干回到喉咙）。

**判定口诀**：抽出来问五句——
1. 这物体真有这属性吗？（类1）
2. 这动作真出得了这结果吗？（类2）
3. 这宾语是个东西还是个感受？（类3）
4. 这承受动作的对象是物理实体吗？（类4）
5. 这状态/属性在现实中归谁？写的是A但实际属于B吗？（类5）
任一答"不"即重写。

**改法方向**：
- 属性换对（棱角→边）。
- 动词换对（擦→划/割；力度匹配结果）。
- 宾语换实体（疼→口子/印子/痕），痛感改写性质（蜇/灼/锐/钝）或身体反应（缩手/倒吸气/咬牙）。
- 抽象对象换回物理对象做主语（字被挤→话从喉咙里磨出来）。
- 状态归位（发干回到嗓子、沉重回到身体、发紧回到喉咙）。
- 若该痛感/状态不承担情绪或节奏功能，直接删（多余的感官填充）；若承担功能，写性质或身体反应，不写"出+一道+感受"或"抽象对象+物理动作"。

**不误报**：
- "刀刃划过手背"正确（刀有刃、划是锐物动作）。
- "纸边割破手指"正确。
- "指腹被纸边压出一道红线"正确（实体痕迹，不是感受当宾语）。
- 签字"写得很重，笔压得纸面凹陷"正确（力度与结果匹配）。
- "声音发颤"正确（颤是声音本身可有的属性，状态归属对）。
- "话从喉咙里挤出来"边界——"挤"配喉咙（物理器官）可接受，配"字"（抽象）不可接受；判定关键看承受动作的是物理器官还是抽象对象。

**方法论提醒**：
- 这一层**不能靠 grep**，必须通读时遇物体接触/痛感/身体反应/抽象对象描写逐句判。正则只能抓"X出+一道+感受"的高频结构（见 banned-words.md 对应段），语义层错配靠人工。
- 跟第 6 层的区别：第 6 层抓"写得巧得发假"（生造词），第 8 层抓"写得物理不自洽"（属性/力度/宾语/对象/归属错配）。两者可能共存但分属不同层。

### 第 9 层：装人设套路组合（AI 写高深/老练主角的固定套件）

> 从《法援律师》Ch001 L273-298 固化——AI 写"深不可测主角"的固定套件，散落在叙述和对话里，单个元素都合法，组合起来才显 AI 味。第 1-8 层全漏，因为每个元素单独不触发各自维度的阈值（密度不够/不够工整/advisory通读），只有组合才暴露。

目的：抓「AI 表演主角深不可测」的套路组合。这不是单点病，是「多个合法元素在同场景堆叠」的组合病。

**典型元素（6 类，同场景出现 ≥3 个即违规）**：

1. **神秘微笑/淡笑**：「X笑了」独立成句，无具体动作支撑，装高深。
2. **眼底/眼神 + 掠过/闪过 + 冷意/寒意/深意**：AI 修辞高频组合（眼底+掠过+冷意），常配「很淡的」「一层」修饰装深沉。
3. **三段式排比回答**：被质问后用三个并列短句回应（「凭…凭…也凭…」「一是…二是…三是…」），形式工整、递进收尾留悬念。
4. **阅历金句**：「我以前见过太多这种东西」「这种事我见多了」——抽掉场景仍是"老练者见过太多"的道理，点题式金句，常暗示主角前世/隐藏背景。
5. **全知视角硬切**：「只有 X 自己知道」「没人知道他心里…」——叙述者跳出来告诉读者主角有秘密，破坏限制视角，且后面通常紧跟解释（把该让读者品的说破）。
6. **拟人化 + 功能解释**：把主角的招牌装置（裂痕/系统/直觉）拟人成会"提醒/警告/告诉他"的东西，且后半句直接解释其功能——过于直白。

**判定**：同一段落或连续场景里，上述元素出现 ≥3 个，即「装人设套路组合」违规。单个元素出现不报（笑了/眼底/三段式单独都可能合理）。

**高发场景**：开篇立人设、主角被质问"你凭什么"、主角接案/接任务、高潮反转前、主角展示能力时。

**综合案例**（Ch001 L273-298，五元素集中 20 行内）：
- 江澈被韩克勤质问"你凭什么觉得能撬"，回应段堆叠：①「江澈笑了」②三段式「凭…凭…也凭这个」③「他眼底掠过一层很淡的冷意」④「我以前见过太多这种东西」⑤「只有江澈自己知道」——AI 表演主角深不可测的完整套件。
- 改法：拆掉套路，用具体专业动作/物件替代。立人设靠「主角做了什么具体的专业动作」（L273 那句医院/工地/门禁/考勤的具体步骤才是江澈的专业），不靠神秘微笑+眼底冷意。

**改法方向**：
- 神秘微笑→换成具体动作（翻协议/指尖按在某行/抬头看对方）。
- 眼底冷意→删，或换成可见的具体表情/动作（眼神在某行停了一下/把协议推过去）。
- 三段式→拆成不工整的口语，或只留一点+具体证据。
- 阅历金句→删，或改成对当下具体证据的判断（不念阅历）。
- 全知视角硬切→删，让读者从后续动作/裂痕描写自己看出秘密。
- 拟人+功能解释→保留装置描写，删"提醒他…"的解释后半句。

**方法论提醒**：
- 这一层**必须通读**，grep 完全无效（元素都是合法词，组合才病）。开篇五章、每卷卷首、高潮章重点通读。
- 跟其他层的关系：元素散落在第2层AI修辞、第6层工整并列、dialogue第6类点题金句，但**组合检测只有本层做**。单维度扫描会漏，必须整体通读。
- 通读时问：「这段是在写一个活人在做事，还是在表演一个'深不可测'的设定？」后者即违规。

### 第 10 层：章节标题 AI 味 / 模板套路
目的：抓章节标题中的 AI 金句句式、抽象比喻、煽情升华、模板重复和标题撞车。正文可以藏，标题是第一印象——读者扫目录就能闻出 AI 味。

**自动化脚本**：`node .agents/skills/_shared/scripts/check-chapter-titles.js --dir "正文目录"`

六类检测规则：

| 类别 | 严重度 | 典型 pattern | 示例 |
|------|--------|------------|------|
| 金句对仗 | blocking | "这不是X，这是Y""X只是Y""X不会Y" | ❌ 这不是赔偿，这是切割 → ✅ 八万块的封口费 |
| 抽象比喻 | blocking | 拼图/画线/余波/交锋/底色/暗涌/锚点/坐标 | ❌ 时间拼图 → ✅ 三份记录对不上 |
| 煽情升华 | blocking | "终于X""第一次，X""在X的地方Y""人心X" | ❌ 终于有人替他问 → ✅ 姚国兴的最后一问 |
| 标题过长 | advisory | 超过 15 字 | ⚠️ 早就写好的"高风险"，和后来的"没看见" |
| 模板频次 | advisory | 同一句式（"把X""先X再Y""三X"）≥4 次 | ⚠️ "把X"祈使句开头出现8次 |
| 标题撞车 | blocking | 两个标题子串包含或尾缀相同（≥4 字） | ❌ 三家各退半步 vs 三层各退半步 |

判定：
- **保留**：标题含设定专有词（如「黑色裂痕」是金手指核心意象），或标题指向具体事件且读者读得懂。
- **该改**：读者扫目录时看不出这章讲什么、觉得"假深沉"、或多章标题像同一模板批量生成。
- 好标题标准：具象、有悬念钩子、口语化、让读者想点进去看。例：「药店收走了她的工牌」「签了字，就别再开口」「四声铃，没有一声落到床上」。

**工作流**：
1. 跑脚本拿自动化结果（blocking + advisory）。
2. 对 blocking 逐条人工复核——确认不是设定词/voice 锚点。
3. 对确认要改的提出新标题建议（具象 + 口语 + 悬念）。
4. 改完同步更新：文件名、文件内标题行、大纲目录、追踪文件中的旧引用。

## 关键判定原则（区分「该清」 vs 「该留」）
- **voice/作者有意意象**：若某隐喻是贯穿全卷的系统性意象，且非生硬抽象，则整体保留，只清零散直喻密度。两例已固化：① 第二卷「桌」=华人商圈层级，还进了章标题；② **「门」母题**=全卷「进门—通路—门道」系统（门路/门道/这道门/几道门/旧门认旧器/认门认账/看门认（看码头那道门认不认咱）），且进了 ch110 章标题「第一层门，算是开了」。此二者均不得判该清。
- **俗语锚点**：常用俗语（拧成一股绳）是 voice 锚点，留。
- **字面/真实感官**：物理动作、真实嗅觉/触觉描写，留。
- **生硬抽象硬喻**：把抽象域用物理/工业/手工动词融合，且无 voice 支撑，清。
- **改前必读上下文**：grep 命中后务必 Read 那一行 ±3 行，确认是字面还是抽象，再决定。误清会伤文本。

## 工作流程
1. 先读项目「真相/基准」文件（卷纲、设定、伏笔、角色状态、时间线、既往审查报告），建立判断标准。
2. **十层**逐层扫描当前正文目录（不要只信旧报告，文件可能改过）。第 1–5 层可用 Grep 批量扫；第 6–9 层需逐段人工通读判断；第 10 层跑 `check-chapter-titles.js` 脚本。
3. 对命中处抽样 Read 上下文，判留/清/展。
4. 改前用 AskUserQuestion 让主人选清理层级（保守/中等/最狠），尤其涉及 voice 意象时。
5. 改：单处用 Edit；批量用 Python 脚本（见下），每处先校验 old 串唯一（count==1）再写回，避免误伤。
6. 改完 Grep 验证：目标 pattern 全卷 0 残留（保留项除外）。第 7–8 层无残留验证——需通读确认被标记的欠写作点均已展开、语义错配均已修正。
7. 写报告到 `报告/` 目录，分节记录每类问题与修改表；若修正了旧报告的误判，在旧报告末尾加「补正」段，不要覆盖原结论。
8. 更新项目 `.workbuddy/memory/YYYY-MM-DD.md` 工作日志。

## 批量改词脚本模板（Python）
```python
# 对目录所有 .md：逐条替换，先校验 old 唯一再写回
import os, glob
ROOT = r"正文目录路径"
rules = [("旧串1","新串1"), ("旧串2","新串2")]  # 每条 old 在全卷应只出现1次
for path in glob.glob(os.path.join(ROOT, "**", "*.md"), recursive=True):
    with open(path, encoding="utf-8") as f:
        text = f.read()
    orig = text
    for old, new in rules:
        c = text.count(old)
        assert c <= 1, f"NOMATCH/重复({c}处): {old} @ {path}"
        if c == 1:
            text = text.replace(old, new)
    if text != orig:
        with open(path, "w", encoding="utf-8") as f:
            f.write(text)
```
