# 读者理解 · 分批精读与前文回查协议

本文件供编排器执行读者自然首读及后置核查；不得在首读前把全文交给 reader。执行记录见 [review-process.md](review-process.md)。只读正文，区分阅读损失与尚未核实的信息，不能把分批造成的上下文缺口当作正文缺陷。

## 阅读范围与独立性

- 每批最多 5 章是必须逐章完整精读的范围，不是此前正文的访问禁令。父流程按章递送正文；首读只给当前章路径和已经自然读过的前文，不提前递送下一章、检索清单或七问。首读返回后再提供此前已采用正文的回查路径清单，不带剧情摘要或预设答案。
- 针对第 N 章的疑点，允许检索第 1～N-1 章已采用正文并读取命中上下文；同批也要先固定第 N 章当时的理解记录，再读 N+1。禁止用未来正文为早先的理解补答案，禁止读设定、大纲、追踪、对标、设计卡及其他候选版本。候选检查只额外允许本次当前候选正文。
- 检索不是精读。记录实际精读文件、检索范围和关键词、实际打开的回查段落、文本版本及原句位置；不能把搜过目录写成通读全书。关键词未命中也不能证明信息不存在。
- 审读者不得参与本批创作或规划，也不得兼任本批文字编辑；新建不继承父会话历史的独立调用（支持时 `fork_turns="none"`），首读仅递送下方“首读任务”与当前正文路径，核查任务单独后发，不接收写作意图、编辑答案或其他候选。角色名不可用时可向独立通用 agent 按两步仅提供当前任务段；有历史污染时必须换会话，不能要求忘掉。父流程可分批派发，但不能以写手自评代替独立阅读；没有独立调用能力或预算耗尽时，如实标独立阅读未评估/待核实，不伪造通过。

## 两次任务之间的实际返回

先自然顺读完整场景和章节，不逐段评分、不带七问找错。reader 必须在读下一章、拿到回查问项前，实际向父流程返回本章的首读理解、投入或困惑、略读倾向、实际收获和期待，附原句；无明显反应可以写无。模型代理不伪造真人情绪、阅读时长、跳读率或满意度。

父流程收到并保留原始返回后，才给同一 reader 单独派发七问核查任务，允许向前检索。不能在同一个初始任务中同时给首读与核查指令并要求“先在心里记录”。本章核查后再递送下一章；七问已知的后续章节仍先独立返回自然反应，再收到该章核查任务，不接收预设问题答案。核查找到前因可以撤销缺失断言，但不能抹去实际首读阻力。逐章核查后再读下一章的读者已知道七问，这种后续阅读不冒称完全未受核查提示影响的自然首读。

重要累计体验验收可使用同一个新 reader 顺读完整单元：每章实际返回首读记录后再递送下一章，全部首读返回后才集中派七问核查。这样保留自然阅读状态，不要求每章新建 agent；核查每章疑点仍只能使用该章及此前正文。

## 后置七问核查

1. 谁在做什么？先用自己的话复述核心动作，不以标题或设计说明作答案。
2. 为什么现在这样做？定位本章或前文的行动依据；找不到先按疑点回查，不直接判前因悬空。
3. 到这一刻已有的信息是否足以理解关键转折？谜底可留，眼前行动理由与关键前提不能靠未来答案补全。
4. 在场人物、出入与空间关系是否自洽？
5. 道具、凭证的持有与转交是否连续？
6. 涉及时，票据、购买力与物理数量是否自洽？外部专业事实不能确认时记需事实核查，不靠猜测定错，也不把外部资料混入正文盲读。
7. 信息冗余与理解依据：复述是否造成无功能重复，还是用于确认、试探、隐瞒、误解、强调或人物互动？瞬间认出事物是否由当前细节、前文或常识支持？区分理解错误与能懂但费力、疲劳的体验，不因重复或“他一听就懂”自动删句、补说明。

人员进出、道具转交不必逐次显写。只有关键在场、持有事实冲突或影响行动理解的缺口才报告；自然省略、合理概数与角色视角限制可以保留。

常识可补的省略、此刻不妨碍理解的有意悬念不报缺失。前文已充分交代则保留原文，不要求本章再解释。必要信息可以明确暗示，不强求每个因果都由旁白明说。

## 子代理提示词

### 首读任务（仅将此段及当前正文递送给新 reader）

```text
你是无父会话历史的独立正文读者，未参与创作、规划或编辑。只自然顺读本次指定的一章及已递送的更早正文，不看设定、大纲、追踪、对标、其他版本、未来章或他人意见，不自行打开审查协议与回查工具。
当前章：<路径及章号>。已自然读过的前文：<路径，首次为无>。
连续读完后实际返回：用自己的话说清当前理解；投入、困惑或略读倾向的位置；实际获得什么、还期待什么；各附原句，允许无明显反应。先报告体验，不直接开修改方案，不为完成表格制造缺点。
说明实际阅读范围与模型代理来源，不伪造真人指标。返回后停止，等待父流程另派核查任务；不要自行读取下一章。
```

### 核查任务（收到本章首读返回后，单独续派给同一 reader）

```text
保留你已返回的首读记录。现在针对同一章执行父流程附带的七问核查；回查清单：<第1至N-1章已采用正文路径及章号>。不得读未来章、设定、大纲、追踪、对标或其他候选。
先核查疑点，再区分确认错误、待核实、前文已交代和表达体验意见。记录检索范围、关键词、实际打开的上下文与原句。尚未查证或预算不足标待核实；未命中不能证明全书缺失。
前因查到后撤销错误断言但保留初读阻力；体验症状不直接推导必须加解释或冲突。只读不改，返回实际范围、版本、证据、影响与判断理由，等候下一章。
```

## 父流程汇总与跨批消歧

1. 核对各批必读范围、实际覆盖与独立性，不把检索覆盖算精读；缺读或未运行单列，不报全范围完成。
2. 对“前因缺失”逐条核对回查依据。若前因可能在另一批，由只读审读者向前定点回查原文；其他批的结论只能作定位线索，不能代替原句。父流程已看过规划时，只负责安排回查及汇总，不替盲读者补答案。
3. 已有前文依据的撤销缺失判断，保留前文位置及消歧理由；仍缺依据的只报告“在已核查范围内未找到”。无法支持确认断点、预算耗尽或存在歧义时归入待核实，不转成通过，也不自动补解释。
4. 合并结果保留确认断点/待核实/前文已交代，附实际范围、版本、原句和处置建议。否定性判断同时附当前动作所需的缺失前提与回查范围，不伪造不存在内容的引文。
5. 用户只要求检查时不写文件。候选理解凭证沿用 [候选逻辑绑定](candidate-logic-binding.md)；累计体验连读另按 `story-review` 的累计连读流程，不把五章分批报告拼成独立顺序连读的证明。

## 意见处置与修后复核

读者的理解与体验同为本次审阅结果，趣味不再只是核查后的附录。既有 rc/arc ID 与凭证不因本协议增加文学评分；机器字段与处置记录遵循 [review-process.md](review-process.md)，不在此另建 schema。

确认硬伤与关键待核实未解决不得签通过；非关键存疑列限制，体验与偏好不得伪装成正确性阻断。专业事实核实另列来源，不回填为首读已知信息。

统筹对所有重要意见记录文字修订、信息重排、设计重审、保留或延期及原文/授权理由；不以规划中将会兑现来撤销当时未获满足的反应。每轮优先 1～2 个体验根因，不限制发现数量。已处置、底线通过和体验改善分别报告；只读任务只输出，不保存这些记录。

任何改动使旧版本凭证失效。实质改动理解、信息次序、动机、场景节奏或兑现时，编辑先复查新全文与受影响前章，再另派未见旧稿和旧意见的新 reader 首读；纯错字标点且不改变意义，编辑复核并按影响定向复核。原 reader 保留初读，不能把知晓答案后的定向复核称作新首读。新旧读者差异只是证据，不保证改善。

同一问题一次定向修订仍在先重新诊断，第二次仍无改善停止自动改写。硬伤未解不通过，体验争议交作者一个推荐及理由，不投票或强迫修改。核对原有优点是否受损，不把删光心理、复述、安静场景当成成功。

## 校准与留出验证

编辑规则校准与正式盲读分开：有来源的作者认可/拒绝案例可用于离线规范校准，不向 reader 提供标签，也不把本章意图或答案注入编辑初审。不同场景分别安排校准材料与隔离留出材料，不能拿已见案例当新效果证明。新旧版本由独立读者匿名阅读，核对漏报、误报与原有优点损伤。缺少作者认可样本或完整场景标签时明确标注；模型复核不补造作者认可，也不证明作者满意或整体效果已验证。
