# 长篇章节骨架模式 · 技术设计

## 1. 产物分层

```text
设定/大纲/细纲
      ↓
骨架/第NNN章_章名.md          规划产物，不是故事事实
      ↓ 作者或独立模型扩写
候选/第NNN章_章名.md          待审正文
候选/第NNN章_追踪事务.json    根据实际正文构造，暂不提交
      ↓ 作者采用
正文/第NNN章_章名.md          已批准正稿
追踪/_tracking-state.json     仅在 promote 后推进
```

`骨架/` 与 `候选/` 都位于书根，避免 `正文/` 下的递归章节发现、写后 Hook 和追踪检查把规划或待审内容当成正式章节。

## 2. 路由

- 长篇“写第 N 章 / 续写 / 继续写 / 日更”默认进入骨架工作流。
- 明确“成稿 / 最终正文 / 直接写正文”时，使用现有正文写作规则，但输出到书根 `候选/`，经作者采用后进入正稿。
- “采用 / 重写 / 弃用”继续使用候选工作流。
- 开书与补纲仍停在 Phase 3；短篇路由不变。

完整骨架流程放入 `references/chapter-skeleton-workflow.md`，`SKILL.md` 只保留路由、默认行为和与 Phase 4 的边界。

## 3. 骨架格式

每份骨架使用可验证 Markdown：

- `## 章节契约`
  - 来源细纲
  - 最终正文字数目标
  - 目标情绪
  - 读者获得
  - 禁止提前释放
  - 开场动作
  - 章尾钩子
- `## 场景 1` 至 `## 场景 N`，N 为 3～6
  - 时空与人物
  - 场景目标
  - 阻力
  - 动作链
  - 结果变化
  - 情绪转折
  - 信息/伏笔
  - 台词意图与潜台词
  - 正文字数预算
- `## 细纲覆盖`
  - 每个语义点使用 `- [x] O1 ... -> 场景 1` 映射一次
- `## 扩写约束`
  - 人物声线、事实红线、允许自由发挥范围

骨架不写完整对话和连续叙事。章节字数目标来自细纲；番茄项目仍服从 2200～2800 字硬门禁。场景预算之和必须等于章节目标。

## 4. 验证器

新增 `skills/story-write/scripts/check-chapter-skeleton.js`：

- 输入：文件列表，或 `--dir <骨架目录>` 配合可选 `--from/--to`。
- 输出：文本摘要；`--json` 输出结构化结果。
- blocking：命名错误、缺少必需节、场景少于 3 或多于 6、场景字段缺失、预算无效或总和不等、未勾选覆盖项、覆盖 ID 重复。
- advisory：发现疑似完整台词或过长连续段落；不影响默认退出码。
- 退出码：0 无 blocking，1 有 blocking，2 参数或读取错误。

验证逻辑只由该脚本维护，测试直接调用脚本，不在 Skill 文档中复制解析规则。

## 5. 流程状态

`flow-state.js` 保持 `current_phase=chapter_writing`，新增三个 `next_action`：

- `write_chapter_skeleton`：当前正式下一章有细纲，但没有骨架或候选。
- `expand_chapter_skeleton`：当前章骨架存在，等待扩写或接收成稿。
- `review_candidate`：当前章候选正文存在，等待结构检查、追踪事务或作者决定。

候选优先于骨架。正式章号只扫描 `正文/` 的正稿文件，忽略 `正文/候选/` 历史兼容目录及书根规划目录。

## 6. 候选系统修复

从已验证提交 `33054da` 恢复两项被后续提交误改的行为：

1. `candidate_root(project) = project/候选`。
2. promote 前运行现有两个 blocking 扫描器，支持 `<!-- 去味:跳过 -->` 与 `--no-scan`。

不改变追踪事务格式与 promote 的移动、回放、失败移回顺序。

## 7. 兼容与回退

- 已有正稿、细纲和追踪文件无需迁移。
- 历史 `正文/候选/` 不自动移动；流程状态明确忽略它，避免误计章号。需要采用的候选应先按书根目录契约整理。
- 回退骨架模式只需移除路由、reference、验证器和新增状态动作；正稿与追踪不受影响。
- 候选修复是恢复既有已验证不变式，不随骨架模式回退。
