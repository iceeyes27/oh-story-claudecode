# 5 · 专名漂移词典

父任务：`.trellis/tasks/09-01-quality-first-gates`
依赖：`09-01-causal-promote`（挂同一入口）

## Goal

检出「抖手」这类架空专名漏成现实真名的泄漏，且不误杀刻意保留的真实名词。

## 背景（demo 实测分布）

| 词 | 出现位置 | 性质 |
|---|---|---|
| `抖音` | 正文 11/20 章、细纲 11 章 | **真泄漏**，本书架空名是「抖手」 |
| `抖音` | `设定/世界观/背景设定.md:30`「短视频平台『抖手』（现实抖音的化名）」、`金手指.md:88`「抖手（类抖音）」 | **合法化名声明，必须豁免** |
| `微博` | 正文 6 章、细纲 3 章、设定多处 | 本书**刻意保留**，不得 blocking |
| `东风` | 正文 3/9 章、细纲 3 章 | 本书**刻意保留**，不得 blocking |
| `军报` / `火箭军` | 全书大量 | 本书**刻意保留**，不得 blocking |
| `知乎` | 正文 20 章 | 需书级声明决定 |

## Requirements

- R6.1 词典只收**封闭的现实平台/产品名**：抖音、快手、B站/哔哩哔哩、微信、小红书、知乎等。
- R6.2 `东风` / `火箭军` / `军报` **不入词典**。它们是真实名词但本书正当使用，塞进词典会让作者拆门禁。
- R6.3 **书级架空声明**：项目可声明「本书就用微博/知乎」，白名单化。否则第 9 章军报微博、第 20 章「微博、抖音、知乎」会炸成一片。
- R6.4 **化名声明豁免（自指问题）**：架空声明文件自身必然包含真名（`背景设定.md:30`、`金手指.md:88`）。词典范围必须显式处理：**正文 + 细纲 blocking，设定层的化名 gloss 豁免**。这是原方案漏掉的一条。
- R6.5 别名从角色快照的 `identity` 与设定里的称呼**运行时派生**，不建手工别名表（手工表会腐烂——参见 `banned-words.md` 的双源教训）。
- R6.6 人名编辑距离 1（如 `钟嘉嘉` / `钟嘉佳`）只 **advisory**。对「钟记者」这类称呼变体无效，不要假装它有效。
- R6.7 按父任务 D3 分级，接进 `check` / `promote`。

## 非目标

- 不做通用的「现实世界名词」检测。
- 不建别名手工表。
- 不把 `东风` 做成 blocking fixture（原方案的验收标准在这一点上是错的）。

## Acceptance Criteria

- [ ] demo 第 11、20 章正文的 `抖音` 被 blocking，报错点名章号与位置。
- [ ] demo 细纲第 11 章的 `抖音` 被 blocking。
- [ ] `设定/世界观/背景设定.md` 与 `金手指.md` 中的 `抖音` **不** blocking。
- [ ] `微博` / `东风` / `军报` / `火箭军` / `知乎` 在 demo 上**零 blocking**。
- [ ] 词典与书级声明分离：词典是共享资产，声明是项目内文件。
- [ ] 词典由脚本**读文件**，不硬编码。
- [ ] 收尾脚本全绿。

## 工期

0.5 天写脚本 + 0.5 天词典/书级声明/豁免规则。审核意见指出，少了后半天「一接上 promote 就会误杀」——本任务的验收清单里，误杀项（微博/东风/gloss）比检出项更多，正是这个原因。
