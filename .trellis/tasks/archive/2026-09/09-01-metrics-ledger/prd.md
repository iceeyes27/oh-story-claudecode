# 6 · 数值台账与写前注入

父任务：`.trellis/tasks/09-01-quality-first-gates`
依赖：无技术依赖，但**排在最后**执行。

## Goal

杀死「结算幻觉」：让活数字（粉丝数、播放量、国运值、任务状态）有唯一权威，并在写前注入，使新章的结算数字不能与已发生的正文冲突。

## 为什么排最后

这是本批最贵的一项（1.5–2 天），治的是**低频但严重**的毛病。它碰 tracking + candidate-transaction 两条 quality-gate 加 4 份副本。在前面几步没做时它是空转——一本读者体验契约缺失、语言门禁可绕过的书，数字对不对不是它最大的问题。

grok 原方案把它排第一，理由是「治本」。本批不同意：它治的是「不崩」，不治「好看」。

## 背景

活数字目前散在三处，无一是活的权威：

1. `设定/世界观/金手指.md` —— 机制 + 任务史（含「粉丝突破100万」「话题热度300万+」「国运+10000/+20000」等具体数值）
2. `设定/题材定位.md` —— 会过期的摘要（「第一任务 +10000，第二任务 +20000」）
3. `AGENTS.md` 的「公理点门禁」—— 另一本书的平行台账（demo 无此文件）

`追踪/上下文.md` 的 `## 当前位置` 目前只有 4 条子弹，**不含任何数字**。写第 21 章时，模型手上没有任何权威数字。

## Requirements

- R7.1 metrics 进 `_tracking-state.json`，缺省 `{}`，旧书兼容（旧 state 无该键时按空表处理，`check` 不炸）。
- R7.2 **不新增第 8 个 `##` 栏**。渲染为 `## 当前位置` 下的一条子弹。`CONTEXT_HEADINGS` 与 `tracking_commit.py:684` 的 `require` 保持不变。
- R7.3 名目用**原文措辞**（「话题热度 300 万+」≠「播放量」）。
- R7.4 每笔事务交**全量当前表**（与 `character_snapshots` 一致），不交 delta。
- R7.5 **回写必须有拒绝条件**，不能只靠「结算后请更新台账」这类提示语——那是 agent 记性不是门禁。二选一或叠加：
   - (a) 事务必须带完整 metrics 快照（空表也要显式 `{}`），schema 拒收缺字段；
   - (b) 正文命中结算句式（封闭句式表：`叮`、`国运`、`任务完成`、`粉丝突破` 等）而 metrics 相对前一 revision 无变化 → promote 拒绝。
   倾向 **(a) 打底 + (b) 收口**。
- R7.6 **三本账收口**：本任务必须宣布 metrics 是唯一活数字权威，`金手指.md` 只保留机制与写作约束、不再承载当前值，`题材定位.md` 的数值摘要标注为派生。不宣布就只是多一个 JSON。
- R7.7 写前注入并进 `追踪/上下文.md` 的派生内容，**不新开块**（`long-mode.md` Phase 4 写前准备已极庞大）。`_tracking-state.json` 继续不进 prompt。
- R7.8 受 `CONTEXT_MAX_BYTES = 12288` 约束，metrics 渲染需有条目上限与截断策略。

## 非目标

- 不做通用数值单调性检测。
- 不做 `story_time` 算术。
- 不做别名绑定（「粉丝数」与「粉丝量」的归一）。
- 不新建 Markdown 台账文件。

## Acceptance Criteria

- [x] 旧 state 无 `metrics` 键时 `check` 正常且不强制迁移；`init` 与新事务行为有独立回归。
- [x] `render_context` 生成的 `上下文.md` 仍恰好 7 个 `##` 栏，`require(headings == CONTEXT_HEADINGS, ...)` 通过。
- [x] `## 当前位置` 下出现「关键数值：…」子弹，名目为原文措辞。
- [x] 事务缺 `metrics` 键时被 schema 拒收（含空表须显式 `{}`）。
- [x] 正文含结算句式而 metrics 未变化时，`promote` 拒绝并说明原因。
- [x] 隔离 fixture 新写一章：无 metrics 更新被拒，正文来源与数值一致时可采用并生成 7 栏上下文。
- [x] `金手指.md` 与 `题材定位.md` 的权威关系已在文档中写明。
- [x] `scripts/test-tracking-commit.py` 保持 schema 4；4 份副本同步且共享文件检查通过。

## 未决

- **schema 是否 4→5**：倾向**否**。`metrics` 缺省 `{}` 且旧 state 不含该键时按空表处理，可保持 schema 4，避免改 `test-tracking-commit.py:193` 与 4 份副本的版本常量。但 R7.5(a)「schema 拒收缺字段」与「旧书兼容」存在张力——需在 `design.md` 里区分「state 的 metrics 键」（可缺，按空表）与「新事务的 metrics 字段」（必填）。**这是本任务最需要想清楚的一处**。
- 结算句式表的最终清单。
