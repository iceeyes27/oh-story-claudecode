# 全量复合检查覆盖契约与运行链路修复

## Goal

确保用户使用未限定范围的“检查”时，系统按固定顺序执行七个复合检查阶段，并执行每个阶段登记的全部过滤项，不因发现普通问题而跳过后续项目，也不以不完整范围宣称完成。

## Background

- `skills/story/SKILL.md` 已定义七阶段路由，但 `skills/story/tests/composite-check-contract.test.js` 目前只验证阶段名称、顺序和公开依赖。
- `ai-flavor-scan` 的技能说明包含九层扫描，入口文案仍写“七层”，存在可漏检的文档契约差异。
- Claude 写作后钩子调用了不存在的 `prose-after-event` CLI 路由；静态检查有三个共享路径错误；连续性测试存在时间边界不稳定；多处提示仍引用已合并的旧 Skill 名称。

## Requirements

### R1. 全量检查清单

新增机器可读的复合检查清单，登记七个阶段、阶段顺序、内部过滤器 ID、执行者、输入范围、必检属性和结果字段。清单作为复合检查覆盖范围的唯一来源。

### R2. 普通“检查”执行规则

- 未限定单项的“检查”必须执行：`story-review`、`ai-flavor-scan`、`story-deslop mode=novel`、`dialogue-naturalness-scan`、`jargon-verb-scan`、`story-deslop mode=general`、`humanizer`。
- 每个阶段内部登记的过滤器必须逐项执行并产生状态；普通发现问题不能阻断后续过滤器和阶段。
- 输入不可读、检查范围不完整或必需执行者不可用时，必须记录失败或阻断原因，不得静默跳过，也不得宣称完成。
- 显式单项请求和“检查更新”继续使用各自范围，不得误报为全量复合检查。

### R3. 覆盖报告

开始时报告书名、正文目录、章节数量、检查阶段和过滤项总数；每阶段报告执行状态、实际范围、问题数量和关键发现；每个过滤器报告状态、范围和结果。仅当七阶段和全部过滤项均有结果时，才允许输出 `复合检查完成：7/7，过滤项 M/M`。

### R4. 契约回归

扩展复合检查契约测试，覆盖顺序、过滤器唯一性、依赖存在性、漏项失败、发现问题后继续执行、不可读输入阻断、嵌套污染检测和触发词边界。

### R5. 运行链路修复

- 为 Claude 写作后钩子补齐当前 CLI 的事件适配路由，并保持成功/失败事件输出合法 JSON。
- 修正三个静态检查中的共享参考文件路径。
- 消除连续性检查对恰好一秒的敏感性。
- 将已废弃的 `story-long-write` / `story-short-write` 运行提示改为统一 `story-write` 入口。
- 将关键本地契约测试纳入默认 `npm test`；不新增 GitHub Actions 或其他 CI。

## Acceptance Criteria

- [x] 清单覆盖七个阶段及其全部已登记过滤项，且每个过滤项有唯一 ID、执行者、范围和结果定义。
- [x] 普通“检查”按固定顺序执行七阶段；单项发现不会跳过后续项目。
- [x] 任一过滤项漏执行、输入不可读或范围不完整时，不出现完成标记，并给出明确原因。
- [x] 复合检查契约测试能捕获漏项、顺序错误、依赖缺失和错误完成报告。
- [x] Claude `PostToolUse` 与 `PostToolUseFailure` 写作后钩子能输出合法检查结果。
- [x] `bash scripts/static-check.sh`、共享资产检查和新增本地契约测试通过；Playwright 缺失浏览器可执行文件，已单独标记为环境阻断。
- [x] 小说正文、项目外部仓库、GitHub Actions 均未被修改或新增。

## Verification Notes

- 复合清单：7 个阶段、95 个必检项；契约测试 7/7 通过。
- 确定性检查：静态检查、共享资产、部署、Hook、连续性、公开 Skill、跨平台适配均通过。
- Dashboard 单元/契约测试：22 项通过、4 项因 Windows 无法制造不可读目录而跳过。
- `npm test` 的 16 项 Playwright E2E 均未进入业务断言，原因是本机缺少 `chromium_headless_shell-1234` 可执行文件。

## Out of Scope

- 不修改任何小说正文、设定或追踪数据。
- 不重写现有七个检查 Skill 的业务算法。
- 不恢复已合并的旧 Skill 目录。
- 不新增 CI、不推送远端、不自动修复生成项目中的本地忽略文件。
