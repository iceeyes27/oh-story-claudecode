# 细读层扫描 · 挑剔真人读者逐段通读

从《霍格沃茨的魔幻手机》复筛轮固化出来的专项扫描。触发背景：机械扫描（AI 味/退化/引号/字数/首现）与十阶段复合检查全部通过后，作者连续多次挑出漏掉的细读层问题（"九个方框≠7 字""解锁密码没交代来源""指头比脑子先动。咔嗒一声轻响。这句话很 AI""摸到一双不属于他的手：正在施力的手怎么变成摸到的客体了？"），要求"自己再扫一遍"，复筛一轮又发现多处同类问题。结论：**脚本门禁抓不到数字自洽、跨章时间线、价格账目、拟声雷同、躯体感知颠倒、台账-正文对账；这一层只能靠挑剔读者逐段通读**，本 skill 把通读的判据、清单、流程固化，作为复合检查的固定阶段自动执行。

## 核心定义

**违规 = 一个挑剔的真人读者在逐段通读时会"咦？"一声的实质问题。** 它不在词表、不在句式、不在结构层，只在"数字能不能对上、时间线顺不顺、这个说法跟前面是不是撞了、躯体感知符不符合生理动线、台账跟正文是不是两本账"这些细读层。

七组清单（逐组过，缺一不可）：
1. **数字与账目自洽**：钱（加隆/西可/金额）、时间（小时/天/月）、电量（%）、人数、价格、百分比、日期——**每个数字必须能复现计算**。跨章出现的同一项数字必须一致。
   - 判定：这个数字怎么来的？用计算器复算（除法/累加/换算），对不上就是违规。正文出现过同项数字的地方，逐处并排核对。
   - 已修判例：净结余"三个月零十二天"——5 加隆 ÷ 1.5 加隆/月 = 3 个月零 10 天（算错）；魔杖价格"旧魔杖七个加隆"与"报废旧魔杖两个西可""新魔杖七加隆"三处撞车；**同一物品多价位必须用词区分**——"连根旧魔杖都要好几个加隆"与"报废旧魔杖两个西可"都叫"旧魔杖"，读者看成一个东西两个价（实际是二手市价 vs 报废贱卖）→ 改"二手魔杖都要好几个加隆"，报废/二手/新三个层次用词拉开。
2. **跨章时间线与承诺兑现**：时间词（明天/今晚/上周/次日/十几个小时前）必须有前文锚点，且与后文事实兼容（开学日无暇去对角巷、"昨天傍晚签约"对应"纸上起算时间上午九点"差 8.5 小时这类）。一章立的承诺（去买魔杖/要充电/要查什么/要防谁）后文必须可见兑现，或显式取消。
   - 判定：这个时间词指向哪一天/哪个时刻？前后章在那一天/那一刻发生了什么？承诺在后续章节有没有落点？
   - 已修判例："明天，我想去买魔杖"——第2章站台（次日开学日）魔杖已在手，9/1 无暇去对角巷 → 改"今晚"；电量"二十四小时后关闭核心进程"——第2章隔日站台仍 0.2% 活跃，0.2% 按 0.1%/h 只够 2 小时 → 改"核心进程关闭倒计时二十四小时，其余组件已全部休眠，勉强够撑到明天"。
3. **同类拟声/句式/模板雷同**：作者已挑过的类型再出现即报，不因单处"无伤大雅"放过。包括：拟声模板（咔嗒一声轻响/轻微的咔哒声/一声脆响）、金句腔（"指头比脑子先动"式动作+结论两连）、数量与提示不符（九个方框 vs 七字提示）、插入说明型破折号的复现。
   - 判定：这个说法是不是跟作者/扫描已定性过的某处同类？同类即报，不管它是不是"单独看还行"。
   - 已修判例："指头比脑子先动。咔嗒一声轻响，屏幕彻底亮起。"（用户定性"很 AI"）→ 删金句腔与拟声；第2章"轻微的咔哒声后，僵死的关节点霍然松开"（同类）→ 删拟声。
4. **表述悬空**：无主因的被动/限定语、凭空指代、无前文依据的修饰。读者会问"这怎么来的？"
   - 判定：把"被 X"补全——谁做的 X？前文有没有依据？补不出来就是悬空。
   - 已修判例："那味被减半的蛇牙粉"——"被减半"无主因、前文无依据 → 删。
5. **对话称呼与指代主语错位**：台词/叙述里指代身份的称呼或主语用错。四种高频形态：①把网文俗语里的称呼安错对象（"宿主"是被绑定者，不是系统的名字）；②称呼的归属分不清（"默认称呼是老板"——是 AI 称呼对方为老板，不是 AI 自己叫老板）；③角色反应与既定称呼脱节（AI 第一句已叫"老板"，主角却回"宿主？"）；④叙述层称呼无源头（"AI提醒"首次作为叙述称呼出现时前面只有"女声"引入与"本机"自称，没有铺垫——称呼体系必须闭环：首次叙述使用前用主角心理/动作确立，如穿越者认知"说白了就是台没电的AI"）。
   - 判定：这句台词/叙述里每个称呼分别指谁？"X 称呼 Y 为 Z"的主宾能不能还原？说话人的反应接的是不是上一句实际说出口的话？叙述层这个称呼第一次出现前有没有确立点？
   - 已修判例：主角"宿主？"→"系统？"，AI"我不叫宿主，系统文才那么叫。本机是离线部署的综合辅助终端，默认称呼是老板。"→"系统文才那么叫。本机是离线部署的综合辅助终端，默认称呼您为老板。"（"您为老板"明确 AI 称呼主角，主语归位）；"翻这些废铁没有意义。"AI提醒→第43行补主角心理"手机里那自称'本机'的东西，说白了就是台没电的AI——可这地方，哪来的电"（"AI"称呼获得源头，且带世界观落差）。
6. **躯体感知与施力客体颠倒**：发出探摸动作的施力肢体，绝不允许作为该动作触碰/摸出的客体受力对象（如“摸到一双不属于他的手”）。身体变异醒来的生理感知时序必须符合真实生理体验：抬手动作 ➔ 视线发现肢体异样 ➔ 神经活动（蜷缩手指/活动关节）确认归属 ➔ 身体与衣着整体感知。
   - 判定：这个触碰动词发出时，施力的是哪一部分身体？被摸到的对象是什么？如果是自身变异肢体，绝不能写成从口袋/被窝里掏摸出来的外物！
   - 已修判例：「往右边口袋摸手机。摸到的是一件洗得发硬的粗布睡衫，和一双不属于他的手。」（主客颠倒，惊悚断肢错觉）→ 改为抬手动作＋视线发现＋蜷曲手指确认神经控制＋衣着体感。
7. **追踪台账-正文对账**：`追踪/逐章记录/`、`追踪/角色状态/`、`追踪/_tracking-state.json`、`追踪/上下文.md` 与正文事实逐项核对。**冲突以正文为准**；细纲设计（SET 表）未在正文兑现的，台账不许预支——要么补正文、要么修台账并登记债务转章。
   - 判定：台账每个数字/状态/伏笔/债务，正文有没有对应事实？台账按细纲写但正文没兑现的，就是虚账。
   - 已修判例：细纲 SET-16 设计"课后冥想补约 2%"，正文未写冥想段，追踪却记章末 2.6% → 按正文改 0.6%（2.1−1.5），补电债务转第 4 章开头，五处台账同步修正。

**判定口令（最关键）**：把这一段读给一个没看过设定、没看过大纲的普通读者，他会不会停下来说"这不对/这哪来的/这跟前面不一样"？
- 会 → 违规，落到具体判据并给修法。
- 不会 → 放过。

**本质**：不是"某个词能不能用"，而是"读者逐段读下来，数字、时间、承诺、说法、身体感知、台账有没有一处对不上"。

## 边界（不误杀，不要报）

- **有具体依据的拟声**：正骨复位弹响、瓷器碎裂、门锁上膛这类有真实生理/物理依据、且上下文具体到物件的声音，可保留——但若它"单独看像模板"（轻微的咔哒声/一声轻响这类万能拟声），仍按雷同报。拿不准标 advisory。
- **功能性破折号**：打断（被台词打断）、强调、时间拖长（"一秒，两秒——"）有功能，不报（由 deslop Gate D / humanizer-em-dash 密度复核管）。
- **文学比喻**：有真实喻体且承担画面/情绪（"轻得像落灰"）不报；抽象概念堆砌归 ai-flavor 层。
- **台账合法预支**：正文明确写了结果（如"买了魔杖"）而过程省略，台账可登记结果；只有正文没有的事（如正文无冥想）不许记。
- **功能性"深吸一口气"**：运动换气、上台前准备等承担实际功能时不报（与 check-ai-patterns 口径一致）。
- **HP 同人已知实体**：邓布利多/奥利凡德/斯内普等原著读者已知，首现无交代不报（归 reader-comprehension 的 _known 白名单）。

## 三层扫描法（逐层做，缺一不可）

### 第 1 层：判例复扫（定向 Grep + 数字并排）
对下列模式做 Grep（带 `-n`），命中后 Read 上下文判同类：
```
咔嗒|咔哒|一声轻响|被减半|明天，我想|明天要去买|二十四小时后|宿主|默认称呼
```
数字并排：对正文中所有带单位的数字（加隆/西可/小时/天/月/%/克/分钟）用 calculator 复算，并跨章核对同项数字（如魔杖价格、电量、净结余、心跳、占比）。

### 第 2 层：逐段通读（主力层，禁止抽查）
按五组清单逐章逐段通读。两条纪律保证召回率：
- **强制覆盖**：不许"整体印象没问题就跳过"，每一段的数字、时间词、拟声、被动限定、承诺都要过判定口令。
- **重读对照**：读到可疑处，先把"一个挑剔读者会怎么说"在心里过一遍，再对照原文——生成比判别灵敏。
- 输出不设字数上限，穷举列出每一处；禁止只报最明显几处。

### 第 3 层：追踪对账（台账 vs 正文逐项）
读 `追踪/逐章记录/`（当前章）、`追踪/角色状态/`（当前角色）、`追踪/_tracking-state.json`、`追踪/上下文.md`，逐项对照正文：
- 台账记的每个数字/状态/伏笔/债务，正文有没有对应事实？
- 细纲 SET 表标注"兑现"的项，正文有没有真的出现？
- 冲突以正文为准：要么补正文，要么修台账并登记债务转章（写明转第几章、什么动作）。

## 工作流程

1. 确认扫描目标：默认扫当前书 `正文/` 全卷 + `追踪/` 台账；可指定单卷/单章。
2. **第 1 层** Grep 判例 + 数字复算并排 → 命中处 Read 上下文判同类。
3. **第 2 层** 逐段通读五组清单，穷举输出。
4. **第 3 层** 追踪对账，逐项列"台账 vs 正文"对照。
5. 汇总：分「确认违规 / 边界待定」两类，附 章节:行号 + 原文 + 判据（哪个数字/哪段时间/哪个承诺/哪处雷同/哪笔虚账）+ 修法。
6. **默认 report-only**：不擅自改正文。用 AskUserQuestion 让用户选「全改 / 只改确认违规 / 只改指定处 / 不改」。
7. 改：单处用 Edit，每处先校验 old 串唯一再写回；改完重跑全部门禁（check-chapter-length、check-chapter-titles、check-ai-patterns --fail-on=blocking、check-degeneration、normalize-punctuation、find-duplicates、check-first-mention）。
8. 台账同步：正文改动涉及状态/数字/债务的，同步修 `追踪/` 五件套（逐章记录/角色状态/_tracking-state.json/上下文.md/对应细纲备注），冲突以正文为准。
9. 写/更新项目 `.workbuddy/memory/YYYY-MM-DD.md` 工作日志，并把新判例补进「已知已修判例」表。

## 判定原则（区分 违规 vs 可接受）

- **违规**：数字无法复算或跨章撞车；时间词无锚点或与后文事实冲突；承诺后文无落点；作者已挑过的拟声/金句/数量类型复现；"被 X"无主因；台账记了正文没有的账 → 修数字/改时间词/兑现承诺/删雷同与悬空/以正文为准修台账。
- **可接受**：有生理/物理依据且上下文具体的拟声；功能性破折号；文学比喻；台账登记正文已见结果的过程省略；功能性深吸气 → 留。
- **改前必读上下文**：Grep 命中务必 Read 那行 ±3 行，确认类别与前后承接再决定。误清会伤 voice。
- **小修大不动**：细读层问题通常单点（一字/一词/一个数字），外科手术式修，不批量重写。
- **跨章联动**：改一个时间词/数字时，顺链核后续所有出现处（如"明天"→"今晚"要联动 AI 台词、追踪、细纲），避免只改一处留另一处。

## 可调项

- 判例表按本书持续补充：每发现一类新细读层问题，补进「已知已修判例」表并同步回 `创作偏好.md`。
- 数字复算范围按题材补：魔法题材重点核钱（加隆/西可）与电量；其他题材按各自计量（医疗=剂量/心率，职场=金额/工时）扩展。
- 第 2 层逐段通读若章节多（≥15 章），可按 5 章/批分批执行，批间并行；每批要求穷举并报告"共通读 N 段"。
