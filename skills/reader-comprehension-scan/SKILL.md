# 读者视角理解力扫描（只读正文，读者看不看得懂）

现有一致性检查都是**作者视角**——拿正文比对 `设定/`、`追踪/_tracking-state.json`、细纲。但设定里自洽 ≠ 正文里交代过。读者手上只有已发布正文，弃书弃在「正文没说清楚」，不在「设定没写」。本 skill 同时记录正文是否让读者愿意继续；理解检查不能代替自然阅读体验。

## 立身铁律：只读正文

**执行本检查时只读正文，绝不读 `设定/`、`大纲/`、`追踪/`、`对标/` 或设计卡。** 通常读取已采用的 `正文/`；候选检查另含当前候选正文，不含其他版本。每批最多 5 章是必需精读窗口；针对第 N 章允许向前检索已采用正文并回查上下文，禁止读取未来章为当前判断补答案。同批按章序先自然首读实际返回，再单独派发七问核查任务；首读前不提供本文件全文、扫描发现、回查清单或核查问项。独立审读者不得参与本批创作/规划或文字编辑；使用不继承历史的新调用，父流程不注入意图、编辑意见或预设答案，见 [references/reading-protocol.md](references/reading-protocol.md)。

## 两层检查

以下为编排器规则，不整体发给首读 reader。首读仅使用 reading-protocol.md 的“首读任务”；必须等本章结果实际返回，才向同一 reader 续派核查。扫描可先运行，但结果只在后置核查中使用，不能预先提示读者寻找某个错误。

### 第 1 层：专名首现交代（确定性脚本）

```bash
node ../_shared/scripts/check-first-mention.js <书目录> [--json] [--min-freq=3] [--reintro-gap=2] [--known=<文件>]
```

- 只报**高精度信号**：① 书名号/引号具名实体（作品名/道具名/绰号）；② 命中虚构专名尾字白名单的 token（系统/阁/宗/令/诀…，白名单在脚本顶部 `NAME_SUFFIX`，按题材增删）。
- **人名/机构不由脚本猜**——中文没有分词，硬猜会把「说道/办公室」全当专名。人名的理解断点交给第 2 层语义通读。
- 裸串候选以量词开头（`MEASURE_PREFIX`）一律丢弃：n-gram 会把量词粘进来，「获得了一个系统」切出「个系统」这种残留会误导作者。数词不在过滤列表内——`三清殿`、`九幽阁`、`万剑宗` 是真专名，滤掉就漏报了。
- **现实世界实体要声明**：脚本分不清《如愿》是真实歌曲还是虚构曲目。真实歌曲、影视、历史人物对读者本就已知，正文不交代不构成理解断点。在 `正文/_已知实体.txt` 每行写一个（`#` 开头为注释）即自动生效，或用 `--known=<文件>` 指定。这是**作者一次性声明**，脚本不猜。
- 严重度：默认 advisory；「首现零交代 + 之后 ≥2 章再被当已知前提出现」升 blocking（读者被要求记住一个从没解释过的东西）。退出码 0/1/2。
- 输出的每一处是**定位线索**，需人工核对首现处是否真的缺交代（也可能交代在别处、或角色本就该神秘）。

### 第 2 层：自然首读后再七问核查

脚本只覆盖可机械判定的子集，普通术语不在脚本完整判定域，脚本通过不能替代术语可懂性核查。人名/普通术语/因果/信息差/空间逻辑/道具物理流转/金融常识的召回靠语义通读。按 [references/reading-protocol.md](references/reading-protocol.md) 分批派**只读正文**的子代理，先自然读本章并返回理解、投入/困惑/略读倾向、收获与期待的原句证据，允许无。父流程收到结果后，另发任务逐问，并附协议“术语可懂性”完整段落（仅后置核查）：

1. 这章谁在做什么？（正文本身能不能说清）
2. 为什么做——前因在**本章或此前正文哪一章**交代过？指不到先向前检索、回查；只报告在已核查范围内未找到，证据不足归入待核实。明确暗示可以成立，不强求旁白明说。
3. 读者读到这里，手上信息够不够理解关键转折及关键用语？普通名词、商贸行话、地方用语、旧称与虚构物件均须按 reading-protocol.md 的“术语可懂性”核查；返回白话理解、正文依据与影响，不以模型知道词义或脚本未命中代替。
4. 本场景在场人物与空间关系是否自洽？关键行动是否出现人员无由增加、消失或相互矛盾？不要求每次进出都有单独交代；常识可补且不影响理解的省略保留。
5. 关键道具与凭证的持有权是否连续？明确归属事实冲突或转交缺口影响行动理解时报告，不要求无关交接逐次显写。
6. 涉及的金融票据、购买力与物理数量是否自洽？正文数字冲突可按证据报告；外部实务或历史物价不能确认时记待核实，不凭模型常识定错，也不在初读时注入外部资料。
7. 信息重复或瞬间判断是否造成具体阅读损失？复述用于确认、试探、隐瞒、误解、强调和人物互动时保留；熟悉感可由当前细节、前文与常识支持。不因刚展示过动作、数字或出现“他一听就懂”就机械删句或补解释。


任一问存在疑点先核查，再区分确认断点与待核实；未查证、预算耗尽或外部专业事实不明不能直接定错。记录章节、当前原句、前文依据或回查范围及影响。前文已充分交代则不要求补重复解释。

## 工作流程

1. 确认扫描目标：默认当前书 `正文/` 全卷；逐章递送，不提前交下一章。
2. 第 1 层运行 `check-first-mention.js`，由编排器保留结果，不注入首读。
3. 第 2 层先自然首读实际返回，再给同一 reader 单独派发七问、术语可懂性规则和回查任务；不是一份任务内要求先想后查。首读理解与体验记录均保留，模型反应不冒充真人指标。
4. 父流程逐项核对跨批前因，附原始 `章节:行号`、实际精读/检索/回查范围、版本和证据。回查找到前因可撤销缺失断言，但不抹去初读阻力。未读或未独立审读单列，不把检索算通读。
5. 区分确认硬伤、关键/非关键待核实、有证据体验缺陷、偏好及保留项。前两者未解决不得签通过；趣味不因模型偏好阻止采用。读者报告症状，统筹再按正文证据/授权决定文字、信息次序或设计处理，重要意见都须回应，延期不冒充解决。
6. 修后规则与执行记录按项目根 `.agents/skills/story-write/references/review-process.md` 及 reading-protocol.md：任何改动旧版本凭证失效；实质更改理解、次序、动机、节奏或兑现须编辑全文复核后换新 reader；纯错字标点按影响定向复核。一次修订仍在先重诊，第二次无改善停止自动改写。
7. **默认 report-only**，不写报告、凭证、正文或追踪；用户授权修改时按写作/修订入口执行，不以本检查直接修改已采用事实。

## 能力边界

普通术语核查归入 `rc-03-comprehension-break`，不只归入趣味项。独立语义审读缺失时 rc-03 记 `BLOCKED`，solo 或扫描结果不能代签。

第 1 层脚本通过只表示「已知高精度首现模式未发现 blocking」；第 2 层依赖模型语感，覆盖率不保证穷尽；审核完成、正确性底线通过与体验改善分开报告。两层都通过**不能**据此声称「读者一定看得懂」。这是辅助定位工具，最终由作者读者审读判断。

## 与其它检查的关系

- `story-review`：作者视角一致性（比对设定/追踪）。本 skill 是读者视角，两者互补不重叠。
- `outline-causal-fields`（细纲前因字段）：在写前建因果；本 skill 在写后查因果是否落到正文。
- 语言：跟随用户语言回复；中文遵循《中文文案排版指北》。
