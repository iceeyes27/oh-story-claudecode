# 写当前场景

先依 `.novel-kit/workflows/progressive-disclosure.md` 核对阶段；版本、状态、恢复依 adoption，审阅与详细交付依 review-loop。

## 选择与准备

读场景状态、未完成修订与采用日志。有待审版本，展示该场全文和详细要点并等待作者；中断采用或待复核依赖先处理。无阻塞时只选已确认章的下一场，执行 `./novel begin <章号> <场景号>`。全场采用后做收尾，不能自行推进下一章。

前文按 review-loop：叙事顺序的直接前场完整原文＋必要更早前因。跨章读最新正式正文；边界不可靠给上一章全文。协调器按证据选前因、记录冻结范围，写手和 copy-editor 使用同范围原文。

写手另收本章细纲的硬约束、必要事件、读者体验目标与可选写法、场景号、相关兑现、设定、角色、追踪、最新累计事实与出口状态、创作护栏、贴近本场的已采用文风片段与作者已确认的修改理由（如有），以及唯一候选写入路径 `草稿/第NNN章/場景MM.md`。旧细纲已确认要求不自动降级。累计事实修订后替换旧值。

动笔前先由写手定本场叙述声音（主角是什么人、他带着什么眼光和口吻讲眼前处境），再简要核对人物为何此刻行动、回应、局面变化与选择依据，均随写手回报留存，不增加作者确认步骤。初稿以《创作护栏》的声音、脑子、节奏三原则为主轴快写，语文禁令为写后自查项，不在写作中逐条对照。行动必要前提缺失先补核原文；改变已确认情节、需新增重要事实时回报，不硬写。写后依创作护栏整场顺读并做简短语义与事实自检；完整语文诊断交独立编辑与裁决者。

## 审阅与每场交付

候选完成后先依 review-loop 执行 `./novel prose-check` 预检，再 review-start 冻结，然后执行完整模式，最多两轮默认自动修正。修正或补读导致输入变化时用新 ID 冻结重审。copy-editor 不收设定、事实解释、出口状态、写前准备、作者修改理由、修改要求或其他意见；缺前因先补原文重新盲读。copy-editor 每次完成后，依 review-loop 第四节第 0 步交 adjudicator 裁决，再按第 4 步三类确定性问题及原意、事实与授权边界决定自动修范围。未修的严重问题仍为未决；作者已授权的优化由写手执行并单独记录。

每场交付完整候选、保留项、原句 → 改句 → 理由 → 问题与证据、事实与资源变化、道具、知情、兑现、completed/失败/缺席、阅读范围、分歧和待裁决事项。prepare 核对开读版本及交付全文。

对话贴出本场全文和详细对照；长场景可打开含全文的交付，同时逐条展示详细要点。不能只给路径或计数。交付后停下；通过只采用当前版本，通过并继续才推进下一场。场景采用保留章内增量，整章采用才更新全书追踪。

展示可先用“正文／需要你决定／重要变化”导航，主要修改、保留项与事实变化仍默认详细展示；不设三条变化上限，不要求作者先回复“展开”。

## 作者要求修改或重写

先 `reopen <章号> <场景号>` 使旧交付失效，再调用 scene-writer 对应模式，保留未授权范围。作者手改只审不自动修，后续明确授权才改。局部修改最多一轮自动修正，重写最多两轮；输入变化用新 ID 开读、审阅、prepare，逐场交付后等作者。

已采用内容走 revise。前场被手改使后场阻塞时，依 adoption 先 withdraw 当前工作单元，保留文本与历史，再处理前置修订；不手改状态绕过。

## 章节收尾

1. 全场通过后 begin <章号> 0，依序合并到 `草稿/第NNN章/整章候選.md`，章名依细纲。
2. scene-writer 顺稿只处理衔接和无功能重复，通常限各场首尾一段，逐场回报原句、改句和理由。实际改动已确认场景时重新交该场审核，不把整章确认代替它。
3. 章节模式保留独立 copy-editor 整章盲读，前文为最新正式上一章；一致性检查顺稿后的事实及相邻章接口，结构检查整章和兑现。
4. 最多两轮修正；兑现证据必须仍在整章候选中，不能沿用被删场景原句。
5. 产出收尾交付及追踪、兑现等候选。交付包含整章全文、按场修改对照、事实变化及下一章到期预览，每个待采用 source 都有全文校验块。
6. chapter 类型采用映射整章到正式正文，同时映射最终追踪等；作者采用后才更新全书状态。保留场景草稿供回溯，后续修订以最新正式章为准，不能合并旧场景覆盖它。
