# 结构保真翻译保护规则

本规则只在用户明确要求「翻译」「译成某语言」或「结构保真翻译」时使用。外文、中英混排、代码或 Markdown 本身不能自动触发翻译。目标语言不明确且无法从请求判断时，先询问目标语言。

## 1. 翻译前标记保护区

以下内容默认原样保留：

- 代码块、行内代码、命令、参数、字段名、路径、URL、邮箱地址。
- 占位符、模板变量、ID、版本号、哈希、产品名和项目名。
- Markdown 控制符、frontmatter 分隔线及其键名。
- 链接和图片的目标地址；可翻译面向读者的链接文字，但链接目标必须保持精确。
- 用户明确要求逐字保留的词、引文或术语。

## 2. 信息守恒

译文必须保留：

- 事实、数字、单位、日期、版本和顺序。
- 否定、条件、例外、因果、时态和可能性强弱。
- 责任主体、动作主体、来源归属和引用关系。
- 警告、限制、前置条件和操作结果。

不得补充原文没有的解释、总结、例子、来源或结论，也不得把翻译改成摘要。

## 3. 结构对应

保持以下结构一一对应：

- 标题层级及顺序。
- 段落数量、空行和分隔线。
- 列表项数量、顺序、缩进和勾选状态。
- 引用层级、代码围栏及其语言标记。
- 表格列数、分隔行、行顺序和单元格对应关系。
- 链接、图片、脚注和引用标记的位置与目标。

除非目标语言语法无法成立，不拆分、合并或重排结构单元。

## 4. 术语策略

1. 优先采用项目已有译法和同一文件内已出现的译法。
2. 没有现成译法时，选择一个准确译法并全文保持一致。
3. 缩写首次是否展开由原文决定，不自行增加解释。
4. 产品名、协议名、接口名和代码标识符默认不翻译。

## 5. 执行顺序

1. 确认源语言、目标语言和用户指定的保留项。
2. 标记保护区，记录标题、列表、表格、链接和代码结构。
3. 按原有结构逐单元翻译，不跨单元重组信息。
4. 执行信息守恒回读。
5. 执行结构回读。
6. 只输出目标语言文本。

同时要求翻译和去 AI 味时，先完成翻译，再在同一结构内做 `minimal + in-place` 轻改。去 AI 味不能改变保护区、信息关系或结构对应。

## 6. 两次强制回读

### 信息守恒回读

逐项核对事实、数字、单位、否定、条件、可能性、责任主体和来源归属。任何一项无法在译文中追溯，都应回到对应结构单元修正。

### 结构回读

逐项核对标题层级、段落、空行、列表项、引用、表格列数、代码围栏、链接目标和图片目标。发现数量、顺序或目标变化时，恢复为与原文对应的结构。
