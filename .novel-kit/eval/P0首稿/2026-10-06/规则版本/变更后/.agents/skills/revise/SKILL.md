# 按场景修订正文

先依 progressive-disclosure 核对阶段；任务、版本和采用依 adoption，审阅及详细交付依 review-loop。

## 范围与基准

- 已收尾章修订最新 `正文/第NNN章.md`；尚未收尾的已采用场景可修订场景草稿。不能把未开始或未采用的文件当成合法修订目标。
- 待审稿走 write-scene。需先修前置已采用场景时，依作者授权 withdraw 当前撰写中、自动审阅中或待审工作单元；保留候选和历史后再修，不以重新开始豁免前置修订。
- AI 修改仅限已授权范围。作者手改保留当前稿，只审不自动改；以核实的采用快照或 Git 版本比较，无基准明确报告，不猜改前稿。
- 不改事实、知情、关系、设定或兑现为文字修订，其余为情节修订；分不清按情节处理。

情节修订先让 consistency-checker 按原文搜索后续依赖，列必须改、可能改、兑现证据与知情变化；只为尚未授权的新增范围请作者决定。

## 建立任务与逐场审核

执行 `revision-start <id> <目标路径...>` 保存当前稿并阻止续写，不先提交全工作区。作者再次手改按 adoption 执行 revision-refresh，保留历次基准，新 ID 重审。

**一次只优化一场。** 已采用整章按视角、时间地点或局面转换识别场景，登记在修订交付内的只读来源位置；有歧义先展示分场依据给作者。原细纲或旧草稿只辅助定位，当前正式正文决定实际范围，不新建第二份可编辑状态。

1. 在修订目录保留完整目标候选，并把当前场截取为纯正文候选；scene-writer 只改当前场的授权位置。
2. 文字修订用文字模式，情节修订用完整模式。写手与 copy-editor 使用同范围冻结的直接前场＋必要前因原文；修订另给必要后文接口，前文理解与后文衔接分开报告。
3. copy-editor 不收修改要求、任务、对照、设定、累计事实、写前准备、作者修改理由或出口状态；其候选依 review-loop 第四节第 0 步交 adjudicator 裁决，默认自动修按第 4 步三类确定性问题及原意、事实与授权边界，不以 S1/S2 自动授权。作者已明确授权的对白、节奏、文风优化或必要段落重组交写手执行，和默认自动修分开记录。结构审阅另收作者要求和原细纲（如有），核对必要事件与整体读者体验，不因新格式降级旧要求。
4. 作者手改稿不调用写手，不自动修；所有问题逐场交作者，后续明确指示才修改。
5. 依 review-loop 展示当前场完整候选、保留项、逐条修改理由和证据、事实/资源/道具/知情/兑现变化、角色完成和缺席、范围、分歧及待裁决。停下等作者；只有通过并继续才优化下一场。
6. **整章中的“场景通过”只确认该场候选**，在交付记录作者指向的版本；不执行把片段映射到整章的 accept。单个已采用场景是完整目标时，可按 revision 采用该目标。
7. 全部授权场景确认后合回完整目标候选，保持其他位置原样。独立整章盲读及事实、结构检查，按场展示新增改动，再以完整章的 revision 交付、review-start、审阅、prepare 和作者采用更新正式正文。

完整目标的开读冻结必须发生在最终审阅之前，不能审完才 review-start。每次正式采用只更新一个完整正文目标，任务仍进行中；通过并继续才处理下一已授权目标。文件提交只列白名单，保留原有暂存。

同章已采用场景修订使后续场景待复核；依证据与授权 revision-extend。无需改字的依赖可用相同完整正文候选复核。跨章依赖由审阅搜索，不宣称脚本理解因果。

## 修订收尾

全部目标采用后重新判定兑现，失效证据退回待核或适当状态，附理由。交付最终追踪、设定、兑现候选及修改事实；revision-finish 至少包含最终追踪。作者采用收尾后任务才完成，不能在最后一章通过时提前解除阻塞。取消、中断恢复、撤回与按路径提交依 adoption。
