# 长篇小说生产系统完善

## Goal

把现有“骨架 → 候选 → 作者采用 → 正稿与追踪”的长篇流程完善为可重复验证的小说生产系统：运行可靠、状态不倒退、上下文来源明确、采用影响可见，并只从作者已经采用的正文学习文风。

## Background

当前仓库已经具备分域权威：`设定/` 保存静态规则，`大纲/` 保存未来计划，`正文/` 保存作者采用的事实，`追踪/_tracking-state.json` 保存当前动态状态，作者记忆只保存创作偏好。该边界保持不变，不建立可独立修改的统一设定数据库或多套重复台账。

现有阻断与缺口：

- Windows 上 `python3` 可能以 9009 退出，Dashboard 没有继续尝试可用的 `python` / `py`。
- 候选采用会刷新 `expected_state_revision`，绕过追踪协议的陈旧事务拒绝。
- Skill adapter 检查存在过期源哈希。
- 读者承诺和人物知情事实缺少结构化动态状态。
- 单章上下文主要由 Agent 按文档组装，缺少确定性工具。
- Dashboard 只能对照文本，不能展示追踪事务的实际影响或当前状态。
- 作者记忆只保存明确偏好，尚不能从作者采用的正文形成受保护的声纹分析。

## Requirements

### R1 运行与采用安全

- Python 探测必须验证解释器能成功运行；某候选命令存在但返回非零时，继续尝试后续解释器。
- 候选事务必须携带生成时的 `expected_state_revision` 和候选正文摘要；缺失、不匹配或正文变化时，在移动正文前拒绝采用。
- 拒绝后候选正文、事务、正稿、追踪状态、逐章记录和派生视图均不改变。
- Dashboard 将陈旧候选映射为 HTTP 409，将内容或协议不合法映射为 422。

### R2 动态追踪扩展

- `_tracking-state.json` 新增 `reader_contracts`，只记录正式正文已经建立的承诺、兑现窗口、状态和证据章。
- `_tracking-state.json` 新增 `knowledge_facts`，只记录正式正文产生的角色知情事实、获知章、来源和保密边界；优先引用时间线事件 ID，不复制客观事实正文。
- 不新增 `storylines` 状态。未来主线与支线继续由卷纲、细纲和下一章承诺负责。
- 旧状态可确定性迁移，写入工具仍是唯一状态修改入口。

### R3 确定性单章上下文

- 提供只读工具，按项目与章号输出有界 JSON 上下文包。
- 输出包含 `state_revision`、来源文件、缺项、当前细纲、上一章正稿、核心角色、活跃伏笔、读者承诺、知情事实、下一章承诺和禁止事项。
- 关键文件缺失、追踪损坏或上下文超限时明确失败，不静默改用整本正文。

### R4 采用影响预览与只读控制台

- Dashboard 候选详情展示追踪事务将改变的角色、伏笔、时间线、读者承诺、知情事实和下一章承诺。
- 影响预览绑定候选正文摘要与 `state_revision`；预览后状态或正文变化时禁止采用。
- 控制台的项目总览、角色、伏笔、双时间线、读者承诺和知情事实均从现有权威数据派生，不产生第二套可编辑状态。

### R5 作者声纹

- `设定/文风.md` 是本书文风的唯一可编辑权威。
- 作者手写区域禁止机器覆盖；机器只更新固定标记区域。
- 样本只读取书根 `正文/` 中已经采用的章节，排除 `候选/`、`候选/_历史/`、`骨架/`、`拆文库/`、`对标/` 和归档目录。
- 分析结果提供证据与样本范围，不复制对标原文，不把机器结果写入作者记忆。

### R6 质量与兼容

- 保留 S1-S4 与证据化结论，不以 AI 的 80/65 数值评分自动采用或重写。
- 保持统一 `story-write`、共享资产单一来源和无 GitHub Actions 决策。
- 不修改或覆盖工作区中与本任务无关的未提交文件。

### R7 修订正确性、旧书吸引力与声纹效果分层验证

- 旧章修订继续使用现有 revision 生命周期：finding 必须独立验证为已修复，盲评输给旧版或平局时保留旧版；该结果只证明修订正确，不证明留存提升。
- 旧书吸引力实验使用独立的被试间协议：A/B 均为连续 15 章，B 只允许预注册章节发生变化，每名真人只能分配到一个 arm。
- 旧书实验主要终点固定为自然首次弃章；摩擦点、最强续读点、累计混乱、疲劳和 voice loss 为次要观察，不得在看到结果后替代主要终点。
- 小样本 pilot 只验证实验可运行并估计方差，不得产生收益结论；powered 阶段必须携带事前功效设计与固定判定规则。
- 作者声纹分为工程验收与效果验收：工程验收不等待真人数据；效果验收必须在相同剧情、模型、上下文和预算下只改变声纹 treatment，并用真人盲评检验目标读者偏好，同时保护理解与连续性不退步。
- 单书、小样本只能证明流程可行；系统层收益仍需多个全新 held-out 故事包、预注册与功效审计。

## Acceptance Criteria

- [ ] Windows 模拟 `python3` 返回 9009 时，Dashboard 继续使用 `python`，候选 reject/promote 回归通过。
- [ ] 陈旧 revision、正文摘要变化、缺失 revision 均在任何写入前拒绝，并有零副作用测试。
- [ ] adapter 检查在实现前后均达到全通过。
- [ ] 新旧 tracking state 的 init、append、revision、check、派生视图与迁移测试全部通过。
- [ ] 单章上下文工具覆盖中文 Windows 路径、缺失文件、状态损坏、角色筛选、容量上限和来源清单。
- [ ] Dashboard 真实临时项目测试覆盖 UI/API/Python 的采用、弃用、陈旧拒绝与影响预览。
- [ ] 控制台只读视图与 `_tracking-state.json`、设定和大纲保持一致，无独立写入口。
- [x] 声纹工具只采样已采用正文，保护作者区域，重复运行幂等，并覆盖空样本与损坏标记。
- [x] revision 生命周期继续拒绝 finding 未修复、修订版输或平局的候选，不把该证书表述为留存收益。
- [x] 新增旧书吸引力实验校验：强制 15 章被试间分配、预注册修订章、主要/次要终点、小样本非结论状态和 powered 功效字段；拒绝同一 reader 读取两臂、未声明章节漂移与事后改主要终点。
- [x] 声纹效果协议冻结除声纹 treatment 外的创作条件，区分工程 PASS 与真人效果证据；缺真人数据时状态保持 `PENDING_HUMAN_EVIDENCE`。
- [ ] 相关静态检查、单元测试、Dashboard 测试、跨平台适配和 `git diff --check` 通过。

## Out of Scope

- 多章 provisional tracking 与批量自动定稿。
- 把十四张工作表变成独立可编辑数据库。
- 自动修改作者手写文风、自动采用候选、自动按数值评分重写。
- 恢复旧 `story-long-*` / `story-short-*` 目录或新增 CI。
