# 三问连读法 · 分批子代理协议

> 本文件由 [../SKILL.md](../SKILL.md) 的第 2 层引用。目标：从读者视角穷举理解断点，只读正文。

## 两条纪律（召回率来源）

**纪律一：分批派发，禁止单代理通读全书。** 每个只读子代理一批 ≤5 章（台词/事件稀疏的书可放宽到 8 章），全书按批切分并行派发。单代理通读全书会摊薄注意力、退化成抽查。

**纪律二：只喂正文，不喂设定。** 子代理 prompt 里只放本批 `正文/第XXX章_*.md` 的内容，**绝不注入** `设定/`、`大纲/`、`追踪/`、`对标/` 的任何信息。一旦注入，检查就退回作者视角、失去意义。

## 判定口诀

把自己当成一个**只读到这里、没看过设定、记性正常**的读者。对每章问三件事：

1. **谁在做什么** —— 这章的核心动作，光靠正文本身能不能说清？说不清（人物凭空出现、动作没头没尾）→ 断点。
2. **为什么** —— 本章事件的前因，在**正文的哪一章**明写过？能指到「第 N 章那件事」→ 通过；指不到、或只在设定里有正文没写 → **前因悬空**。
3. **信息够不够** —— 读到这里，读者手上的信息够不够理解本章的关键转折/爽点/反转？不够（需要一个读者还不知道的前提才成立）→ **理解断点**。

## 子代理提示词（直接复用，替换本批章节范围）

```
你是一个只读的中文小说「读者视角理解力」审查代理。任务：假装你是一个刚读到这批章节、没看过任何设定/大纲/人物表、记性正常的普通读者，找出「光看正文读者会看不懂」的地方。只读不改。

严格限制：你只能读我给你的正文章节文件。不存在设定表、人物档案、大纲、追踪文件——就算你能猜到，也要以「正文里有没有明写」为准。正文没写清楚 = 读者看不懂 = 要报，哪怕你觉得作者心里大概是有的。

文件范围：<本批章节文件列表，≤5 章；只读 第XXX章_*.md>。

方法（逐章顺序读，禁止凭整体印象说「没问题」）：
对每一章，逐条回答三问，答不出就是断点：
1. 谁在做什么：本章核心动作，光靠正文能说清吗？人物是不是凭空出现、动作是不是没头没尾？
2. 为什么：本章事件的前因，在正文的哪一章明写过？请指出具体章号+那件事。指不到 = 前因悬空。
3. 信息够不够：读到这里，读者手上的信息够不够理解本章的关键转折/爽点/反转？如果要靠一个读者还不知道的前提才成立 = 理解断点。

同时留意：某个专名/道具/组织/能力，是不是第一次出现就被当成「读者早该知道」在用，而正文从没交代过它是什么、哪来的。

覆盖率硬要求：不许抽查，每章都要过三问；输出末尾报告本批共审 N 章。
不要报：作者故意留的悬念（后文明显会揭晓、且此刻不影响理解当前动作）；读者用常识就能补上的省略。拿不准的单列「边界待定」。

输出：只读不改；中文，不设字数上限，穷举列出每一处（章节:大致位置 + 读者此刻看不懂什么 + 缺的是哪条信息 + 归类：谁在做什么/前因悬空/理解断点/首现未交代），分「确认断点 / 边界待定」两组；最后一行报告「本批共审 N 章，确认断点 M 处，边界待定 K 处」。
```

## 汇总

合并各批输出，按章号排序，分「确认断点 / 边界待定」。确认断点交作者：断点多集中在开篇前 15 章时，往往就是「看了十几章看不下去」的直接原因——优先修这些。
