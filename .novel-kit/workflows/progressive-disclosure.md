# 漸進式披露與流程恢復

協調器在選擇 Skill、恢復中斷或切換階段時讀本協議；只載入當前階段所需的流程段落與書稿資料。這是讀取與交互規則，不取代採用關卡，也不新增可手改的流程狀態檔。

## 先辨識目前位置

先依作者本次指令、已明確授權範圍及對話中的版本確認，再讀檔案索引與必要狀態：`追蹤/場景狀態.md`、`審閱/修訂/*/任務.json`、`審閱/採用/*/journal.json`；接手舊稿另查 `導入/清單.json`。先確認是否存在，不要求新書預先具備這些檔案。需要核對時才讀相應細綱、候選、正文與交付。

依下列順序處理；不得只憑檔案存在或最新章號推斷已採用：

1. 有 applying／reverting 的採用日誌：依 adoption 的恢復或取消流程處理，先不開始新寫作；既有授權不明時只詢問恢復所需的決定。
2. 有待審交付：作者要求修改或重寫就走對應流程；未明確「通過」時附該版本交付路徑，等待作者。單說「繼續」不是採用。
3. 有未完成修訂或待復核依賴：回到 revise 的既有任務，不新開重複任務，也不開始下一場。
4. 有撰寫中或自動審閱中的場景：核對候選與輸入版本後恢復該場景。輸入已變時重做受影響審閱，不沿用舊結論。
5. 無上述阻塞時才依已確認細綱選下一場；全場已採用則準備章節收尾。上一章收尾或導入確認未完成時，不規劃下一章；細綱未確認時，不寫場景。

「檢查」「先不改」只讀指定範圍並回報，不因發現中斷而自行恢復寫入。狀態與原文或版本衝突時列出證據，交作者裁決，不手改工具狀態以消除衝突。

## 按階段載入

| 階段 | 現在需要的資料與規則 | 延後讀取 |
|---|---|---|
| 開書 | new-book、已有構想、相關設定與作者文風材料 | 審閱迴圈、採用交易細節、無關正文 |
| 導入 | import-book 當前步驟、原稿索引與確認範圍；抽取時逐章讀原文 | 未輪到的原稿全文、可選體檢規則 |
| 規劃 | plan-chapter、追蹤、到期兌現、分卷大綱、相關設定與角色 | 全書正文、寫手與修正模式 |
| 寫場景 | write-scene 的選擇與準備、scene-writer 對應模式、本章細綱、相關兌現與角色、文風、指定前文及已採用章內增量 | 未出場角色、未來正文、章節收尾細節 |
| 自動審閱 | review-loop 的所選模式與角色規則、當前版本候選及各角色允許的資料 | 無關模式、其他審閱者的意見（首輪） |
| 作者待審 | 當前交付版本、問題、分歧與待決事項 | 下一場正文、重跑已完成且仍有效的審閱 |
| 採用或恢復 | adoption 的相應操作、指定交付與版本、交易及任務狀態 | 其他章節全文、無關修訂任務內容 |
| 章節收尾 | write-scene 的收尾段、全章已採用場景、細綱、相關兌現與追蹤、章節審閱模式 | 下一章寫作資料 |
| 修訂 | revise 的對應類型、授權目標與基準、相鄰原文、相關設定與追蹤；情節修訂按依賴證據擴讀後文 | 不相關卷全文、未授權修改 |

延後讀取不是禁止查證：遇到指代、因果、知情或設定疑點，按線索補讀原文並記錄實際範圍。不得用上下文預算截掉必要證據，或把抽樣當全書檢查。承諾的完整導入、整章盲讀及指定範圍審閱必須完成。

子代理只收到角色允許的資料；copy-editor 不接收本協議的狀態診斷、設定、細綱、修改要求或其他審閱意見。實際交付依 review-loop 的資料表；縮減載入不等於縮減審閱者。

## 交互與恢復紀錄

開始或切換階段時用簡短自然語句說明目前位置、本次動作與真正缺少的資料，不固定輸出五欄狀態卡。已有資料與已授權範圍不重問；資料不足時只問無法從檔案取得的必要項目。作者確認、採用與範圍外變更仍須等明確決定，不能以「沒有缺失資料」跳過。

已完成的動作依原流程寫入場景狀態、交付、採用日誌、修訂任務或導入報告。中斷後重新核對這些來源及檔案版本；沒有持久化證據時，明示尚未登記，不自行補造審閱或作者授權。自動審閱完成不推進到下一場，作者採用後的續寫仍依 AGENTS.md 的回覆規則。
