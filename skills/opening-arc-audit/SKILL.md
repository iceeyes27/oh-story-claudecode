# 开篇连读体检（连着看十几章会不会弃书）

读者是**连着看十几章**弃书的。现有检查全是逐章或相邻章——测得出单章好不好，测不出「累计悬念只开不闭、主线原地打转」。而「故弄玄虚」正是这个**累积量**：每章都抛新钩子、却不给答案，主线还不动。本 skill 把开篇 N 章当整体连读，把它量化成一张收支表。

## 分工：语义判开闭，脚本做裁决

悬念「开/闭」、主线「推进/打转」是语义判断，不可靠地纯脚本化。但语义层一旦把判断写成结构化 ledger，**累计与阈值裁决就是确定性的**、可回归测试。

- **语义层**（[references/arc-reading-protocol.md](references/arc-reading-protocol.md)）：连读前 N 章，逐章产出「开了哪些悬念 / 闭了哪些（引用被闭的 id）/ 是否推进主线」，写成 ledger JSON。
- **脚本层**（`arc-ledger.js`）：吃 ledger，算累计开环/闭环/净悬空/平均延迟/主线推进步数，套阈值判 blocking，渲染收支表。

## 用法

```bash
node scripts/arc-ledger.js <ledger.json> [--json] [--window=15] [--net-ratio=1] [--advance-floor=0.333]
```

ledger 格式与一份可运行示例见 [references/ledger-example.json](references/ledger-example.json)（基于 demo 爽文前 15 章：开 9 闭 9、平均 1.44 章闭环、主线推进 14/15 → 健康、不 blocking，正好和「故弄玄虚」对照）。

**阈值裁决**（默认）：`净悬空 > 已闭环 且 主线推进步数 < ceil(窗口/3)` → `arc 级故弄玄虚` blocking。阈值是**信号非铁律**，blocking 必附收支表供作者复核，脚本不自动改稿。

**退出码**：0 无 blocking / 1 blocking / 2 ledger 错误（close 引用了不存在或未来章的 id——防语义层填错表蒙混）或参数错误。

## 阈值档位（按题材调）

| 题材 | net-ratio | advance-floor | 说明 |
|---|---|---|---|
| 爽文/快节奏 | 1（默认） | 0.333（默认） | 要求悬念勤闭、主线常动 |
| 悬疑/推理 | 1.5 | 0.25 | 容忍更高悬空（悬念是卖点），但主线仍要推进 |
| 慢热/群像 | 1 | 0.25 | 放宽主线推进下限 |

## 工作流程

1. 定窗口（默认前 15 章）。
2. 按 arc-reading-protocol.md 分批连读，产出 ledger JSON。
3. 跑 `arc-ledger.js` 得收支表与裁决。
4. blocking 时把「悬而未决清单」交作者：优先闭掉几个早开的环、或让主线目标发生可指认推进。
5. **report-only**，不自动改稿。

## 能力边界

脚本只做确定性累计与阈值裁决；开/闭/推进的判断质量取决于语义层。裁决为 blocking 是「触发了故弄玄虚阈值」的信号，不等于「一定难看」；未触发也不等于「一定好看」。最终由作者判断。

## 与其它检查的关系

- 逐章质量、爽点、钩子 → `story-write` Phase 5 / `story-review`。本 skill 只测开篇 arc 的悬念收支与主线推进这一个累积维度。
- 读者单章看不看得懂 → `reader-comprehension-scan`（读者视角理解断点）。两者互补：一个管「单章懂不懂」，一个管「连读跟不跟得上」。
- 语言：跟随用户语言；中文遵循《中文文案排版指北》。
