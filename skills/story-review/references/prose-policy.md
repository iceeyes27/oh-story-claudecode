# 清晰度、文风与规则优先级

本文件解决两类常见失败：一类是因果和当前行动交代不足，读者不知道谁为什么做什么；另一类是为了“像网文”“去 AI 味”机械切短、删主语、删连接、堆悬念，结果极简、省略和故弄玄虚反而破坏叙事。

## 优先级

冲突时按以下顺序裁决：

1. **当前场面可理解**：当下行动需要的前提、人物目标、原因→行动→结果必须直接可恢复。不能要求读者靠猜补核心因果。
2. **已接受事实与信息边界**：不能为顺句子改掉事实，不能向读者泄露作者真相。
3. **本书自定义文风与题材卡**：视角距离、句长、口语度、留白、停顿、方言、叙述温度服从本书。
4. **局部自然度与去 AI 味建议**：检测器命中是证据线索，不是改写许可证。
5. **通用经验值**：钩子密度、对话比例、短句比例等只作诊断参考，不能压过前四项。

## 清楚不等于解释过量

- 应直写：谁在行动、当前要什么、关键选择为什么发生、行动如何带来结果、场景/时间/视角切换的必要锚点。
- 可留白：人物不愿说出的感受、尚未到揭示点的真相、能从动作与上下文稳定推出的次级含义。
- 必须修：核心主语连续缺失导致人物混淆；因果只留结果；代词无唯一指向；心理与动作跳接；省略掉关键知识来源；为了“高级”把时间顺序打乱却不给锚。
- 不应机械修：自然口语省略、有意的断句、角色声线里的停顿、题材所需的克制、能产生明确双关的留白。

用户若反馈“逻辑不通、叙事混乱、写作水平低还故弄玄虚”，默认修复策略是先恢复简单直叙的因果骨架，再把本书真正有功能的声线放回去；不靠更多谜语、术语、倒叙或碎句掩盖问题。

## P1 treatment：因果预检 → 简单正文 → 声线恢复

契约修复、悬念安全降权和题材兴趣预读记录属于两臂共享的共同底座 `C`。实验中的历史旧流程只记作 `historical_reference`；可比较的控制臂是 `P0-control = C + 单稿`，实验臂是 `P1-treatment = C + 因果预检 + 双遍正文`。不能把共同底座的收益冒充 P1 treatment 效果。

### 起草前因果预检

从冻结细纲的实际情节点表派生有序 `causal_beats`。每项绑定源 `scene_id`，记录 `actor / goal / known_basis / cause_or_trigger / action_or_choice / result`；整组再绑定细纲 hash 和 `must_know / may_believe / must_not_know / open_ids`。同一输入、版本和算法必须可重算。

动机、知识来源或因果连接任一缺失时，停止起草并回到细纲；正文不得自行补洞。这个临时产物不把章级 reader oracle 升级成新的 scene-level 永久契约。

### Pass A：plain_direct

Pass A 是可直接发表的完整正文，不是摘要或说明性脚手架。它必须保留场景化行动、稳定 POV、人物最低辨识度和必要潜台词；不得新增无功能谜团、擅改既定时间顺序或滥造术语。题材必需术语首次出现要有行动锚点。

Pass A 同时拒绝两类反向失败：

- `explanation_bloat`：用作者结论代替场景；动作后重复解释情绪；同一因果被旁白、心理和对话反复复述。
- `voice_loss`：人物对话可互换；叙述退化成案情说明；只剩抽象判断，没有具体动作、感官或人物取舍。

### Pass B：voice_restore

Pass B 只改善压缩、节奏、具体感、个性化对话和潜台词。不得改变 causal beats、既有事实、批准事件及顺序、POV、揭示边界和四类 reader oracle；禁止的是新增或擅改，不是否定题材已经锁定的非线性结构、合法悬念或必要术语。

Pass B 若损害理解，先做一次定向修复；仍失败时，只有 Pass A 同时通过最终 prose 下限（场景化、POV 稳定、人物可区分、无解释膨胀）才可回退，否则阻断。Tier 0 的手工 SHADOW smoke 必须标记 `non-enforced`，不能冒充生命周期证书或“已解决累计弃读”的证据。

## 章尾与追读理由

每章应兑现细纲里的 `expectation_id`，给出继续阅读的理由；理由可以是目标继续、冲突升级、选择后果、关系变化、兑现余波或开放问题。以下都不是全局硬规则：

- 每章必须留下未解问题；
- 每章至少两条悬念线；
- 每章都用强悬念/反转/爽点收尾；
- “宁过火，不平淡”。

低压、关系、修炼试错、信息整理章可以完整收束一个小问题，只要阶段目标、关系期待、下一步行动或余波仍成立。章尾落点要具体，但不为制造钩子凭空加新支线。

## 问题处置而非风格清洗

S3/S4 风格项逐条决定：修复、带功能保留、误报或作者 override。`PRESERVED_WITH_FUNCTION` 必须写清其功能，并在盲化 A/B 中不劣。不能为了“清零”把整章统一成长逗号句，也不能统一成三五字电报体。

修复影响范围默认是问题句/段和直接因果相邻区。第二次仍出现相同 finding，要重新判断根因属于提示输入、细纲设计、信息顺序还是正文执行；不自动整章重写。结构或全文重写由作者批准。
