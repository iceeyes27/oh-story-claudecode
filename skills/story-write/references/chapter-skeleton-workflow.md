# 长篇章节骨架工作流

本流程用于 `story-write long` 的默认章节生产：项目把细纲转换为可直接扩写的场景执行稿，但不负责最终遣词造句。骨架是规划产物，不是正文，也不是已经发生的故事事实。

## 路由

- “写第 N 章”“续写”“继续写”“日更”默认进入本流程。
- “生成第 N 章骨架”“出正文骨架”明确进入本流程。
- 只有用户明确说“成稿”“最终正文”“直接写正文”时，才进入 SKILL.md Phase 4 的成品正文分支；成稿先写入书根 `候选/`，不直接推进追踪。
- 短篇不使用本流程。

## 目录与状态

```text
{书名}/
├── 大纲/细纲_第NNN章.md
├── 骨架/第NNN章_章名.md       # 规划产物
├── 候选/第NNN章_章名.md       # 作者或独立模型扩写后的待审正文
├── 正文/第NNN章_章名.md       # 已采用正稿
└── 追踪/_tracking-state.json  # 只反映已采用正稿
```

生成或修改骨架时：

- 不写 `正文/`。
- 不构造追踪事务。
- 不推进 `_tracking-state.json`、逐章记录、角色状态、伏笔或时间线。
- 不把骨架中的计划事实当成后续正文已经发生的事实。

## 写前读取

只加载当前章必需资料：

1. `大纲/细纲_第NNN章.md`。
2. 对应卷纲中的当前剧情单元、卷契约、禁止提前释放和终局边界。
3. `tracking_commit.py check` 与 `追踪/上下文.md`，取得最近已采用正文的事实状态。
4. 上一章正式正文；不存在时按第一章处理。
5. 本章出场角色、势力和相关伏笔。
6. 已存在的同章骨架；只有用户要求修改或重新生成时读取。
7. 正文超过 10 章时，按 `longform-stability.md` 读取当前角色不变量、世界观红线和有效交接包；这些材料只约束骨架，不因生成骨架而更新。

细纲缺失或缺少当前章节蓝图必需字段时，先补细纲，不用骨架代替细纲。出骨架前对本章跑 `node skills/story-write/scripts/check-outline-contract.js --json --project {书目录} --chapter {N}`；新写章缺 `目标情绪` / `主角目标/关键选择` / `结尾拍ID/类型` / `期待ID/类型` / `读者验收预期` 时先补细纲。真正阻断采用的是 `candidate-commit.py check` / `promote`，不在骨架命令里另开入口。

## 生成步骤

1. 把细纲中的独立语义点编号为 `O1`、`O2`……，合并重复描述，不合并不同结果。
2. 按时空连续性和冲突变化拆成 3～6 个场景。一个场景必须产生信息、关系、代价、选择、情绪或伏笔变化。
3. 为每个场景写动作链和结果变化。动作链写事件顺序，不写连续叙事段落。
4. 台词只写“谁想达到什么、表面怎么说、实际隐瞒什么”，不写完整台词。
5. 将每个细纲语义点映射到且只映射到一个主场景。跨场景延续可在说明中标注，但主归属不能重复。
6. 从细纲读取最终正文字数目标，把预算分到各场景，预算总和必须等于章节目标。番茄项目仍须遵守 2200～2800 字范围。
7. 写入书根 `骨架/` 后运行确定性验证；存在 blocking 时当轮修正。

## 骨架格式

```markdown
# 第001章 章名

## 章节契约

- 来源细纲：大纲/细纲_第001章.md
- 最终正文字数目标：2500 字
- 目标情绪：压迫转为短暂主动
- 读者获得：看到主角拿到第一项可验证证据
- 禁止提前释放：幕后主使身份、下一章证人立场
- 开场动作：主角在窗口被退回材料
- 章尾钩子：回执编号指向一份不存在的申请

## 场景 1

- 时空与人物：上午，受理窗口；主角、受理员
- 场景目标：取得正式受理回执
- 阻力：受理员以材料缺页拒收
- 动作链：递交材料 -> 指出缺页 -> 核对目录 -> 主角发现页码被替换
- 结果变化：申请未受理，但主角确认问题出在送达后的材料
- 情绪转折：被动受阻 -> 产生明确怀疑
- 信息/伏笔：登记缺页编号 F012；推进回执编号异常
- 台词意图与潜台词：受理员想结束争执，表面强调流程，实际回避材料何时被替换
- 正文字数预算：800 字

## 场景 2

...

## 细纲覆盖

- [x] O1 材料被退回 -> 场景 1
- [x] O2 找到页码异常 -> 场景 1
- [x] O3 获得回执编号 -> 场景 3

## 扩写约束

- 人物声线：主角少解释，多追问具体经手人和时间
- 事实红线：不能写成已经确认有人篡改，只能确认页码与目录不一致
- 允许自由发挥：窗口排队动作、材料翻找方式、非关键路人反应
```

字段名是验证器契约，不得改成同义标题。场景编号从 1 连续递增。

## 验证

```bash
node .agents/skills/story-write/scripts/check-chapter-skeleton.js --dir "{书名}/骨架" --from N --to N
```

验证器检查结构、覆盖和预算，不判断最终文笔。完整台词或过长连续段落只提示人工复核；没有 blocking 也不能表述为“文风自然”或“没有 AI 味”。

## 批量骨架

- 单轮最多生成 2 章骨架。
- 后一章可以读取前一章骨架的计划结果，但必须标记为“计划承接”，不能写入追踪。
- 后一章依赖前一章最终措辞、临场选择或新增事实时停止在依赖点，等前一章成稿采用后再继续。

## 接收成稿

作者或独立模型扩写后，把正文写入书根 `候选/第NNN章_章名.md`，然后执行：

1. 对照骨架与细纲检查语义点是否完整、是否新增剧情、是否提前释放信息。
2. 检查章节标题和最终字数；番茄项目执行项目规定的章节长度门禁。
3. 运行 AI 句式、退化、标点和细纲照抄检查。扫描结论只能说明已知确定性模式是否命中。
4. 以实际候选正文为证据构造 `候选/第NNN章_追踪事务.json`，不得从骨架直接生成最终事务。
5. 作者确认采用后，按 `candidate-workflow.md` 执行 promote；成功后才进入 `正文/` 并推进追踪。

候选正文与骨架冲突时，以作者确认后的实际正文事实为基础修改规划和追踪，不静默猜测。
