# 叙事复杂度

## 配置与兼容

项目在 `设定/题材定位.md` 的“基本信息”声明：

```markdown
- 叙事复杂度：平直
- 标题档位：fanqie
```

新建长篇默认写入 `平直` 与 `fanqie`。已有项目缺少 `叙事复杂度` 字段时按 `常规` 执行，不能因工具升级静默改写旧书；缺少标题档位时按脚本默认 `fanqie`。

## 平直

- 优先单线、顺时序；确需切换时间或地点时先写明确过渡。
- 每个关键动作写清主语，按“前因 → 选择/动作 → 结果”组织；人物动机、关系、能力来历首次成为剧情前提时直接交代。
- 同时未解释的核心悬念不超过 2 个。旧悬念未推进时，不为章尾再造新谜团。
- 章尾可以明写下一步行动、选择后果、阶段目标或已发生事件的余波；不强制卡掉关键信息，也不为“高级感”省略因果。
- 句子先求清楚，再保留题材声线和必要潜台词；不把平直写成说明书、电报体或流水账。

## 常规

保持既有写作行为：允许有锚点的时间切换、适量多线和留白；核心因果、主语和首次必要交代仍必须可恢复。章尾要有继续阅读的理由，但理由不等于必须隐藏信息。

## 复杂

允许多线、非线性结构和更高悬念密度，但必须由细纲明确声明信息边界、切换锚点和回收计划。复杂不是省略解释的许可；读者视角检查仍需通过。

## 标题档位

- `fanqie`：说明性超长标题、普通市场问句、相邻通用角色词重合只作 advisory；AI 偏正摘要句、口号式设问、精确/近似复读仍 blocking。
- `terse`：保留 2～6 字、最长 7 字及相邻核心词根的旧严格门禁。

运行：`node .agents/skills/_shared/scripts/check-chapter-titles.js --dir "{正文目录}" --profile {fanqie|terse}`。
